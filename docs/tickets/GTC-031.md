## [[GTC-031]] — Plan/Setup: Setup modal Next button submits form when opened from dashboard card

**Severity:** [ ] Critical [ ] High [x] Medium [ ] Low
**Escalated (brand/trust risk):** [ ] Yes [x] No

---

### Signal

**Expected**
Clicking "Next" on Steps 1 and 2 of the Edit Event Details modal advances to the next step. "Save Changes" only appears on Step 3.

**Actual**
When the modal is opened via the Event Details dashboard card, clicking "Next" on Step 1 or Step 2 submits the form and closes the modal. Step 3 (Venue Details) briefly flashes before the modal closes. Step 3 is only reachable via direct tab click.

**Smallest failing case**
Navigate to any event plan page → click "Click to edit →" on the Event Details dashboard card → click Next on Step 1 or Step 2 → observe modal closes instead of advancing.

---

### Reproduce

**Required state**
- Any event status
- Auth state: Logged in as host

**Multi-actor:** [ ] Yes [x] No

**Steps**
1. Navigate to Draft Empty fixture event
2. Click "Click to edit →" on the Event Details dashboard card (not the checklist stepper button)
3. Observe Step 1 — Event Basics
4. Click "Next"

**Observe:** Modal submits and closes instead of advancing to Step 2

**Data setup**
Use existing fixture: TEST-FIXTURE — Draft Empty (cmnciiyen00011yqznl3x38ku)

---

### Root Cause

The footer button logic gates on `stepLabel && step < 3` to decide whether to render a Next button (`type="button"`) or Save Changes (`type="submit"`). `stepLabel` is derived from `checklistStepContext`, which is only set by two entry points:
- Post-payment flow
- `handleChecklistOpenEditDetails`

When the modal is opened via the Event Details dashboard card (`setEditEventModalOpen(true)`), `checklistStepContext` is never set — it stays null. `stepLabel` evaluates to `undefined`, so `stepLabel && step < 3` is always false. The footer renders `type="submit"` on every step, submitting the form on every Next click.

This is a regression from [[GTC-028]], which fixed Step 1 via the checklist entry point but did not address the dashboard card entry point.

---

### Scope

**Fix here:**
- `src/components/plan/EditEventModal.tsx` — footer button logic should not depend on `stepLabel` to determine button type. When `step < 3`, always render `type="button"` with `onClick={() => setStep(step + 1)}` regardless of how the modal was opened. Only render `type="submit"` on Step 3.

**Do not touch:**
- All Do-Not-Touch Zones in GATHER-BUILD-CONSTANTS.md are binding
- `checklistStepContext` and `stepLabel` usage elsewhere — only fix the footer button condition
- `handleSubmit` — must not be changed
- [[GTC-028]] fix — must not regress
