# GTC-217 — Household CREATE path is non-transactional

**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** TBD

*Spun out of GTC-173 (C2) per its Stop Condition 9 and Scope note: "if the non-transactional
write pattern proves to be the actual root cause of any loss found during testing, flag it
rather than silently expanding this ticket's scope... that is a larger fix... and may warrant
its own ticket." Confirmed live in code during GTC-173 preflight — see below.*

### Context

`POST /api/events/[id]/households` (`households/route.ts`) builds a household as a sequence of
independent, unwrapped Prisma calls: `household.create`, then a loop of `createMember` calls (one
per primary contact / partner / helper / guest, each itself several sequential awaits for
Person/PersonEvent), then the channel-picker write (`contactPersonEventId`). None of it runs
inside `prisma.$transaction`. A mid-request failure (e.g. the third helper's create throws) can
leave a household record with only some of its members persisted — a half-built household with
no way to tell, from the data alone, that the write never finished.

This is the **same bug class** GTC-201 (A3b-2) already fixed on the household **PUT/edit** path
(`reconcileHouseholdMembers` now takes a `Prisma.TransactionClient`, and its sole caller wraps it
in `prisma.$transaction`). It was never applied to CREATE.

### Scope

**Fix here:**
- Wrap the CREATE path's writes (household creation, all member creates, the channel-picker
  write) in a single `prisma.$transaction`, mirroring the shape GTC-201 used for the PUT route.
- No schema change is expected — this is pure transaction-wrapping of existing writes, not new
  columns or constraints.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`.
- `reconcileMembers.ts` / the PUT/edit path — already transactional (GTC-201); out of scope here.
- The diff-based upsert matching logic (GTC-159/201) — this ticket only wraps CREATE, it does not
  change how members are matched or reconciled.

### Dependencies

None blocking — startable independently. Filed as a follow-on to GTC-173 (C2) for provenance.

### Acceptance

- [ ] `POST /api/events/[id]/households` performs all its writes (household, all members, channel
      picker) inside one `prisma.$transaction`.
- [ ] Regression test: a simulated mid-sequence failure (e.g. a throwing member create) leaves
      **no** partial household — either the whole create rolls back, or the test documents why
      that's not achievable and what was chosen instead.
- [ ] `npx tsc --noEmit` clean, build passes.
