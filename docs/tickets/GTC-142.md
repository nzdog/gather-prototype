### What was found

A 17-person / 117-item Christmas event surfaced a 500 on `POST /api/events/[id]/finalize-plan`. The dietary-coverage AI call hit its 1024-token cap (~3083 chars of dense JSON), `parseClaudeJSON` saw `stopReason === 'max_tokens'` and threw, and the route returned 500. The truncation log identified neither the call site nor the prompt class — only response length — so attribution required a code-shape argument rather than direct evidence.

Three AI calls inside finalize-plan compete for tokens; the dietary-coverage payload is the only one whose size scales with both item count *and* requirement count, making it the call that broke first under post-GTC-133 universal-opt-in scale.

### What was changed

**Phase 1 — `src/lib/ai/token-limits.ts`**
- `MAX_TOKENS_DIETARY_COVERAGE`: 1024 → 4096 (4× headroom; matches `MAX_TOKENS_SECTION_GENERATION` precedent)
- `MAX_TOKENS_CONSIDERATIONS`: 1024 → 2048 (2× headroom; prophylactic, same root-cause class)
- `MAX_TOKENS_GAP_FILL`: unchanged at 2048 (not the culprit)
- JSDoc updated on both bumped constants with rationale + GTC-142 reference

**Phase 2 — `src/lib/ai/claude.ts`**
- Added optional `callSiteLabel?: string` field to `ClaudeConfig`
- `parseClaudeJSON` accepts an optional `callSiteLabel` second arg; when set, the truncation log line becomes `[Claude API] AI response truncated (label) - max_tokens reached. Response length: …` and the thrown Error message includes the label too. Without a label, log/error shape is preserved (back-compat for any external caller).
- `callClaudeForJSON` forwards `config.callSiteLabel` into `parseClaudeJSON`

**Phase 3 — `src/app/api/events/[id]/finalize-plan/route.ts`**
- Gap-fill: `callSiteLabel: \`gap-fill:${section}\`` (section interpolated for usefulness)
- Dietary coverage: `callSiteLabel: 'dietary-coverage'`
- Things-to-consider: `callSiteLabel: 'things-to-consider'`

**Phase 4 — Other AI call sites**
- `src/app/api/events/[id]/generate-section/route.ts` → `generate-section:${body.section}`
- `src/app/api/events/[id]/conflicts/[conflictId]/suggest-resolution/route.ts` → `conflict-resolution`
- `src/lib/ai/generate.ts` → `plan-generation`, `plan-regeneration`, `conflict-explanation`, `selective-regeneration`

### Known limitations

- 4096 may not be enough headroom for events significantly larger than the 17-person/117-item seed (e.g. 50+ guests with many dietary requirements). The new labeled logs will surface this if it happens; no prophylactic further bump applied without evidence.
- The graceful-degradation pattern (try/catch around dietary/considerations to allow partial plan generation) was explicitly out of scope and is not addressed here.
- Default `callSiteLabel` for `callClaude` itself (the non-JSON helper) is not threaded; only JSON-parsing call sites carry labels, which is where the truncation log fires.
