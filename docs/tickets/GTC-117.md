# [[GTC-117]] — Moment 2: Opening screen — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** e875da9

### What was found

- Moment1Summary already uses `MomentArc` with `currentMoment={2}` and `completedMoments={[1]}` — but that's the summary screen, not the Moment 2 opening. The new Moment2Opening component uses the same arc props.
- The page.tsx state machine uses `showSetup` → `showMoment1` → main plan flow as sequential gates. Added `showMoment2Opening` between `showMoment1` and the main plan flow.
- Moment1Summary's "On to the plan →" button calls `onContinue()` which previously cleared `showMoment1` and went straight to the plan. Now it also sets `showMoment2Opening = true`.
- Primary button style matches Moment 1 buttons: `px-6 py-3 bg-accent text-white font-medium rounded-lg hover:bg-accent-dark transition-colors`.
- The `eventName` prop is defined in the interface (per ticket spec) but not displayed on this screen — the opening screen shows only the assistant line and button. Destructured without binding to avoid TS6133.

### What was changed

**New file: `src/components/plan/Moment2Opening.tsx`**
- Full-screen component with `fixed inset-0 z-50 bg-white` (matches Moment 1 pattern)
- MomentArc with `currentMoment={2}`, `completedMoments={[1]}`
- Assistant line: "Let's get this plan out of your head and onto the page."
- Primary button: "Let's do this →" calls `onStart()`
- Centred layout with `max-w-2xl`, vertically and horizontally centred via flex
- Props: `{ eventName: string; onStart: () => void }`

**Modified: `src/app/plan/[eventId]/page.tsx`**
- Added `import Moment2Opening`
- Added `showMoment2Opening` state (default `false`)
- Moment1Summary `onContinue` now sets `showMoment2Opening = true`
- New render gate: when `showMoment2Opening && event` → renders `Moment2Opening`
- `onStart` clears `showMoment2Opening` → falls through to existing plan generation flow
