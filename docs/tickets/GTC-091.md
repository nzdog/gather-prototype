# GTC-091 — Dev harness: interactive ConflictCard and ConflictList test page — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** [pending]

### What was found

- The `Conflict` model has 30+ fields including enums for `type`, `severity`, `status`, `claimType`, `resolutionClass`, and `delegatedTo`.
- `ConflictCard` accepts 6 action callbacks plus the `aiCallsDisabled` prop added in GTC-090.
- No `/dev/` route directory existed — created fresh.
- `ConflictList` groups cards by severity and manages modal state for acknowledge/resolve flows. For the harness, rendering `ConflictCard` directly was cleaner since we need per-card state control without real API calls.

### What was changed

**New file:**
- `src/app/dev/conflicts/page.tsx` — interactive dev harness page at `/dev/conflicts`.

**No other files changed.**

### Features

- Production gate: `notFound()` called before any hooks when `NODE_ENV !== 'development'`.
- 8 fixture conflicts covering all required severity/status/canDelegate combinations.
- All 5 action buttons wired to local state transitions:
  - Mark Resolved: removes card
  - Dismiss: removes card
  - Acknowledge: transitions to ACKNOWLEDGED status
  - Delegate to Coordinator: transitions to DELEGATED status
  - Resolve with AI: 1.5s mock delay, then adds mock suggestion; disabled when toggle is on
- Toolbar with AI calls disabled toggle and Reset all button.
- Card counter showing visible/total.

### 8 fixture conflict titles

1. Oven capacity exceeded at 6pm (CRITICAL/OPEN/canDelegate:true/suggestion/affectedParties)
2. No BBQ available at venue (CRITICAL/ACKNOWLEDGED)
3. No gluten-free mains (SIGNIFICANT/OPEN/canDelegate:true/suggestion)
4. Desserts team has only 1 item (SIGNIFICANT/DELEGATED)
5. Placeholder quantity on "Bread rolls" (ADVISORY/OPEN/canDelegate:false/suggestion)
6. Drinks team has no coordinator (ADVISORY/OPEN/canDelegate:false/no suggestion/no affectedParties)
7. Zero mains for 30 guests (CRITICAL/canDelegate:false)
8. Only 1 dairy-free option (ADVISORY/canDelegate:true)

### Known limitations

- Uses `ConflictCard` directly rather than `ConflictList` — the list component manages its own modal and API state which would require significant mocking.
- No persistence — all state is in-memory and resets on page refresh.
