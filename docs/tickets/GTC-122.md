# GTC-122 — Dietary requirements before food sections — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 30a190b

### What was found

- The Dietary requirements accordion was positioned 6th (after all food sections and Setup & Cleanup), meaning Kate would set dietary needs _after_ food sections had already been progressively generated.
- The `generateSection` function in the modal already passed `currentState.dietaryData.requirements` in the `householdData.dietaryRequirements` field on every call.
- The `generate-section` endpoint's food section prompts already included dietary requirements when present (line 103 of the prompt template).
- So the data flow was correct — dietary requirements were already passed to all food section AI calls. The issue was purely UX ordering: Kate would naturally fill dietary _after_ food sections, meaning progressive generation for food sections would fire before dietary data was entered.

### What was changed

- **`src/components/plan/Moment2Step1Modal.tsx`**: Moved the DietaryAccordion from position 6 to position 1 in the accordion list, immediately after the event type selector. New order: Dietary, Mains, Sides, Dessert, Drinks, Setup & Cleanup, Other.

No endpoint or schema changes — the dietary requirements were already being passed through the request payload and incorporated into all food section prompts.

### Known limitations

- If Kate skips the Dietary accordion and goes straight to Mains, the progressive generation for Mains will still fire without dietary context. This is by design — Kate can always re-edit and re-close a section to regenerate it with updated dietary data.
