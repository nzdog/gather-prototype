# GTC-100 — Remove Resolve with AI; detect all unassigned items as conflicts — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** [pending]

## What was found

- `ResolveWithAIModal` is only used in `ConflictList.tsx` — NOT deleted per ticket instructions.
- `onResolveWithAI` handler in `ConflictList` is only used for the Resolve with AI button — safe to remove entirely.
- `aiCallsDisabled` is only used for the Resolve with AI button across all files — safe to remove everywhere.
- `detectUnassignedCriticalItems` only detected critical unassigned items. Non-critical unassigned items were silently ignored.

## What was changed

### Change 1 — Remove Resolve with AI button
- **`src/components/plan/ConflictCard.tsx`**: Removed `onResolveWithAI` and `aiCallsDisabled` props from interface and destructuring. Removed the Resolve with AI button from JSX.
- **`src/components/plan/ConflictList.tsx`**: Removed `ResolveWithAIModal` import, `resolveWithAIModalOpen`/`aiResolveConflict` state, `handleResolveWithAI`/`handleAcceptAISuggestion` handlers, `aiCallsDisabled` prop from interface/destructuring, all `onResolveWithAI`/`aiCallsDisabled` prop passes to ConflictCard, and the ResolveWithAIModal render block.
- **`src/app/dev/conflicts/page.tsx`**: Removed `aiCallsDisabled` state, `handleResolveWithAI` handler, `resolvingIds` state and overlay, AI calls disabled checkbox, and `onResolveWithAI`/`aiCallsDisabled` props from ConflictCard call site.
- **`src/app/plan/[eventId]/page.tsx`**: Removed `aiCallsDisabled` prop from both ConflictList call sites.

### Change 2 — Detect all unassigned items as conflicts
- **`src/lib/ai/check.ts`**: Renamed `detectUnassignedCriticalItems` to `detectUnassignedItems`. Expanded detection to ALL unassigned items (not just critical). Critical unassigned items get severity `CRITICAL`; non-critical get `ADVISORY`. Updated fingerprint from `unassigned-critical-item-` to `unassigned-item-`. Updated title from `"[name]" is critical but has no assignee` to `"[name]" has no assignee`. Added legacy fingerprint cleanup in `saveConflicts` to resolve orphaned `unassigned-critical-item-*` records.

### Change 3 — Updated test
- **`tests/unassigned-critical-items-test.ts`**: Updated to test `detectUnassignedItems` with new function name, new fingerprint pattern, and expanded scope (11 tests covering CRITICAL and ADVISORY severities, new fingerprint pattern, description variants).

## Known limitations

- `ResolveWithAIModal.tsx` is no longer imported anywhere but was intentionally kept per ticket instructions. It is dead code until re-used.
- Legacy fingerprint cleanup runs on every `saveConflicts` call. This is a lightweight `updateMany` with a `startsWith` filter and will become a no-op once all legacy records are resolved.
