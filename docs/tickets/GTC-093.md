# GTC-093 — "Go fix it" pre-expands relevant team accordion in Items modal — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** de181e0

### What was found

**Field inspection for team name extraction:**

Inspected `src/lib/ai/check.ts` for all items-type conflict generators:

- `QUANTITY_MISSING` (detectPlaceholderConflicts) — sets `affectedItems` (item IDs) but no `affectedParties` or `category`.
- `TIMING` (detectTimingConflicts) — sets `affectedItems` (item IDs), `equipment`, `timeSlot` but no `affectedParties`.
- `DIETARY_GAP` (detectDietaryGaps) — sets `dietaryType`, `guestCount` but no `affectedItems`, `affectedParties`, or `category`.
- `STRUCTURAL_IMBALANCE` (detectMissingCoordinators) — puts `teamName` in `suggestion` object.
- `COVERAGE_GAP` (detectCoverageGaps) — sets `category` to `event.occasionType` (not a team name).

**Conclusion:** No items-type conflict reliably carries a team name in the Conflict record. However, `affectedParties` is typed as `Json?` (string array) and the AI suggest-resolution endpoint and the dev harness fixtures already populate it with team name strings. The `affectedParties[0]` value is the best available signal. When it's `null` or empty, the modal opens with all accordions collapsed (graceful fallback).

**handleCloseExpansion inspection:**

`handleCloseExpansion` (line ~587) did NOT previously touch `expandedItemCategories`. The set persisted across modal open/close cycles. Added `setExpandedItemCategories(new Set())` to `handleCloseExpansion` so that programmatic pre-expansion from "Go fix it" does not persist to the next manual open. This is consistent with the existing pattern of resetting `setModalBreadcrumbTrail`, `setPeopleInitialView`, and `setInitialExpandedTeam` on close.

### What was changed

**`src/components/plan/ConflictCard.tsx`:**
- Updated `onGoFixIt` prop signature to `(conflictId: string, conflictType: ConflictType, affectedTeamName?: string) => void`.
- Button click handler now extracts `affectedParties[0]` as `teamName` and passes it as the third argument.

**`src/components/plan/ConflictList.tsx`:**
- Updated `onGoFixIt` prop type to include `affectedTeamName?: string`.

**`src/app/plan/[eventId]/page.tsx`:**
- Updated `handleGoFixIt` to accept `affectedTeamName?: string`.
- When `section === 'items'` and `affectedTeamName` is provided, calls `setExpandedItemCategories(new Set([affectedTeamName]))` before `handleExpandSection`.
- Added `setExpandedItemCategories(new Set())` to `handleCloseExpansion` to reset on modal close.

**`src/app/dev/conflicts/page.tsx`:**
- Updated `handleGoFixIt` signature to include `affectedTeamName?: string`.
- Alert message now shows the team name that would be pre-expanded (or notes when none is available).
- Fixture conflicts already had realistic `affectedParties` values from GTC-091 (e.g. `['BBQ Team', 'Mains Team']`).

### Known limitations

- Real conflicts from `check.ts` for QUANTITY_MISSING and TIMING do not populate `affectedParties` — the pre-expansion only works when `affectedParties` is present (e.g. from AI conflict resolution or future check.ts updates).
- DIETARY_GAP conflicts have no team association — the Items modal opens with all accordions collapsed.
- Only the first entry in `affectedParties` is used for pre-expansion.
