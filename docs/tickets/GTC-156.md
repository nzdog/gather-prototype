# GTC-156 — Record freeze design decision; delete stale freeze comments — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** ships in the `chore(GTC-156)` commit alongside this ticket (hash not backfilled — bundled per the three-unit commit plan)

**Severity:** Low (doc/comment accuracy in a load-bearing module)
**Surfaced by:** GTC-154 follow-up. Removing the dead `canFreeze()` left two comments still
implying a hard freeze block that does not (and, per product decision, should not) exist.

### Decision recorded

**Hosts CAN freeze a plan with unassigned items. Warnings-only via `checkFreezeReadiness()`
is the intended and final behavior — not a gap.** Confirmed by Nigel, 2026-07-09.

### Signal

Two stale comments in `src/lib/workflow.ts` contradicted the decision:
1. `runGateCheck` doc comment (was lines 433–434): "Assignment coverage is enforced at
   CONFIRMING → FROZEN transition." No live code enforces this.
2. The doc comment on `getCriticalGapCount` (was lines 217–222): "Returns the count of
   unassigned items blocking freeze (T6). Used for UI messaging (...)." Described a freeze
   block; the function also has zero callers.

Note: the task brief referred to this second function as `getUnassignedCount`; no function of
that name exists. The comment described is on `getCriticalGapCount` — the clear intended target.

### What changed

- Deleted the "Assignment coverage is enforced at CONFIRMING → FROZEN" line from `runGateCheck`.
- Rewrote `getCriticalGapCount`'s doc comment: it counts unassigned items; freeze never
  hard-blocks (decided 2026-07-09); the count feeds warnings-only freeze-readiness messaging;
  currently no callers. Kept the "Queries assignment: null, NOT Item.status" note.
- `.claude/skills/gather-architecture-contract/SKILL.md`: recast the freeze bullet as an
  explicit **DESIGN DECISION (2026-07-09)** (deliberate, not a weak point); aligned section 6's
  Item.status-cache justification (freeze is warnings-only, so a stale cache misleads a readout
  rather than corrupting a gate decision).
- `.claude/skills/gather-domain-reference/SKILL.md`: updated the freeze note to a recorded
  design decision and dropped the now-removed-comment reference.
- `.claude/skills/gather-frontier-and-roadmap/SKILL.md`: already reflected the removal (GTC-154).
- All `workflow.ts:NNN` references across skills shifted for this edit and re-verified against the
  edited file (checkFreezeReadiness :107, canTransition :243, canMutate :265, logAudit :289,
  runGateCheck :440, EPIC 4 :73).
