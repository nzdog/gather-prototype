### What was found
The participant view (`src/app/p/[token]/page.tsx`) is a single component with multiple states: loading, error, and main view (which includes header, frozen banner, RSVP states, assignment cards, and footer). The loading and error states were already centered with `flex items-center justify-center`. The main view had no max-width container — content ran full-bleed edge to edge.

### What was changed
**`src/app/p/[token]/page.tsx`**
- Wrapped all main view content (header through footer) in a `max-w-2xl mx-auto px-4 sm:px-6 lg:px-8 pt-8 pb-6` container div inside the full-bleed background div
- Outer div changed from `min-h-screen flex flex-col bg-gray-50` to `min-h-screen bg-gray-50` (flex moved to container)
- Container div carries `min-h-screen flex flex-col` to preserve the sticky footer layout
- Added `rounded-t-xl` to the header section for a polished card top
- Added `rounded-b-xl` to the footer section for a polished card bottom
- No changes to RSVP logic, token validation, assignment data, or any Do-Not-Touch zones
