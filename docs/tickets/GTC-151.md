# GTC-151 — Setup route allowlist regression fix — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** ab8678e

**Severity:** High (silent data loss — Step 1 persistence broken for most event types)
**Surfaced by:** GTC-150 verification (`docs/tickets/GTC-150.md`, Known limitations).

### Phase 1 audit

- **Legacy allowlist** (`setup/route.ts:6–14`): `['BBQ', 'Roast dinner', 'Potluck', 'Picnic', 'Kids party', 'Christmas', 'Other']`. Referenced in exactly three lines, all in this file (definition, validator :143, error payload :145).
- **`CONFIG_EVENT_TYPES`** (`config-loader.ts:86`, `as const`, 11 values): `Casual BBQ, Birthday (Kids), Birthday (Adult), Christmas, Easter, Wedding Reception, Baby Shower, Engagement Party, Anniversary, Farewell, Other`. (The ticket's repro mentioned "Beach picnic"/"Roast dinner" as pickable — neither is in the config list; the pickable set is these 11.)
- **Overlap: exactly `Christmas` and `Other`** — 9 of 11 pickable types silently failed to persist.
- **Adjacent divergences: none of the same class.** `ALLOWED_EVENT_TYPES` existed nowhere else; no other route validates event types (`POST /api/events` deals in `occasionType`, a different V1 field; Moment 1 has no type picker); `finalize-plan` only *reads* `setup.eventType` with an `?? 'Other'` fallback. Phase 3 therefore empty.
- **Schema:** `EventSetup.eventType` is `String?` (`schema.prisma:979`) — plain string, no Prisma enum, **no migration needed** (ticket unknown resolved).
- **Modal confirmed** sending config labels: chips render from `CONFIG_EVENT_TYPES.map` (`Moment2Step1Modal.tsx:477`).
- **Legacy-row edge surfaced and accepted (pure Option A per Nigel):** `LEGACY_EVENT_TYPE_MAP` forward-maps only `BBQ` and `Kids party` on modal read; a stored `Roast dinner`/`Potluck`/`Picnic` row would be rejected on its next save under the new allowlist. Zero EventSetup rows exist in dev, and the modal UI has only ever offered config labels, so such rows shouldn't exist anywhere.

### What was changed

One file, `setup/route.ts`: the hardcoded seven-value list deleted; `CONFIG_EVENT_TYPES` imported from `@/lib/ai/config-loader` and used as the validator allowlist and in the 400 error payload — client chips and server validation now share one source of truth, so this class of bug cannot recur by drift. The `eventType === 'Other'` → `eventTypeOther` required rule is unchanged (`Other` is in the config list).

None found (audit above). Nothing to fix in Phase 3.
