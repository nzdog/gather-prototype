### Signal

`canFreeze(eventId)` (src/lib/workflow.ts, formerly lines 79–88 with doc comment 71–78)
returned `unassignedCount === 0` and its comment declared it the safety-critical freeze gate
("Freeze blocked if ANY item lacks assignment (T6)"). In reality the live CONFIRMING→FROZEN
path — `src/app/api/events/[id]/transition/route.ts:90` — calls `checkFreezeReadiness()`,
which is warnings-only (`canFreeze: true` always, per its result type). The function was an
intended-but-never-wired gate: dead code that reads as load-bearing.

  **unrelated `canFreeze:` field** on `FreezeCheckResult` (workflow.ts) which
  `freeze-check/route.ts:21` returns to the UI. The field is live and untouched.
- No imports of the function anywhere; no test references; exported only from the internal
  lib module (no public surface) → deletion, not deprecation.
- Historical spec mentions in `docs/03_specs/` and `docs/04_roadmap/tickets/epic4-freeze*`
  left as-is (historical record).
