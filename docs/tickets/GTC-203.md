## Scope

### 1. The security suite leaves coordinator tokens teamless

**Observed 2026-08-04.** After `npm run test:security`, the SENT fixture's COORDINATOR
`AccessToken` rows have **`teamId = NULL`**. Straight after a bare
`npx tsx tests/security-fixtures.ts` they are correctly team-scoped.

Some route the suite drives deletes the coordinator tokens and re-issues them through
`ensureEventTokens()`, which does not restore the `teamId` the fixture set. The consequence is
narrow but nasty: a `/c/<token>` URL captured after a suite run fails to load, and the failure
presents as a 500 on the page under test rather than as a fixture problem.

**Why it is worth fixing rather than documenting forever:** the security suite is the preflight
gate, so *"run the suite, then walk the UI"* is the normal order of work. The trap is on the
happy path.

Tasks:

- [ ] Identify which test drives the re-issue (start at the routes that call `ensureEventTokens()`
      — `people/[personId]` PATCH is the likely one).
- [ ] Restore team scoping in the suite's teardown, or make the offending test restore what it
      perturbs. **Do not weaken the assertion** to avoid the side effect — zone 6.
- [ ] Assert it: after a full suite run, every COORDINATOR token still carries its `teamId`. The
      trap should not be able to come back silently.
- [ ] Remove section 4b from `gather-run-and-operate` once the fix lands (the entry names this
      ticket as its expiry).

⚠ `tests/security-*.ts` is **do-not-touch zone 6**. This ticket touches the fixture/teardown path
only, and only to make the suite leave the database as it found it. No assertion may be weakened,
skipped, or deleted. If restoring the scoping requires changing what an assertion proves, that is a
stop-and-report.

### 2. The acceptance-box rule belongs in the docs skill

`gather-docs-and-writing` documents ticket authoring — frontmatter, body sections, evidence
discipline, commit-hash backfill. It does not yet say the thing [[GTC-200]]'s review proved:

> **An acceptance box is ticked against measurement, never against intention.**

Both boxes the review caught were ticked by sessions that had *decided* to do the work, described
their intent accurately in prose, and never checked the result. [[GTC-197]]'s narrative even said
*"deferred with reasoning"* where it had genuinely deferred something else — the writing was honest;
the checkbox ran ahead of it.

That failure mode is invisible from inside the session that commits it and cheap to catch from
outside, which is an argument for the rule being written down rather than relied upon.

Tasks:

- [ ] Add the rule to `gather-docs-and-writing`'s evidence-discipline section, with the concrete
      test: *for each box, name the command, screenshot, or measured number that proves it — if you
      cannot, the box is not ticked.*
- [ ] Cite [[GTC-200]]'s review as the incident, and [[GTC-168]]/[[GTC-197]]'s in-place corrections
      as the shape a correction takes: **at the point of error, false tick left visible and
      annotated, never quietly rewritten.**
- [ ] Note the corollary the same review demonstrated: a divergence ruled only in a code comment
      (the [[GTC-196]] anchor dual-write) is a divergence nobody can find. Rulings go in tickets;
      comments point at them.
