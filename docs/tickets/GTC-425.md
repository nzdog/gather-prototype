# GTC-425 - The demo's copy-start route closed behind a switch

> Filed by Claude Code on 29 Oct 2026, from the founder's prompts in one
> session (investigate, plan, then build). Branch feat/demo-start-switch
> from 5d2960d (equal to origin/main). Commits: f45ae01 (the fix),
> ac1f321 (the suite), and the commit that adds this ticket.

## What was wrong

The "Try it yourself" demo (GTC-392) was hidden in production, but only
on the screen. The /demo button and the /demo/new page are
development-only (`process.env.NODE_ENV` gates in
`src/app/demo/page.tsx` and `src/app/demo/new/layout.tsx`, GTC-395). The
route behind them was not: `POST /api/demo/session` with
`{ start: 'copy' }` had no switch and no environment gate, and
middleware does not stop it. Anyone who sent that one request to the
live site would have:

- written a copy (six rows in one transaction: a throwaway User on
  `@demo-copy.invalid`, a host Person "Sam", an isDemo Event, its
  EventSetup, a HOST EventRole, a two-hour Session), built from code, no
  template event needed;
- received a two-hour HOST session on that copy, from which to add
  people (any address they typed), the crowd, and up to 3 AI plan calls
  per copy (100 a day across copies), at the founder's AI cost.

Nothing could send: GTC-392's send wall holds whatever GATHER_LIVE_SENDS
says. The session could not create a real event (POST /api/events needs
a paid Stripe checkout, 402 without one).

## Production, checked before the build

Read by the founder by hand in the Railway dashboard (project
feisty-enjoyment, production, the Postgres-33NH database that the live
Gather service uses) on 29 Oct 2026, SELECT only:

- isDemo events: 0 (not even the old shared Henderson sample)
- copies (isDemo events hosted from `@demo-copy.invalid`): 0
- Users and People on demo-copy addresses: 0 and 0
- people in a sample event, and people in both a sample and a real
  event: none
- real events: 4

The message-row query (Q4) failed in the dashboard's editor; with no
isDemo event there can be no message row tied to one. Bottom line:
nobody had used the route in production and nothing leaked.

## The founder's rulings (29 Oct 2026, in Claude Code)

- Close the copy-start route behind a switch named GATHER_DEMO_START.
  Only the exact value "on" opens it; read on every request; default
  off; 404 when closed; the check placed before the limits and before
  anything is read or written.
- GTC-015 decided the route is reachable in production, and GTC-269
  reaffirmed it. That stands for the route. The copy-start shape is now
  gated by a switch the founder turns on at launch. The old no-body
  shape is unchanged. tests/demo-endpoints-test.ts test 1.2 is reworded
  and re-aimed to hold both.
- The button and page gates (NODE_ENV) stay exactly as they are.
- Nothing is set on Railway and no Railway setting is touched.
  GATHER_DEMO_START is set only in this Mac's `.env.local`, so the demo
  and its suites keep working locally. The founder set nothing on
  Railway.
- The guest-matching fix (a real event can reuse a person made in a
  sample) is not part of this ticket; the founder's leaning is a marker
  column on Person (option B), built with GTC-392 part D.

- S1 the switch: unset and every near miss ("", "true", "1", "yes",

- S2 the route as code: one call, before `cookies()`, `visitorOf(`,
  `checkStartLimit(`, `startDemoCopy(` and `prisma.`; inside an `if`

## Flags

- **demo-tweaks B5.** Its fourth clause is `git diff --quiet HEAD --
  src/app/api`: it reads the WORKING FOLDER against HEAD, so any
  uncommitted change under src/app/api turns it red. Its other three
  clauses were checked one by one and hold. It is red before this
  ticket's commit and should be green after it. GTC-414 re-based the
  old freeze checks onto a fixed history; this clause was not among
  them, so it will trip on every future uncommitted API change.
- **The route scanner does not see the switch.** `collectEnvGate` in
  tests/security-route-scan.ts counts only NODE_ENV conditions as an
  environment gate, so the scanner still reports this handler as "no
  credential" (`['POST src/app/api/demo/session/route.ts', false, '']`
  in security-route-scan-control). That verdict is still true (the
  switch is not a credential), and the scanner is not the proof of the
  switch; test:demo-start-switch is. Zone 6 files are not edited.
- **The suites ran without the outside egress guard** that GTC-422's
  runs used. The dev server on :3000 loaded `.env.local`, which holds
  provider keys; GATHER_LIVE_SENDS was unset throughout, so every send
  stopped at its last step.
- **Still open (GTC-392):** part D (the clean-up and going public), and
  the guest-matching fix above. Production stays closed to copies until
  the founder sets GATHER_DEMO_START=on on Railway at launch.
