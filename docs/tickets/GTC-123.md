# [[GTC-123]] — Replace hardcoded food defaults with NZ config file — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** e3d2c0a

## What was found

The `Moment2Step1Modal.tsx` component had a hardcoded `FOOD_DEFAULTS` constant mapping 7 generic event types to static food item arrays. Meanwhile, `src/lib/ai/plan-option-tree-config.json` contained a comprehensive NZ-specific config with 10 occasion types, 13 category keys, multi-level options with `dependsOn` patterns, and `nzNotes` for cultural context.

The hardcoded defaults were generic (e.g. "Ham, Turkey, Roast lamb" for Christmas) while the config had NZ-specific items (e.g. "Glazed ham, Roast lamb, Roast chicken, Roast beef, Roast pork" under "Traditional roast" style for Christmas). The config also covered occasions not in the original 7 (Wedding Reception, Baby Shower, Engagement Party, Easter, Anniversary, Farewell).

The `generate-section` endpoint had no NZ context — its system prompt was a generic "meal planning assistant" with no cultural specificity.

## What was changed

### New file: `src/lib/ai/config-loader.ts`

Mapping and extraction utility that bridges the JSON config to the accordion UI and AI prompts:

- **Event type → config key mapping** with legacy backward compatibility (`"BBQ"` → `bbq_casual`, `"Kids party"` → `birthday_kids`)
- **Category → accordion section mapping**: `mains`/`breakfast_brunch` → Mains, `sides_salads`/`table_snacks`/`entree_starters` → Sides, `dessert`/`cake` → Dessert, `drinks_alcoholic`/`drinks_non_alcoholic` → Drinks
- **Default item extraction**: Uses Level 2 `dependsOn` first key's options (specific dishes), skips `multiSelect` dietary levels, falls back to Level 1 options filtered of negative choices
- **Reference item extraction** (for AI): Collects ALL Level 2 `dependsOn` items across all styles for comprehensive AI context
- **Exports**: `getAccordionDefaults()`, `getNzNotes()`, `getSectionReferenceItems()`, `CONFIG_EVENT_TYPES`, `LEGACY_EVENT_TYPE_MAP`

### Modified: `src/components/plan/Moment2Step1Modal.tsx`

- Removed `toItems` helper, `FOOD_DEFAULTS` constant, and old `EVENT_TYPES` array
- Imported `CONFIG_EVENT_TYPES` (11 options: 10 config occasions + Other), `getAccordionDefaults`, `LEGACY_EVENT_TYPE_MAP`
- Updated `FEEDBACK_LINES` for all new event types
- `handleEventTypeSelect` now calls `getAccordionDefaults(type)` instead of indexing `FOOD_DEFAULTS`
- `fetchSetup` applies `LEGACY_EVENT_TYPE_MAP` migration when loading saved records
- Event type selector pill buttons now render from `CONFIG_EVENT_TYPES`

### Modified: `src/app/api/events/[id]/generate-section/route.ts`

- Imported `getNzNotes` and `getSectionReferenceItems` from config-loader
- System prompt now includes NZ cultural context: `"...in New Zealand. {nzNotes}"`
- User prompt for food, setup, and other sections includes a reference items block sourced from the config's category options
- Dietary section unchanged (no config mapping needed — dietary is cross-cutting)

## Known limitations

- Legacy event types "Roast dinner", "Potluck", and "Picnic" have no config match — they fall back to empty defaults. These types had no corresponding NZ config occasion. Existing records with these types will load their saved food items but won't have a highlighted pill button.
- The full JSON config (~150KB) is bundled into the client since the modal is a `'use client'` component. Acceptable for prototype; could be optimized with a server action if bundle size becomes a concern.
- Non-food config categories (`activities_entertainment`, `decorations`) are not surfaced in the accordion UI — the current accordion only has food + setup + dietary + other sections.
