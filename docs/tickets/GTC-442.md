## Which forms of the cron secret the routes accept

Added by the founder's ruling. Read on 1 Nov 2026 at df782c4, code
not run:
- src/app/api/cron/cron-secret.ts holds only the decision.
  `cronSecretAccepted` refuses everyone when CRON_SECRET is unset or
  empty; otherwise the credential must equal it exactly.
- All five routes (nudges, wrap-up-dispatch, decide-by-followups,
  outbound-dispatch, tnz-status-poll) read the credential with the
  same line, for GET and POST alike:
  `authHeader?.replace('Bearer ', '') || secretParam`.
- So both forms are accepted: `Authorization: Bearer <secret>` and
  `?secret=<secret>`. vercel.json uses the query form for all five.
- The header wins when it is sent: a wrong header is refused even
  with the right query. A header holding the bare secret, with no
  "Bearer ", also passes.
- Which form the founder's scheduler sends is not known here; he will
  say. The plan's deploy-day line names the Bearer header; it stands
  once he confirms the form.
