# GTC-176 — D3: Held-softly reassignment + release notification

**Status:** Open | **Branch:** TBD | **Commit:** [pending] (filed `e5f6e82`) | **Effort:** high

*Effort level is a proposal from the discovery-report ticket breakdown — run `/effort` manually
before execution.*

### Context

Hinge spec §8 + Moment 4 §8.6: a maybe (or any silence) stays the guest's — held softly — until
Kate reassigns it, which she can do anytime, with her why. **When she reassigns a maybe'd item,
the system closes the loop with the released guest** ("all good, the pavlova's covered") —
releasing them is something the system can do, so it does. This also dissolves the
duplicate-item edge case (nobody arrives with a second dessert).

Today: both assign routes (`items/[itemId]/assign`, `c/[token]/items/[itemId]/assign`)
delete-then-create identically regardless of prior state, and neither notifies the previously
assigned person. `frozen-edit/route.ts`'s `handleReassign` already does the "why" +
"notify the released guest" halves correctly, but writes into `InviteEvent`'s untyped metadata
blob rather than a real ledger, and is gated to FROZEN only.

### Scope

**Fix here:**
- Reassignment routes (the general-purpose ones, not just `frozen-edit`) notify the released
  guest via the existing SMS/email carrier on reassignment.
- Wire the "why" capture through A2's (GTC-168) unified ledger, replacing the ad hoc `InviteEvent`
  metadata pattern `frozen-edit` currently uses.
- Confirm this works for a maybe specifically (item held softly, not treated as loose) once D1's
  maybe state exists.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`.
- The ledger mechanism itself (A2's territory) — this ticket consumes it, doesn't build it.

### Dependencies

D1 (GTC-174), A2 (GTC-168) — cannot be scoped precisely on the ledger side until A2 lands.

### Acceptance

- [ ] Reassigning any item (maybe, silence, or accepted claim) notifies the previously assigned
      person, if one existed.
- [ ] The reassignment reason is captured through A2's unified ledger, not an ad hoc metadata blob.
- [ ] `npx tsc --noEmit` clean, build passes.
