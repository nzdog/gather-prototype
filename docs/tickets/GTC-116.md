# [[GTC-116]] — Moment 2: Schema and setup data storage — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 216b188

### What was found

- `requireEventRole` helper exists at `src/lib/auth/guards.ts` — accepts `['HOST', 'COHOST']` role arrays. Used for both endpoints.
- Existing API pattern (e.g. `src/app/api/events/[id]/route.ts`) uses `NextRequest`/`NextResponse`, async params via `context.params`, and `console.error` for error logging (not `console.log`).
- No shared TypeScript types file for API request/response shapes — types are defined inline per route. Followed same pattern.
- Moment 2 flow document confirmed the EventSetup model approach: stores Kate's Step 1 answers (event type, accordion section data, dietary requirements) as JSON fields, separate from the generated plan data in Team/Item models.

### What was changed

**Schema (`prisma/schema.prisma`):**
- Added `EventSetup` model with all specified fields: `eventType`, `eventTypeOther`, `mainsData`, `sidesData`, `dessertsData`, `drinksData`, `setupCleanupData`, `dietaryData`, `otherNotes`, `createdAt`, `updatedAt`
- Added `setup EventSetup?` relation to `Event` model
- `eventId` has `@unique` constraint (one EventSetup per Event)
- `onDelete: Cascade` ensures cleanup when Event is deleted

**Migration (`prisma/migrations/20260416062317_add_event_setup_model/`):**
- Creates `EventSetup` table with JSONB columns, unique index on `eventId`, and foreign key with CASCADE delete

**API route (`src/app/api/events/[id]/setup/route.ts`):**
- `GET` — returns `{ setup: EventSetup | null }`, auth-gated to HOST/COHOST
- `POST` — upserts EventSetup record, only updates fields present in request body
- Validates `eventType` against allowed values list
- Rejects `eventType: "Other"` without non-empty `eventTypeOther`
- Validates `dietaryData.requirements` is an array when provided
- TypeScript interfaces defined for all request body shapes

**Test (`tests/event-setup-test.ts`):**
- 20 assertions covering: model CRUD, relation, unique constraint, partial updates, all JSON fields, eventTypeOther, cascade delete, null state
- Script: `npm run test:event-setup`

**package.json:**
- Added `test:event-setup` script

### Known limitations

- API endpoints are not tested via HTTP (no dev server in test harness) — database-level behaviour is verified directly via Prisma. Auth guard integration is verified by code inspection (both handlers call `requireEventRole` and return early on `NextResponse`).
- Progressive generation (background AI calls per accordion section) is a later ticket — this ticket only stores the raw input.
