### What was found
The existing plan check trigger lives in `src/app/plan/[eventId]/page.tsx` as `handleCheckPlan()` (line ~572), which calls `POST /api/events/${eventId}/check`. This function was only invoked from the setup checklist banner (step 5) and after plan regeneration — it was never wired into the Plan Status modal.

The `ConflictList` component (`src/components/plan/ConflictList.tsx`) displayed the text "Click 'Check Plan' to assess for potential conflicts" when `hasRunCheck` was false, but no actual button was rendered. The instruction referenced a control that didn't exist.

### What was changed

**`src/components/plan/ConflictList.tsx`**
- Added `onCheckPlan?: () => void` and `isCheckingPlan?: boolean` props to `ConflictListProps`
- Added a "Check Plan" button in the "Ready to check your plan" empty state
- Button shows spinner + "Checking…" text when `isCheckingPlan` is true
- Button disabled during loading to prevent double-clicks
- Updated instructional text from `Click "Check Plan"` to `Check your plan` (no longer referencing a phantom button)

**`src/app/plan/[eventId]/page.tsx`**
- Added `isCheckingPlan` state variable
- Wrapped `handleCheckPlan` with `setIsCheckingPlan(true)` / `finally { setIsCheckingPlan(false) }`
- Passed `onCheckPlan={handleCheckPlan}` and `isCheckingPlan={isCheckingPlan}` to `ConflictList` inside the Plan Status modal
