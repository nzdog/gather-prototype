# GTC-352 — event data is promised deleted after 12 months, and nothing deletes it

> Filed 2026-10-01 at [[GTC-288]]'s plan, on founder ruling D15, verbatim: _"GTC-352: the privacy
> page says event data is kept for 12 months after the event and then deleted. Nothing in Gather
> deletes it automatically. Not caused by this ticket, but the new reply line leans on it."_
> Severity blank. **Not a deploy precondition.**

**Status:** Open — a stub. Not scoped.

---

### Signal

`src/app/privacy/page.tsx`, *Data Retention*: _"Event data is retained for 12 months after the event
date, then deleted."_ No code in the tree does that. The scheduled routes under `src/app/api/cron/`
are `decide-by-followups`, `nudges`, `outbound-dispatch` and `wrap-up-dispatch`; none deletes an
event or its data. (Checked 2026-10-01, at [[GTC-288]]'s build.)

[[GTC-288]] added a line that leans on the promise: _"If you reply to one of our texts, we keep your
reply with the event it was about, and delete it with that event's data."_ Kept replies
(`TextReply`) cascade with their event and their person, so they go when the event goes — which, per
the above, is only when someone deletes it.

### Unknowns

1. Whether the promise is kept by building the deletion (a scheduled job, and what "event data"
   covers — including the opt-out history, which the same page says is kept permanently) or by
   changing the words.
2. Production's oldest event dates, which decide how much a first run would delete.
