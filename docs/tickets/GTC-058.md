# [[GTC-058]] — People modal role dropdown, table default, explanatory message — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** f57f200

### What was found

- **Role update API:** `PATCH /api/events/[id]/people/[personId]` already existed in `src/app/api/events/[id]/people/[personId]/route.ts`. Accepts `{ role?, teamId? }` and handles coordinator demotion automatically.
- **Role storage:** `PersonEvent.role` enum (`HOST`, `COORDINATOR`, `PARTICIPANT`) in Prisma schema. The host is identified by `Event.hostId` referencing `Person.id`.
- **Table view default:** Already set to `'table'` in `PeopleSection.tsx` state init — no change needed.
- **Host display:** The host's `PersonEvent.role` is returned from the API as stored. The fix ensures the host row always renders as HOST via `hostId` prop matching, with a disabled dropdown.

### What was changed

**`src/components/plan/PeopleSection.tsx`**
- Added explanatory message below the header: "Review your guests and assign coordinators to lead each team..."
- Replaced static role badge `<span>` in the table with a `<select>` dropdown per row
- Host row: dropdown locked to HOST (disabled), all three options visible but non-selectable
- Non-host rows: dropdown with Host (disabled), Coordinator, Participant options; onChange calls `handleUpdatePerson` via the existing PATCH API
- Added `handleRoleChange` callback wired to the existing `handleUpdatePerson` function
- Added `useCallback` import

### Known limitations / follow-up flags

- The EditPersonModal (opened via Edit button) also has a role dropdown but does not lock the host to HOST — it doesn't receive `hostId`. This is a pre-existing condition; the ticket scope covers the table-level dropdown only.
- The board view does not show role dropdowns (drag-and-drop is for team assignment). Role changes in board view still require the Edit button.
