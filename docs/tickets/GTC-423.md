## What this ticket does, in plain English

At the bottom of the board sits a row of five controls: "See menu", "See
assignments", "Change who's on what", "Invites & people" and "Print the
list". They were small grey underlined words, and they did not line up
(the links stood 24 pixels tall beside 18-pixel fold-out lines). Now all
five look like Moment 2's plain white buttons: a thin grey border, round
corners, black words, a light grey wash under the pointer. They all have
the same height, sit on the same line where they fit, and wrapped lines
have a small gap between them. Their words, their order and what each
one does are unchanged. "Invites & people" stays.

## Where the change is (read before editing, at 6b8c4ab)

One file: `src/components/glance/GlanceBoard.tsx`.

- A new constant after the imports, `DOOR_ROW_BUTTON_CLASS`.
- The row's `<div>` (was line 691): `mt-2 flex flex-wrap gap-x-4 gap-y-1`
  became `mt-2 flex flex-wrap gap-2`.
- Four `className` props (was lines 697-727) now read the constant:
  `PlanLists` (which hands it to both fold-out lines), the
  "Change who's on what" link, the "Invites & people" link and
  `PrintListDoor`. Four uses draw five controls.

`src/components/glance/PlanLists.tsx` is NOT changed: each summary draws
`${className} list-none [&::-webkit-details-marker]:hidden`, so the class
the board passes is enough. With `inline-flex` a summary is no longer a
list item, so it draws no marker in Chrome; Safari's marker stays hidden
by the class already there. Measured: the marker's list style is "none".

### The classes, old and new

```

  inline-block text-[12px] text-[#888780] underline underline-offset-2

  transition-colors inline-flex items-center text-black cursor-pointer
```

### Moment 2's text colour, measured

Moment 2's secondary buttons set no text colour: they draw the page's
own, which is black. Measured in a walled headless Chrome on the plan
view of "GTC-129 Test BBQ" (a draft), its "Invites, people and nudges ->"
button: colour rgb(0, 0, 0), 14px, 38px tall, 1px border
rgb(209, 213, 219), 8px corners, padding 8px 16px. No ancestor sets a
colour; the body is rgb(0, 0, 0). So the board's class says `text-black`
(rgb(0, 0, 0)), the same colour, written down so a later colour on the
board cannot change it.

Two words beyond the ruled string, and why:

- `text-black`: the ruling's "Moment 2's own dark text", as measured.
- `cursor-pointer`: links and buttons show a pointer anyway; a summary
  does not. Without it the two fold-out lines would lose the pointer
  they had (their old class carried `cursor-pointer`).
