# GTC-222 — Citation convention: cite symbols, not line numbers — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 9bccf42
**Effort:** High (as filed). **Severity:** Low — no behaviour change.

### Why

[[GTC-211]]'s citations drifted 17 lines and pointed at `onMaterialChange` (F1/[[GTC-183]]'s
hook) while describing `onAssignmentReleased`. Executing from those numbers edits the wrong
function and builds green. The correction document had the same defect as the document it
corrected. Line numbers rot; symbol names move with the code.

Confirmed at `7984652`: [[GTC-211]] addresses `onAssignmentReleased` as
`src/lib/ledger.ts:590-596`. In the current tree line 591 opens
`export async function onMaterialChange` — GTC-183 (F1)'s no-op hook, a different ticket's
property. `onAssignmentReleased` really begins seventeen lines further down (607). Both are
seven-line no-op stubs with near-identical shape, so an executor following the number lands
on a function that *looks* like the right one, edits it, and passes every gate.

**The rule already existed — in two places.** `gather-docs-and-writing` House style has
carried *"Cite code by symbol name, never by line number"* since [[GTC-158]] re-anchored the
library after [[GTC-154]]/[[GTC-156]] shifted citations twice in two days.
`gather-validation-and-evidence` repeats it for evidence fields, with the sharper reason:
*line numbers drift between the fix commit and the hash-backfill follow-up, so a line
reference is often stale by the time the ticket closes.* [[GTC-211]] was written anyway, by
an author with both rules available.

That is the actual finding, and **it is the justification for the template placement.** The
convention did not fail for want of existing. It failed for want of being written **where
citations get written** — a skill is loaded by topic, and "I am about to cite a line number"
is not a topic anyone loads a skill for. A rule that has been live since [[GTC-158]] and is
violated anyway is not a rule that needs restating; it is a rule in the wrong location.
Hence scope item 1 puts it in the template, which is opened by definition before a ticket is
authored, rather than in a fourth skill.

A third skill was actively contradicting it: `gather-frontier-and-roadmap` instructed
executors to *"record file:line or commit hash per epic item"*. Corrected here.

**Correction documents are the most fragile citation class, not the safest.** A correction
is written from a verified read at commit X; the fix it describes then lands and moves the
lines it cites. Being acted on is what makes it wrong. Observed three times: [[GTC-211]],
[[GTC-212]], and this sweep's own synthesis arithmetic.

The third instance is worth stating plainly, because it happened inside this ticket. The
sweep's synthesis pass reported "8 of 13 stubs, 46 of 246 citations" while its own
per-ticket rows summed to 9 and 51 — a correction document miscounting the corrections. The
table below carries the recomputed figures. A document whose purpose is to be trusted about
numbers is exactly the document that must be re-derived, not read.

### Scope

1. **Ticket template.** Citations are `` `symbol` `` in `` `file` `` (+ commit hash for
   precision). Line numbers permitted only as a parenthetical hint, never as the address.
2. **ANCHOR tokens** for locations with no symbol — a branch arm, or a spot where something
   should go and doesn't yet: `// ANCHOR(GTC-nnn): short label`. Grep-shaped on purpose.
   Not prose.
3. **Comment rule.** A comment may record WHY, or that a state is provisional. It may not
   assert WHAT the code does — that is a test's job, and that assertion is what went false
   in `onAssignmentReleased`.
4. **Backward link.** Deliberate temporary states carry the ticket ID that ends them. First
   instance: `ignoreDuringBuilds: true` → GTC-221.
5. **Sweep** sibling stubs GTC-209–221 for the same drift, filed in one session at one
   commit and drifting since. Read-only; report, don't fix.

### Out of scope

Retro-citing closed tickets. Convention applies forward.

### Sharpest cases (each re-verified by hand at `7984652`)

- **[[GTC-209]]'s transaction argument inverts itself.** The ticket's load-bearing claim is
  that `generateWrapUpLinks` is called *outside* the `$transaction`. `wrap-up/route.ts:106-108`
  now sits **inside** the `$transaction` callback, on the `tx.event.update` call. The pointer
  asserts the opposite of the argument it was cited to support. The conclusion still holds at
  the real call site — the citation is what turned around.
- **[[GTC-210]] directs the edit to the wrong function.** Scope says to put the quiet-hours
  guard in `dispatchPendingWrapUpMessages`. `wrap-up.ts:157` is a `token,` field inside
  `generateWrapUpLinks` — the row *writer*, not the *dispatcher* (`generateWrapUpLinks` opens
  at 107, `dispatchPendingWrapUpMessages` at 183). Cited twice, including in the one section
  that tells the executor where to type.
- **[[GTC-212]] is a correction document whose corrections are all wrong.** It exists partly to
  fix [[GTC-206]]'s stale citations and states "the current locations are…". All four
  replacements have themselves drifted. The one sentence telling the next person what to trust
  is wrong on every number — the same defect [[GTC-211]] has, in a ticket written to cure it.
- **[[GTC-212]]'s prescribed check does not run.** Its read-only SQL selects
  `AuditEntry."createdAt"`. No such column: `model AuditEntry` has `timestamp`. This one fails
  loudly, which makes it the *least* dangerous of the set.
- **[[GTC-216]]'s migration coordinates edit enum bodies.** The one-statement migration adds

  four enum declarations ending at `enum PatternConfidence` (1062); the companion index citation
  lands on that enum's members.
- **[[GTC-211]] names a method that does not exist — but the line is right.** It scopes "one

  positional drift — the coordinate holds and the verb is wrong. Counted in the table row

### What the sweep actually shows

Every one of these citations was correct when written, and the substance of nearly every claim
still holds. What moved was the coordinates, not the facts.

Three tickets were invalidated by **their own fixes landing** — [[GTC-209]] and [[GTC-210]]
each inserted lines above their own cited points, so the ticket that shipped the change is the
ticket whose evidence it broke. The rest were invalidated by neighbours: one unrelated pair of
commits ([[GTC-174]]/[[GTC-175]]) grew `prisma/schema.prisma` by ~84 lines and invalidated
every schema coordinate across three tickets at once.

The four clean stubs are the control group, and they are decisive. [[GTC-217]] and [[GTC-219]]
cite no line numbers at all and are structurally immune — they cannot drift. [[GTC-218]] and
[[GTC-220]] cite one range each and both still land, having simply not been near a churning
file. Immunity tracked citation *style*, not author care.

So the failure mode is not sloppiness. A line number encodes a fact about a file's layout at
one instant; a symbol name encodes a fact about the code. Only the second is what a ticket
means. And the dangerous residue is the silent class: a deleted path or an off-by-one throws,
but a citation that drifts onto `onMaterialChange`, or onto the day-restore block, or into the
transaction it claims to sit outside of, produces a clean edit to the wrong construct — and a
green build.

### Unknowns — resolved

**Should the rules also reach `GATHER-BUILD-CONSTANTS.md`?** This ticket stopped rather than
deciding it, because the constants file is binding doctrine on every future session and
`gather-docs-and-writing` treats edits to it like schema migrations.

The argument for reach: the templates are read by whoever *authors* a ticket; the constants
file is read by whoever *executes* one. [[GTC-211]]'s drift was authored, but it would have
been consumed by an executor who never opened a template.

**Ruled 2026-08-10: pointer only.** A one-line pointer in Executor Preamble step 2, naming
the canonical Citations section as binding on every ticket type. The rules are not restated
there — a doctrine file carrying its own copy of a convention is a second thing to keep in
sync, and this ticket exists because conventions do not stay in sync.
