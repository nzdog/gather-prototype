# GTC-087 — Fix "Start assigning teams" CTA to open People modal on Board view — CLOSED
**Status:** Complete | **Branch:** master | **Commit:** a8d2082

### What was found
The "Start assigning teams" button in `NextStepBanner` called
`handleExpandSection('teams')`, opening the Teams modal. The intended
behaviour is to open the People modal on Board view so the host can
drag-and-drop people between teams.

`PeopleSection` had no way to receive an initial view from outside —
its `view` state was hardcoded to `'table'`.

`handleCloseExpansion` is a shared handler used by all `SectionExpandModal`
instances — it is the correct place to reset `peopleInitialView` back
to `'table'` so that non-banner opens default to Table view.

### What was changed

**`src/components/plan/PeopleSection.tsx`**
- Added optional `initialView?: 'table' | 'board'` prop to
  `PeopleSectionProps`
- Destructured `initialView` in component params
- Changed `useState` initialiser from `'table'` to
  `initialView ?? 'table'`

**`src/app/plan/[eventId]/page.tsx`**
- Added `peopleInitialView` state (`useState<'table' | 'board'>('table')`)
- Passed `initialView={peopleInitialView}` to the `PeopleSection` instance
- Added `setPeopleInitialView('table')` in `handleCloseExpansion` to
  reset on any modal close
- Changed banner CTA from `handleExpandSection('teams')` to:
  ```
  setPeopleInitialView('board');
  handleExpandSection('people');
  ```

### Known limitations
- `initialView` sets the `useState` default but does not force-sync on
  re-render. This is correct because the modal unmounts on close (via
  `SectionExpandModal`), so a fresh mount picks up the new `initialView`
  each time.
