## Scope

### Phase 1 — Audit

Before any deletion, confirm:

a. **Location.** Find the `/demo/review` page file. Report its full path.

b. **What it does.** Read the page component. Report:
   - What UI it presents
   - Which API endpoints it calls (specifically confirm the `/generate` call, and whether it
     exercises the `keepItemIds`/`regenerateItemIds` selective branch — relevant to [[GTC-239]])
   - Any imports it uses that only exist to serve `/demo/review`

c. **Reachability.** Search for links or navigation entries pointing to `/demo/review`:
   ```
   grep -rn "/demo/review" src/ --include="*.ts" --include="*.tsx" --include="*.md"
   grep -rn "demo/review" src/ --include="*.ts" --include="*.tsx"
   ```
   Report every hit. If any live navigation link points to it, surface for reconsideration of
   the Phase 0 decision before deletion.

d. **Supporting files.** Is `/demo/review` part of a larger `demo/` directory with siblings,
   or standalone? If siblings exist, is deleting `/demo/review` safe or does it destabilize
   the `demo/` area?

e. **Sole callers.** Any imports/helpers that exist *only* for `/demo/review`'s benefit and
   would become dead code after removal? Report so they can be deleted in the same pass.

Stop after Phase 1 and surface findings. Wait for approval before Phase 2.
