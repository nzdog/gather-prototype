# GTC-088 — Board View: Role colour tints, items button, and reassign items flow — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** 8180a6c

### What was found

- **Board view card location:** `src/components/plan/TeamBoard.tsx` — `DraggablePersonChip` component renders the person card at line 97 with hardcoded `bg-white`.
- **Tailwind palette:** Custom palette has `sage` (green), `accent`, and `warm` tokens. Standard Tailwind `amber-50` and `blue-50` are available by default and provide the warm/cool tints needed without adding new tokens.
- **Items badge:** Rendered as a `<span>` at line 126–130 in `DraggablePersonChip`. No `onClick` handler — purely visual.
- **Edit Person modal:** `src/components/plan/EditPersonModal.tsx` — opened via `handleEditPerson` in `PeopleSection.tsx`, controlled by `editModalOpen` state. Shows assigned items section but no reassignment button.
- **Teams modal:** Rendered in `src/app/plan/[eventId]/page.tsx` lines 2422+. Team accordion expansion controlled by `expandedTeams` Set state. No `initialExpandedTeam` prop existed — added as new state.
- **Modal transition pattern:** The plan page uses `pendingModalAction` ref + effect to close one expansion modal and open another on the next render cycle (established for "Generate Plan" flow).

### What was changed

**Change 1 — Role colour tints (TeamBoard.tsx):**
- Added `getCardTint()` helper: returns `bg-amber-50` for HOST, `bg-blue-50` for COORDINATOR, `bg-white` for all others.
- Applied `getCardTint(person.role)` to the `DraggablePersonChip` card element, replacing hardcoded `bg-white`.
- Table view cards in `PeopleSection.tsx` are unchanged.

**Change 2 — Items badge opens Edit Person modal (TeamBoard.tsx):**
- Converted the items badge from `<span>` to `<button>` with `onClick` calling `onEditPerson?.(person)`.
- Added `cursor-pointer` and `hover:bg-sage-200` for interactivity signal.

**Change 3 — Reassign items flow (EditPersonModal.tsx, PeopleSection.tsx, page.tsx):**
- Added `onReassignItems?: (teamId: string | null) => void` prop to `EditPersonModalProps`.
- Rendered "Reassign items →" button below assigned items list, above Save/Cancel, styled as secondary button (`bg-gray-200 text-gray-700 hover:bg-gray-300`). Only rendered when `person.itemCount > 0`.
- Added `onReassignItems` prop to `PeopleSectionProps`. PeopleSection wraps the callback to close the edit modal before forwarding.
- In plan page: added `initialExpandedTeam` state. The `onReassignItems` handler sets `initialExpandedTeam`, sets `pendingModalAction` to `'reassign-items'`, and calls `handleCloseExpansion()`.
- Added effect: when `expandedSection === 'teams'` and `initialExpandedTeam` is set, pre-expands that team's accordion and loads its items.
- `initialExpandedTeam` is reset to `null` in `handleCloseExpansion()` (same pattern as `peopleInitialView` from GTC-087).

### Known limitations

- The reassign items flow only works from the People expansion modal (not the inline PeopleSection on the dashboard), because only the expansion modal passes the `onReassignItems` callback. The dashboard PeopleSection doesn't have a Teams modal to navigate to.
