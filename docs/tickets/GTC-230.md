# GTC-230 — STUB: a seed script can permanently break `npm run test:security`

**Status:** Open — stub, needs scoping when pulled. **Effort:** Low.

*Source: GTC-214's preflight, 2026-08-15. Filed rather than fixed, per the house rule that
a pre-existing issue found in passing is not the finding ticket's to fix.*

## Signal

`npm run test:security` — the preflight gate — aborts before a single assertion runs:

```
Fatal error:
Invalid `prisma.person.deleteMany()` invocation in tests/security-fixtures.ts
Foreign key constraint violated on the constraint: `Event_hostId_fkey`
    at async cleanup (tests/security-fixtures.ts)
    at async main (tests/security-validation.ts)
```

Zero tests run. The gate reports failure without ever reaching the contract it guards.

## Cause

`cleanup` in `tests/security-fixtures.ts` deletes events by name (`EVENT_NAMES`, all of the
form `Security Test Event (*)`), then deletes fixture Persons by email
(`*@test.local`, `security-test@gather.test`). If a fixture Person hosts **any event whose
name is not in that list**, the Person delete violates `Event_hostId_fkey` and the suite
dies.

`scripts/seed-gtc-133-test-event.ts` creates exactly that. It resolves its host User by
falling back through: `SEED_HOST_EMAIL` → `nigel@mckorbett.co.nz` → **first existing User
by `createdAt` asc** → a new fallback user. On a machine where the security fixture user is
the oldest row, the third branch selects it; the script then finds that user's Person
(`Security Test Host`) and creates `GTC-133 Sub-commit (g) Test` hosted by it.

Observed 2026-08-15: event `cmstsv8up00011ymuhd8r63av`, DRAFT, hosted by
`security-test@gather.test`. Deleting that one event restored the suite to 51/51.

## Why it matters more than a stale row

The breakage **persists across runs and is not self-healing** — `cleanup` is the very thing
that cannot complete, so re-running never clears it. Anyone who runs that seed silently
loses their preflight gate until they diagnose a foreign-key error in a file they were not
working on. The failure names neither the seed script nor the event.

## Needs scoping when pulled

Candidate directions, not a ruling:

- Make `cleanup` resilient — null out or delete events hosted by fixture Persons before
  deleting the Persons, so no external row can wedge it.
- Stop the seed selecting an arbitrary "first existing User": require `SEED_HOST_EMAIL`, or
  exclude known fixture emails from the fallback.
- Both. They fix different halves: one stops the collision, the other stops any future
  collision from being fatal.

Also worth checking whether the other `scripts/seed-*.ts` and `create-*.ts` helpers share
the "first existing User" fallback.

## Do not touch

`tests/security-*.ts` is Do-Not-Touch zone 6. Making `cleanup` robust is not weakening an
assertion, but it is a change inside the zone and needs explicit instruction — which is
part of why this is filed rather than fixed.
