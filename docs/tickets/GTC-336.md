# GTC-336 — ruling S's lookup and ruling U's door disagree about whose message a child's was

**Status:** Open — a stub, filed 2026-09-28 at [[GTC-305]] on founder ruling (*"File, don't fix"*).
Not scoped.

> ⚠ **CANDIDATE PRECONDITION OF THE [[GTC-311]] + [[GTC-189]] SLICE 8 DEPLOY — founder ruling,
> 2026-09-28, beside [[GTC-251]] and [[GTC-329]].** Severity set by the founder the same day:
> MEDIUM, as proposed.

---

### Signal — two defects, one cause

**1. The door refuses a carried child with a false sentence.** A carried child can read red
`NOT_DELIVERED` through ruling S (*"Ollie's strip goes red when the message carrying his ask
bounced"*). `doorOffered` in `src/lib/glance/actions.ts` keys on reasons, so the child's panel
offers the door. The door's GET — `resolveSubject` in `src/lib/press/resend.ts` — reads ASK rows for
the CHILD's own membership (`personEventId: membership.id`). A child never has one, so
`deliveryFactFrom` finds no failure and it refuses 409 `NOTHING_FAILED`:

> Their last message did not fail, so Gather has nothing to try again.
> (`RESEND_REFUSAL_WORDS.NOTHING_FAILED` in `src/lib/press/resend-door.ts`)

That is false for that child: the message carrying their ask did fail. Confirmed by reading the
code at [[GTC-305]]; the runtime check is recorded in GTC-305's Evidence.

**2. Ruling S's lookup reaches children the message never carried.** `readEventGlance` finds a
child's carrier with `carrierMembershipFor` in `src/lib/glance/delivery-fact.ts`, which follows the
household's CONTACT (`contactPersonEventId`, else PRIMARY_CONTACT) — not the chooser's ladder. Its
docstring names that limit. So three children inherit a bounced ASK row their item was never in,
and read red `NOT_DELIVERED`:

- a host's-household child whose household contact is another adult (under ruling A the child's
  item went to the host's list, not into that adult's message);
- a host's-household child whose contact is the host, when the host holds an A2 carried row that
  bounced;
- a child with no items, in a household whose contact's ASK row bounced (nothing was ever asked of
  them).

Each is pinned AS BUILT — labelled as the built behaviour, not the wanted one — in
`tests/board-not-chased-test.ts` layer D (the three *"AS BUILT (point 3)"* assertions). They flip
when this is fixed, and they should. The door is then offered to these children too, and refuses
them with the same false sentence.

### The likely shape of a fix — not built

Either the door resolves the carrier as ruling S does (and ruling S resolves it as the chooser
does, so only children whose ask really rode in the failed message inherit its failure), or the
door is not offered on a child's strip at all and the carrier's own strip carries it.
