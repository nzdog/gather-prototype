# GTC-055 — Items & Quantities card shows stale count after Teams modal assignments — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** [fill after commit]

### What was found

`handleCloseExpansion()` in `src/app/plan/[eventId]/page.tsx` (line 471) only removed the `expand` query param and cleared breadcrumbs — it did not re-fetch any dashboard data. When the user made assignments via `handleQuickAssign` inside the Teams expansion modal, that function called `loadTeamItems()` and `loadTeams()` but NOT `loadItems()`. The Items & Quantities card reads from the `items` state array, which remained stale after the modal closed.

**Cards affected:**
- **Items & Quantities** — `items` state not refreshed after Teams modal assignments
- **Teams** — `teams` state not refreshed after Items expansion modal edits
- **People** — `people` state not refreshed after People expansion modal changes

### What was changed

**`src/app/plan/[eventId]/page.tsx`**
- Added `loadItems()`, `loadTeams()`, and `loadPeople()` calls to `handleCloseExpansion()` so all dashboard cards refresh when any expansion modal closes. This follows the existing data-fetch pattern used throughout the page (e.g., after plan generation, after transition modal success).

### Known limitations / follow-up flags

- `loadConflicts()` is not called on expansion close — conflicts are not modified by expansion modals and are loaded via separate triggers (Check Plan, conflict resolution). No staleness observed.
- The three fetch calls are fire-and-forget (not awaited) which is appropriate here — the modal is already closing and the dashboard will update as responses arrive.
