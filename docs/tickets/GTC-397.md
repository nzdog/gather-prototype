## Design

- The DECISION moves into `scripts/lib/deploy-audit-decide.mjs`: pure
  functions from the audit JSON and the lockfile JSON to the failures, the
  notes and the listing. No import at all (no fs, no child process, no
  network). The script stays the thin wrapper: it runs `npm audit
  --package-lock-only --json`, reads `package-lock.json`, and prints.
- The walk: for each of the four, start at every lockfile copy of it; follow
  `dependencies`, `optionalDependencies` and `peerDependencies`, each
  resolved as node does (the nearest `node_modules/<dep>` walking up from the
  depending copy's own path; a dependency that resolves to nothing, such as
  an optional package for another platform not in the lockfile, is skipped).
  Breadth first, so each flagged copy is named by its shortest chain, top
  first. A copy counts only if npm's `nodes` for that package name list that
  exact path, so of two copies only the reachable flagged one counts.
- The labels are today's: `<top> <- ... <- <pkg>: <GHSA> <severity>`; the
  top package alone when it is itself flagged (`axios: GHSA-... high`).
  Failures are de-duplicated as today.
- A lockfile that cannot be read: exit 2, as an unreadable audit is
  (nothing was checked). This is new, and fails safe.
