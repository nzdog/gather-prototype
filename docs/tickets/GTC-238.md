# GTC-238 — Kate types a note; the server throws it away; the UI says it saved

**Status:** Complete | **Effort:** as predicted — four lines, two routes

*Source: [[GTC-236]] Phase 1 audit + founder ruling Q1 ("notes counts as an edit"),
2026-08-22. Founder ruling: separate track from GTC-236, severity high. Derived from code
at `cfa6845`.*

## Signal

**Expected:** editing an item's notes in the V2 plan view persists the note, and — per the
Q1 ruling — counts as a substantive edit (flips `GENERATED → HOST_EDITED`, protecting the
item from regeneration).

**Actual:** `onUpdateItem` in `src/app/plan/[eventId]/setup/page.tsx` sends `body.notes`,
but the `PATCH` handler in `src/app/api/events/[id]/items/[itemId]/route.ts` never reads it —
`notes` appears nowhere in its `updateData` construction. The note is dropped server-side
while the plan view's optimistic local-state patch makes it LOOK saved until reload.

**Smallest failing case:** V2 plan view → Edit an item → type a note → save → reload.
Note gone.

## Also in scope (same ruling)

- Add `notes` to `substantiveFieldsBeingEdited` in the same handler (the ruling's actual
  content: a note is Kate's manual work and must protect the item from regeneration).
- `PATCH` in `src/app/api/c/[token]/items/[itemId]/route.ts` PERSISTS notes (hint: ~69) but
  omits it from its substantive check (~45-55) — add it there too.

## Evidence (Executor-Completed)

**Root cause confirmed:** the `PATCH` handler in
`src/app/api/events/[id]/items/[itemId]/route.ts` built `updateData` without ever reading
`body.notes`, returned `200 success: true` regardless, and the plan view's optimistic state
masked the loss until reload. `notes` was also absent from `substantiveFieldsBeingEdited`
and from `TRACKED_ITEM_FIELDS`, so even had it persisted it would have neither protected the
item from regeneration nor been versioned.

**Fix:** host route — `body.notes` into `updateData`, into the substantive set, and into
`TRACKED_ITEM_FIELDS`; `/c/` token route — `body.notes` into its substantive check (it
already persisted notes). Four lines, two files. Scoped per founder ruling as its own
commit, separate from GTC-236.

**Test-first, live wire (severity High):**

- RED (pre-fix): `PATCH {notes: 'GTC-238 RED test note'}` → 200, yet DB notes unchanged
  (still the AI's original text), source still `GENERATED`. Silent-success confirmed.
- GREEN (post-fix): same call → notes persisted verbatim, source flipped `HOST_EDITED`,
  AND a ledger row landed (`EDIT_ITEM`, `field: notes`, sequence 8) — the versioning axis
  the tracked-fields line exists for.
- Gates: typecheck clean, `test:security` 51/51, `console.log` 0.

The in-process route test the template prefers is blocked by session auth
(`requireEventRole` reads a cookie — the same reason `clearPlanForRegeneration` was
extracted for testability); the live-wire RED/GREEN through the authenticated browser
session is the honest equivalent and is quoted above.
