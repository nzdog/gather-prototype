# GTC-161 — Step 1 autosave swallows failures — CLOSED

> Captures a finished, verified client fix that had been sitting uncommitted
> in the working tree across earlier sessions. Committing it here prevents
> loss and pays down the recurring "reason around the dirty tree" tax.

## 1. Bug signal
GTC-151 fixed the *server* side of the setup-route event-type allowlist, but
its checklist item "autosave paths surface failures" was never done. In
`src/components/plan/Moment2Step1Modal.tsx`, `saveToApi` fired the autosave
`fetch` and never checked `res.ok`. Because `fetch` only rejects on network
errors (not HTTP 4xx/5xx), any non-2xx response fell through the `try`, the
empty `catch` never ran, `saving` flipped off as if it succeeded, and the
host's Step 1 edits silently failed to persist.

**Expected:** a rejected setup save surfaces an error; generation does not
proceed on unpersisted edits.
**Actual (pre-fix):** silent success; edits lost on reload; `finalize-plan`
could run against stale/absent setup.

**Severity:** High — silent data loss (same class as GTC-151).

## 2. Fix (in `Moment2Step1Modal.tsx`)
- `saveToApi` checks `res.ok`; on non-2xx reads the route's `error` message,
  sets a new `saveError` state, returns `false`; on success clears it and
  returns `true`. Network errors also set `saveError` instead of being
  swallowed.
- `handleGenerate` guards on the flush-save result — returns early if the
  final save failed (does not generate off unpersisted edits).
- The sticky footer renders `saveError` as a `role="alert"` message above the
  Generate button. Debounced/accordion-close saves surface via the same
  state, which self-clears on the next successful save.

## 3. Evidence
- `tsc --noEmit` clean · `format:check` clean.
- **Test-first escape hatch (High):** no React component test harness exists
  in-repo (the tsx test pattern is DB/pure-logic only; cf. `moment1-input-test.ts`).
  Automated RED→GREEN for a client-state/DOM behaviour is not feasible with
  the current harness. **Substitute gate:** typecheck clean + code review of
  the swallow removal. **Recommended follow-up:** a browser walk (force a
  setup-route 400, confirm the alert shows and Generate is blocked) when a
  component harness is available.

## 4. Acceptance assertions
- [x] `saveToApi` returns a boolean and sets `saveError` on any non-2xx or
      network failure (no silent swallow).
- [x] `handleGenerate` does not call `onGenerate()` when the flush save fails.
- [x] `saveError` is rendered to the user (`role="alert"`).
