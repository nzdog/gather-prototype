### Signal

Found by Claude Code planning [[GTC-357]] and [[GTC-358]], 2026-10-03, verbatim: *"A Moment-flow
event can't be sent from the Moment flow alone. The press refuses any event not in CONFIRMING ...
No step of Moments 1 to 3 or the pre-flight moves an event out of DRAFT. Only the old dashboard
does: its checklist banner's button, or its "Move to CONFIRMING →" card (GateCheck) ... Every
fixture so far (GTC-355, GTC-356, these) set CONFIRMING directly, which is why it never showed."*

### What the code shows (Cowork, read 2026-10-03 at `c6e7b3a`)

- The press refuses an event not in CONFIRMING with `NOT_CONFIRMING`
  (`src/lib/press/press-words.ts`): *"This event is not ready to send yet. Finish the plan first and
  come back."*
- The one way out of DRAFT is `POST /api/events/[id]/transition` (HOST only), whose only caller is
  `src/components/plan/TransitionModal.tsx` on the old dashboard. It runs
  `transitionToConfirming` (`src/lib/workflow.ts`): the gate check, then a `PlanSnapshot`, status
  `CONFIRMING`, `structureMode: 'LOCKED'`, and `ensureEventTokens` (the guests' links).
- The gate (`runGateCheck`) blocks on: a CRITICAL conflict with no acknowledgement; a critical item
  with a placeholder quantity not acknowledged; no team; no ITEM row; an event not in DRAFT.
  Unassigned items never block (*"Note: ALL_ITEMS_ASSIGNED is NOT required"*).
- Moment 3 re-runs the conflict check only once a check has been run (`lastCheckPlanAt`), and the
  Moment flow has no screen to acknowledge a conflict or a placeholder quantity.
- 61 test files set `status: 'CONFIRMING'` on their fixtures directly.
- [[GTC-357]]'s R2 retires the checklist banner on Moment-flow events, so until this ticket lands
  the only way to CONFIRMING is the old dashboard's "Move to CONFIRMING →" card.

### The ruling

Asked in Cowork, 2026-10-03, verbatim:

> Claude Code found a gap: a Moment-flow event can't be sent from the Moment flow at all. The send
> button refuses any event that hasn't been through the old dashboard's "Move to CONFIRMING" step,
> which takes a snapshot of the plan, locks its shape and makes the guests' links. Nothing in
> Moments 1 to 3 or the pre-flight does that step, so a host would hit "This event is not ready to
> send yet". Your Moment 3 document says "When she's done, the plan is held." When should that step
> happen?

The founder's answer, verbatim: **"On "Move on" from Moment 3 (Recommended)"**. The option read:
*"Moving on from Moment 3 holds the plan, as your document says, then opens the pre-flight. If
something blocks it (a serious clash in the plan, or an important item still without a quantity),
Moment 3 says what and how to fix it. Fixed before launch, as a new ticket, GTC-360."*

### What it settles

- **"Move on →" from Moment 3 holds the plan** — the existing DRAFT → CONFIRMING transition, with
  its gate, snapshot, lock and links — and then opens the pre-flight. It matches the founder's
  Moment 3 document: *"When she's done, the plan is held."*
- **A block is shown in Moment 3**, with what it is and how to fix it there.
- **A precondition of the deploy.**

**W4's target, checked before building (as the ruling asked).** The old dashboard's Items & Quantities
section (`/plan/[id]?expand=items`) lists every item with an Edit button, on V1 and Moment-flow
events alike; the item editor sets a quantity ("Specified", with an amount) or keeps "Placeholder
(TBD)" with its acknowledgement checkbox — either clears the gate's critical-placeholder block. So W4
and its link point to the right place.

**Correction, 2026-10-03 (Claude Code's, found planning this ticket).** This ticket's note *"until
this ticket lands the only way to CONFIRMING is the old dashboard's "Move to CONFIRMING →" card"* is
not true of the code: that card (`GateCheck`) renders inside a hidden `div` on the old dashboard, so a
host never sees it. The only visible way was the setup checklist banner's button, which [[GTC-357]]
R2 retired from Moment-flow events. So between [[GTC-357]]'s commit and this ticket, a Moment-flow
event has no visible way to CONFIRMING at all.

**Q6, recorded as ruled:** on Moment-flow events the old dashboard hides the "Before you send" /
"Freeze Plan" card (a dead end once CONFIRMING) and the stage-progress strip (V1 words). This
reverses [[GTC-357]]'s Q8, whose premise — that the strip leads to "Move to CONFIRMING →" — was
wrong, for the reason above. Noted in [[GTC-357]] too.

**Root cause, as found.** Nothing in Moments 1 to 3 or the pre-flight moved a Moment-flow event out of
DRAFT, and the press refuses anything not in CONFIRMING. The old dashboard's "Move to CONFIRMING →"
card is rendered hidden, and the checklist banner's button — the one visible way — was retired from

**What was built**
- **The hold** — `src/lib/moment3/hold.ts` (new, client-safe): `holdThePlan` asks the transition that
  already exists (`POST /api/events/[id]/transition`; the route and `transitionToConfirming` are
  unchanged) and `holdOutcomeFrom` says what its answer means — held (`GO`), a block (an empty plan
  first, then a serious clash, then a missing quantity), a co-host (`NOT_HOST`, Q3), or a failure. A
  held but unsent event goes on without asking (Q4); an "already held" answer goes on too.
- **"Move on →"** — every completion panel's button. The setup page's handler keeps [[GTC-357]]'s
  target ternary and calls `moveOn`: a sent event goes to the board; an unsent one is held, then
  opened on the pre-flight. "Keep going" never holds. While it works the button reads W1 and is
  disabled (Q9: no double hold).
- **In Moment 3** — inside the completion panel (`data-m3="hold-notice"`): W3 with "Open Plan Status"
  (`/plan/[id]?expand=planstatus`), W4 with "Open Items & Quantities" (`/plan/[id]?expand=items`), W5,
  W6 for a co-host, W2 for a failure. `Moment3AssignView` asks no route for it; the request lives in
  the helper. "The plan is held. Now let's make sure everyone knows." is unchanged, and is now true
  once she moves on.
- **The pre-flight on a DRAFT event** — the press's NOT_CONFIRMING sentence is W7 (Q5).
- **The old dashboard, Moment-flow events only (Q6)** — the stage-progress strip and the "Before you
  send" / "Freeze Plan" card are hidden; V1 events unchanged. This reverses [[GTC-357]]'s Q8 (noted
