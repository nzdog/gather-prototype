# GTC-480 - Multi-day: Moments 2 and 3 by session

Base: origin/main 3f656d9 (24 Nov 2026, the merge of pull request #121,
GTC-479). The founder's multi-day rulings are in [[GTC-476]]; the foundation
is [[GTC-478]]; Moment 1's sessions card and the date rule are [[GTC-479]].
In the code a session is a `Day` row; the screens say "session" (Q1). All
dates and times are NZ time.

Everything here is behind `GATHER_SESSIONS`. With it off, nothing a host or
guest sees, receives or is nudged about changes.

The brief asked for eight parts, A to H. At the plan the founder split it
(ruling 1): this ticket builds A, B, C and H, the host's planning screens.
D, E, F and G (the deadline, the guest page, the board, the pre-flight) are
[[GTC-485]], built after this ticket merges.

## The founder's words and rulings that govern this ticket (from the brief)

- 22 Nov: "Set up, if the event goes over more than 1 day, how do we allow
  hosts to plan it? Can we have tabs for each day?"
- Q8: a dish's decide-by counts back from its own session's date.
- Q9: a dish may have no session ("whole event").
- Q12: a shared dish splits only within one session.
- Q13: changing a dish's session counts as changing the ask.
- GTC-479's date rule: every session date is read through
  `src/lib/sessions/dates.ts`, never from the stored time.

## What planning found (24 Nov 2026)

- **D cannot be built inside the brief's hard limits.** The deadline reaches
  a guest only through the maybe follow-up. Its finder
  (`src/lib/sms/decide-by-eligibility.ts`) and its email retry
  (`src/lib/sms/decide-by-sender.ts`) load each dish without its session, so
  for `neededBy` to count from the session both must load the session's
  date. `tests/tweaks-guard-test.ts` classes the finder as a Zone 7 file and
  the sender as a Zone 9 file, both held byte for byte since 21a9577; the
  brief keeps Zones 7 and 9 untouched. And `tests/decide-by-clock-test.ts`
  (line 287) checks that `neededBy()` is byte-identical: changing it turns an
  existing decide-by check red, which the brief calls a stop.
- **G changes what is sent.** The pre-flight's draft first line is also the
  line the send uses whenever the host has not saved one of their own
  (`composeAsk`, `src/lib/messages/ask-register.ts` line 525).
- **Every screen D to G touches is held byte for byte by older tests:** the
  guest page (tweaks-e P1, tweaks-i P1, demo-board G1), the pre-flight page
  (tweaks-d P1, tweaks-f P1, demo-board L2), the board (tweaks-g P1, tweaks-h
  P1, demo-board T3, demo-replies B4) and every glance file (share-a-dish
  J2).
- So the plan recommended the split the founder ruled (ruling 1).

## The plan (as approved, 24 Nov 2026)

**The session plan.** The switch already reaches the setup page through
GTC-479's layout. One new piece sits there, inside the switch: while the
switch is on, it asks the existing sessions route (GET
`/api/events/:id/sessions`, GTC-479's, behind the switch) for the event's
sessions when Moment 2 or Moment 3 opens, and remembers the open tab, so
Moment 3 opens on the tab Moment 2 last showed. With the switch off it asks
nothing and changes nothing. No new route, no migration.

**A. The tabs** (Moment 2's plan view and Moment 3's "Who's on what?").

- Shown only when the switch is on and the event has at least one session.
- One tab per session in date order (GTC-479's order), then "Whole event".
  Each tab shows its count of rows (dishes and jobs).
- It opens on the first tab that has a row; if none has, the first session.
- One tab's rows at a time. Moment 2 still shows every section, each with
  only the open tab's rows ("No items yet." where it has none), so "+ Add
  item" works on any tab. Moment 3 shows the sections that have a row on the
  open tab.
- Moment 2's count line, the marks key and an own plan's first-time line read
  the whole plan, as today. Marks for delete clear when the tab changes, so
  the floating "Delete N items now" never deletes a row out of sight.
- At 390 pixels the tab row scrolls sideways inside itself (the page never
  scrolls sideways). It is not fixed or sticky, so it never sits under the
  fixed bars.

**B. The session picker.**

- A "Session" list on "+ Add item" and on Edit in Moment 2, and in Moment 3's
  Details box, for dishes and jobs alike. A new row starts on the open tab's
  session.
- It saves through the page's one item save (`saveItemEdit`), which already
  asks "why" through the existing box for a change to an ask field after the
  send once the holder has answered. The session is already an ask field
  (GTC-477, Q13), so the save only has to send it. A whole-event row sends
  null.
- Moving a row to another session makes a drafted row the host's own (the
  item route already does this), so a regenerate keeps it. Regenerate is not
  session-aware until GTC-482: rows it drafts land on "Whole event". Nothing
  new is sent (the notify hooks are empty).

**C. Sharing a dish (GTC-472).**

- The server already gives the copy the source row's session.
- With the switch on, the split counts only the dish's rows in the pressed
  row's session (`src/lib/moment3/share-dish.ts`, `load`). A shared row later
  moved to another session leaves that split. Off: as today.
- On screen, the new copy carries the session, so it shows on the same tab;
  GTC-472's note after taking someone off a shared row (W8) looks for a
  same-named row in the same session only.

**H. GTC-479's notes.**

- Moment 1's card shows a session's date once when its name is only that date.
- "Coming to": "Change" and "Done" stay beside a wrapped line.
- The coordinator page's session list sorts through `sortSessions` while the
  switch is on; off, as today.

**Decision 2, Accept all and the counter.** "Want me to suggest?" suggests for
the whole event. "Accept all" accepts only the open tab's suggestions, and its
number counts them (GTC-365: "one tap accepts exactly the suggestions on
screen"). "X of Y items assigned.", the people panel's counts and "All sorted
→" stay the whole event's.

**The words (decision 4), word for word.**

- The tab row, read aloud: "Sessions"
- A tab: its name and count, "Christmas lunch (6)", with its date under it,
  "Thu 25 Dec", unless the name is only the date ("Thu 24 Dec (3)", once)
- The last tab: "Whole event (4)"
- The picker's label: "Session"; its choices "Christmas lunch, Thu 25 Dec" (or
  "Thu 24 Dec" alone when the name is only the date), then "Whole event"
- Moment 3, a tab with no rows: "Nothing in this session yet." and, on "Whole
  event", "Nothing for the whole event yet."
- Unchanged: "No items yet.", "Updated.", "Added.", the why box, the Accept
  all and counter words, every Moment 1 word.

**Files.** New: `src/lib/sessions/tabs.ts` (pure: the words, the tabs, the
"name is only the date" test) and `src/components/sessions/SessionTabs.tsx`

**The older pins that move**, each the narrowest way with a dated note naming

named hunks, each exactly once, the rest byte for byte); sessions-moment1 U3
