# GTC-314 — The family directory cannot be switched off

**Status:** Open — filed 2026-09-18 during [[GTC-262]]'s build | **Branch:** `feat/moment-one-redesign`
**Severity:** [ ] Critical [ ] High [x] Medium [ ] Low
Escalated (brand/trust risk): [ ] Yes [x] No — nothing here hands out a credential a guest
was not meant to have. It is about the host being unable to take the door away again.

*Filed on founder instruction, 2026-09-18: "The kill switch and Event.status are a separate
ticket and you should file it. Not folded in. A surface with no off switch, keyed on a
permanent id, is a different defect from the one this ticket fixes."*

---

### Signal

**Expected**
A link a host is told to share with the whole family can be withdrawn by the host, and stops
working when the event it belongs to is not live.

**Actual**
`GET /api/gather/[eventId]/directory` is keyed on `Event.id` alone. It never reads
`Event.sharedLinkToken`, never checks `Event.sharedLinkEnabled`, and never checks
`Event.status`. There is no other gate anywhere: `middleware.ts`'s `config.matcher` covers
`/p/`, `/h/`, `/c/`, `/api/p/` and `/api/c/` and does not name this path.

Three consequences, each measured below:

1. **The host's only switch does not close it.** `DELETE` in
   `src/app/api/events/[id]/shared-link/route.ts` sets `sharedLinkEnabled: false`, which
   closes `/join/[token]` and `POST /api/join/[token]/claim`. The directory is unaffected.
2. **It serves events in every status,** including `DRAFT` — a plan the host has not sent —
   and `FROZEN` — an event already over.
3. **There is nothing to rotate.** A shared link has a `sharedLinkToken` that could in
   principle be regenerated. The directory's key is the event's primary id, so anyone who
   has ever seen the link keeps it for the life of the event.

**Smallest failing case**
Switch the shared link off on a `CONFIRMING` event, then `curl` its directory with no
cookie: it still returns the full guest list and a working participant link per person.

### Reproduce

**Required state**
- Auth state: none. Every request below is unauthenticated.
- Event state: any. Measured on `CONFIRMING`, `DRAFT` and `FROZEN`.
- Multi-actor: [ ] Yes [x] No

**Steps**
1. Take any event id.
2. Confirm `sharedLinkEnabled` is `false` on it.
3. `curl http://localhost:3000/api/gather/<eventId>/directory` with no cookie.

**Observe:** HTTP 200 with the full people list and a live token per person.

**Measured 2026-09-18** (`gather_dev`, unauthenticated, no cookie), each on an event whose
`sharedLinkEnabled` is `false`:

```
Henderson Family Christmas 2025  (CONFIRMING, sharedLinkEnabled=false)
  42 people, 35 carrying a working participant link

Security Test Event (DRAFT)      (DRAFT,      sharedLinkEnabled=false)
  4 people

Security Test Event (SENT-LEGACY)(FROZEN,     sharedLinkEnabled=false)
  4 people
```

Only 1 of 29 events in `gather_dev` has `sharedLinkEnabled = true`. The other 28 have a
fully open directory regardless.

**Data setup**
Default seed is sufficient.

### Unknowns

⚠ **All three are product decisions, not implementation details. Per the house rule an
executor reaching them stops and asks rather than inferring.**

1. **Should `sharedLinkEnabled` govern both surfaces, or should the directory have its own
   switch?** One switch is simpler and matches the host's mental model — she was told to
   share one link. Two switches match the fact that these are genuinely two links with two
   audiences. The copy on the Family Directory card ("Share this single link with your whole
   family") currently implies one.
2. **What should a `DRAFT` event's directory do?** There is an argument that it should work:
   the host may want to circulate the list while planning. There is a stronger one that it
   should not, since `POST /api/join/[token]/claim` already refuses a non-`CONFIRMING`,
   non-sent event with "This event is not accepting responses" and the two surfaces
   disagreeing is how this class of defect keeps appearing.
3. **Is "off" a refusal or an empty list?** A refusal tells a caller the event exists. An
   empty list is indistinguishable from an event with no guests. [[GTC-262]] chose the
   non-oracle direction at the claim route for a reason that may or may not apply here,
   since an event id is not a guessed `personId`.
