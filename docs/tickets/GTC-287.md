# GTC-287 — a coordinator token that points at nothing

**Status:** Open — needs scoping when pulled | **Effort:** TBD

*Adjacency named during [[GTC-237]]'s investigation, 2026-09-12. Not fixed there.*

## Signal

`AccessToken.teamId` and `PersonEvent.teamId` are both `ON DELETE SET NULL`
(`AccessToken_teamId_fkey` in the init migration; `PersonEvent_teamId_fkey` changed to
`SET NULL` by `20260708005434_change_person_event_team_set_null`). So when a team is deleted:

- a coordinator's `AccessToken` survives with `teamId` NULL — a live credential scoped to a
  team that no longer exists;
- their `PersonEvent.teamId` is nulled, so they stop being that team's coordinator with no
  record that they ever were.

No constraint is violated. The unique index `AccessToken(eventId, personId, scope, teamId)` is a
plain unique index, and Postgres treats NULLs as distinct, so two nulled coordinator tokens for
one person coexist quietly.

**Where team deletes come from:** `sweepEmptyGeneratedTeams` after a regeneration (per-team,
[[GTC-237]]), `clearPlanForRegeneration`'s sweep on V1, and `DELETE
/api/events/[id]/teams/[teamId]`.

## Why it is filed and not fixed

It is an integrity smell, not a live incident: nothing observed has produced an orphaned token
in the development database, and coordinator tokens are issued from `PersonEvent.role` in
`src/lib/tokens.ts`, a V1-dashboard path that a V2 event reaches only by visiting
`/plan/[eventId]`. It touches Do-Not-Touch Zone 3 (AccessToken & TokenScope), so it needs its
own ticket and a security re-audit rather than a drive-by.

## Unknowns that need answering before scoping

- What does a nulled `COORDINATOR` token authorise today? `requireEventRole` and the `/c/[token]`
  routes have to be read before deciding whether this is cosmetic or a scope hole.
- Should the token be revoked, re-pointed, or left as an audit trace?

## Do not touch

Do-Not-Touch Zone 3 is the subject of this ticket, not an exception to it. Any change to token
issuance, validation or scope logic requires a full security re-audit per
`GATHER-BUILD-CONSTANTS.md`.
