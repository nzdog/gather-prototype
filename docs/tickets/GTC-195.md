# GTC-195 — K1: Clone-review / ghost-guest guard

**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** high

*Effort level is a proposal from the discovery-report ticket breakdown — run `/effort` manually
before execution.*

### Context

Moment 4 spec §10.10 (source supplied — this closes discovery-gap #16, which the original
discovery pass left unscoped because no source material existed in the repo at the time): when an
event is cloned forward, the guest list **never copies silently.** Time changes households —
people die, couples separate, families fall out — and a cloned list silently carrying a dead
relative into this year's event is the most painful default the product could ship. Cloning's
**first act** is a deliberate people-review: the old list presented for explicit
confirm/remove/edit per household before anything else proceeds. **Not an optional check.**

The discovery pass did not investigate any existing clone/duplicate-event mechanism specifically —
verify what exists (if anything) at ticket start rather than assuming greenfield.

### Scope

**Fix here:**
- Locate the existing clone/duplicate-event mechanism, if one exists in the repo (verify first;
  do not assume it's greenfield without checking).
- Insert the mandatory per-household review step as the **first act** of cloning — before any
  other clone processing (plan content, teams, items) runs.
- The review step: old list presented, explicit confirm/remove/edit per household required before
  proceeding — not a skippable dialog, not a default-confirmed state.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`.
- Whatever plan-content cloning logic exists beyond the guest list, unless the review step's
  insertion point structurally requires touching it (e.g. sequencing the clone pipeline so the
  review gates everything downstream) — if so, keep that change minimal and note it explicitly in
  the Evidence section.

### Dependencies

None.

### Acceptance

- [ ] Cloning an event with any existing mechanism now presents a mandatory per-household review
      before any other clone step runs.
- [ ] The review cannot be silently bypassed or defaulted to "keep everything."
- [ ] Each household can be independently confirmed, removed, or edited.
- [ ] `npx tsc --noEmit` clean, build passes.
- [ ] Browser walk: clone a seeded event, confirm the review gate blocks progress until addressed.

   and report before proceeding, since that changes the effort estimate materially.
