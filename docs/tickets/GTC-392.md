## The visitor's path (as discussed)

- Start: "Try Gather" makes her own sample event. The $25 payment is skipped.
  A banner says it is a demo and to use made-up names.
- Moment 1: she types a few households; a demo-only "Add a crowd" button
  adds about 30 invented people in households.
- Moment 2: she answers the questions, or a demo-only button fills typical
  answers. The plan is made by a capped real AI call.
- Moment 3: no shortcut; the existing auto-assign can do the work.
- Pre-flight and Send: real screens. Send is pretend: it shows what would go
  to whom; nothing is queued for a provider and nothing leaves.
- Moment 4, the board: a Host | Guest toggle. A demo-only "Make the guests
  reply" button has the invented crowd answer so the board shows red, amber
  and green. The guest view is one fixed sample guest; she can change how that
  guest answers (yes, no, maybe, the dish) and flip back to see the board move.

### The send wall

The rule: a demo event (`isDemo: true`) never queues and never sends,
whatever the live switch says. One new module holds it,
`src/lib/demo/send-wall.ts`: `isDemoEvent(db, eventId)`, the query
fragment `REAL_EVENTS_ONLY` (`{ isDemo: false }`), and the refusal words.
It sits in three layers, so a later door that forgets the first is still
stopped by the third.

Layer 1, the doors (refuse before anything is written):
- `pressSend`: a new refusal `DEMO_EVENT` (409, the state family), checked
  after `HOST_HAS_NO_ACCOUNT`, the last refusal before the transaction, so
  before tokens, rows or the ledger (Q15: placed there so the seeded
  unclaimed demo event still answers `HOST_HAS_NO_ACCOUNT`). Both send
  routes get it from the one function. Words: W2.
- `resendToPerson` / `readDoor`: a new `ResendRefusalCode` `DEMO_EVENT`,
  its words written inside `RESEND_REFUSAL_WORDS` (W3), so `resend-door.ts`
  keeps only type imports (bounce-door, carried-child-door). Not a third
  `DoorReason` (bounce-door pins two).
- The by-hand nudge route and `trigger-nudges`: 409 before any read of
  contacts, above `openTextSend(` (W3).
- `wrap-up` and `wrap-up/retry`: 409 in a block of its own before
  `wrappedAt` or any link; the `!isComplete` refusal stays byte for byte
  (W3).
- `sendTestEmailFor`: a new outcome `DEMO`, before the message is read
  (W4). The route file is untouched (message-composition L574 bans send
  words in it).

Layer 2, the queues (a demo event is never a candidate), each composing
`isDemo: false` beside its own rule, spelled in place as
`event: { ...SENT_AND_LIVE(now), isDemo: false }` in the two finders that
use it; `SENT_AND_LIVE` itself, and the list of files that name it, are
not changed (test:lifecycle C3, test:event-day-end S4):
- `findNudgeCandidates`, `findNudgeCandidatesForEvent`,
  `findDecideByFollowupCandidates`;
- `findNeverAttempted`, `findDueForRetry`, `enrolMiniSends`;
- the wrap-up dispatch's pending-link query, `retryUndeliveredThankYous`,
  `retryFailedDispatches`, and the follow-up's text retry,
  `retryUndeliveredFollowups` (`decide-by-sender.ts`).
A demo row, should one ever exist, is skipped, not withheld: no new why
code, nothing claimed; part D deletes it with its event (cascade).

Layer 3, the last step (after Zone 7's opt-out checks and provider choice,
immediately before the live switch):
- The check never throws and never fails closed: no event id, or no such
  event, reads "not a demo" (`findUnique` on the id, `?.isDemo === true`).
  About 30 assertions call the senders with no id or a made-up one.
- `sendSms`: if the event is a demo, return `SMS_DISABLED` with the words
  "Not sent: this is a sample event", write no InviteEvent. Not a new
  block reason (that would move test:cron-health U); the meaning, "sending
  is not on here", is the one `SMS_DISABLED` already carries. A text
  stopped here fails its cron run's text channel, so a breach of layers 1
  and 2 reaches the founder by the scheduler's failure email.
- `sendHostVoiced` and `sendNudgeEmail` in `src/lib/email.ts`: the same
  check before `getResendClient()`, returning `success: false` with no
  provider code (the shape that already means "never left the process").
  Kept short: outbound-drain E needs `resultOf(label` within 1,400
  characters of `sendHostVoiced`'s start (483 comment-stripped today).
  Inside `sendHostVoiced`, not the three wrappers (decide-by-email needs
  `sendHostVoiced(` within 200 characters of `sendDecideByEmail`).
- No new comment or code anywhere in `src/` may contain the literal
  `sendSms({` (test:texts counts exactly five call sites in raw source).

Exempt, each for a stated reason, and pinned by the new suite's census:

### The AI cap

One new gate, `takeDemoAiCall(eventId)` in `src/lib/demo/ai-cap.ts`,
called by all six AI routes right after they load the event:
- A real event: answers "not a demo" and the route does exactly what it
  does today, its own limit and its own count untouched.
- A demo copy, in one short transaction under a Postgres advisory lock (so
  two presses cannot both pass):
  - the daily total: the sum of `aiCallsUsed` over copies started since
    today's NZ midnight (`nzDayStart`, GTC-390) at or over the total
    refuses 429 with W6;
