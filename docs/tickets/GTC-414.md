# GTC-414 - T0: the old freeze checks read a fixed history; a guard holds the protected zones

> Filed by Claude Code on 28 Oct 2026, from the founder's prompt (the FULL

> Branch feat/tweaks-t0, made from feat/final-fixes at 21a9577 (GitHub's
> main). Status: built, not pushed. T0 is pushed together with Batch 1.

## What this ticket does, in plain English

Eleven older test suites (demo-tweaks, and demo-tweaks-2 to -11) each hold
"freeze" checks: "these files are the same as they were at an old commit".
They read the files as they sit in the working folder. So any later ticket
that edits one of those files turns them red, even after it commits, and
each of the 18 tweak tickets would have had to re-base up to ten of them.

This ticket changes no app file and no behaviour. It does two things:

- Every freeze check in those eleven suites now asks a question about a
  FIXED history: "are the frozen files at the old commit the same as the
  same files at 21a9577?", read with git between the two commits, never
  from the working folder. The answer is the same on every future branch,
  so later tickets cannot turn these checks red. A wrong base, or a file at
  21a9577 that differs from its old base, still turns them red.
- A new suite, test:tweaks-guard, takes over the job of watching the
  protected zones (sign-in, sessions, tokens, Stripe, the schema, the
  security suite, SMS and email opt-out), for good: each protected file,
  folder or function must be byte for byte as at 21a9577 in the working
  folder, the index and HEAD.

What T0 gives up, on purpose (ruling 2): the old suites no longer catch NEW
edits by themselves. The guard suite (for the zones) and each later
ticket's own suite (its own "only my files changed since 21a9577" check)
take that job over.

Note on the count: the prompt says "the ten suites" and names
tests/demo-tweaks-test.tsx and demo-tweaks-2 to -11. That is eleven files.
All eleven are named, so all eleven are in this ticket.

## How every re-based check now reads

Each suite gained, next to its own base constants:

- T0_AT, the full 21a9577 commit, with a comment naming this ticket;
- atT0(file): the file as git holds it at 21a9577 ('' if git cannot);
- where needed, sameAtT0(base, paths): "git diff --quiet base T0_AT --
  paths", true only when git says the two commits hold the same bytes (a
  git error, such as a wrong base, is false); existsAtT0; and, for the
  name lists, a diff that gives null on a git error so it reads red.

Rules followed in every suite:

- The old base is unchanged (tag names stay tag names).
- The frozen paths and the exclusions are unchanged, word for word.
- "The file exists" sub-checks now ask git whether it exists at 21a9577.
- Where a check mixes live parts (regexes on today's code, words, counts)
  with a frozen comparison, only the comparison moved to 21a9577; the
  CHECKS function gained an optional last argument (the fixed copy), which
  defaults to the old behaviour so a dry run with the old arguments still
  means what it did. The live parts still read the working folder.
- Labels (the check names printed) are unchanged.
- Every changed line carries a short [[GTC-414]] comment.
