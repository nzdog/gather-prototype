# GTC-247 — Local dev environment has no working send path — SMS or email — OPEN

**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** low (credential/config
only — no code change expected)
**Severity:** Low (dev-environment gap, not a production issue; not caused by any code change)
**Escalated (brand/trust risk):** No

**Filed from:** GTC-245 Phase 2a smoke testing, 2026-08-23. Widened from Twilio-only scope after
GTC-245 Phase 2b smoke testing, 2026-08-23, surfaced the same class of failure on the Resend
path.

---

## Signal

**Expected:** All three of this app's outbound send paths — Twilio SMS, TNZ SMS, and Resend
email (the magic-link auth delivery mechanism) — can be smoke-tested locally against their real
provider APIs using the credentials configured in this environment's `.env`.

**Actual:** None of the three currently authenticate or are even configured. Three distinct
failures, three distinct providers:

| Path | Credential | Result |
|---|---|---|
| Twilio SMS (non-NZ/AU) | `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` | `401 Authenticate` — Twilio rejects the credentials |
| TNZ SMS (NZ/AU) | `TNZ_AUTH_TOKEN` | Not present in `.env` at all — not invalid, simply absent |
| Resend email (magic-link auth delivery) | `RESEND_API_KEY` | `401 validation_error: "API key is invalid"` — Resend rejects the credential |

**Smallest failing case, per path:**
- Twilio: `npx tsx tests/sms-validation-test.ts` (Test 2, the repo's existing safe pattern —
  routes the syntactically-valid but unassigned `+1234567890` US number to Twilio). Result:
  `[SMS] Failed to send to +1234567890 via Twilio: Authenticate` →
  `{ success: false, blocked: 'SEND_FAILED', error: 'Authenticate' }`.
- TNZ: any send to a `+64`/`+61` number returns `SMS_DISABLED` — `TNZ not configured
  (TNZ_AUTH_TOKEN missing)`.
- Resend: call `sendMagicLinkEmail` with a real, DB-persisted `MagicLink` token (not the
  fabricated-token `scripts/test-email.ts`, which can't prove the auth step). Result:
  `[Resend API Error]: { status: 401, error: { statusCode: 401, name: 'validation_error',
  message: 'API key is invalid' }, path: '/emails' }`.

---

## Consequence

**No send path — SMS or email — can currently be verified end to end in this local
environment.** All three can be exercised up to the point of provider rejection (transport
layer proven working in every case — see Evidence below) and no further; none can prove an
actual successful dispatch.

**The magic-link auth path is the one that matters most here, and it has zero local delivery
coverage.** Magic-link email (via Resend) is this app's *sole* authentication mechanism
(`GATHER-BUILD-CONSTANTS.md` Do-Not-Touch Zone 2). Right now, nobody working in this local
environment can confirm — by actually receiving an email and using the link — that a fresh
magic link authenticates correctly. The auth *logic* itself (`/api/auth/verify`, token
lookup/expiry/consumption) is unaffected and untouched by any of this; what's missing is the
ability to close the loop with a real send.

---

## Evidence this predates and is unrelated to any dependency work

Cited from [[GTC-245]]:

- **Phase 2a** (twilio/stripe branch, 2026-08-23): the Twilio test above was run immediately
  after re-resolving `axios`/`follow-redirects`/`form-data`/`qs` in `package-lock.json`,
  specifically to smoke-test that fix. The `Authenticate` response is itself proof the
  dependency bump didn't break anything — a broken HTTP client fails at the transport layer
  (connection refused, TLS handshake failure, malformed request, unparseable response); an
  `Authenticate` response requires the request to have been correctly built, sent, and the
  response correctly parsed back into a structured error.
- **Phase 2b** (resend branch, 2026-08-23): same shape, same conclusion. The Resend test above
  was run immediately after re-resolving `resend` (6.7.0 → 6.22.0, dropping `svix`/`uuid` from
  the tree) specifically to smoke-test that fix. A `401 validation_error: "API key is invalid"`
  is Resend's API correctly receiving, parsing, and rejecting the request on credential
  grounds — again transport-layer proof the bump didn't break the HTTP path, and again not
  something either dependency change touches: neither diff comes near `RESEND_API_KEY`,
  `TWILIO_ACCOUNT_SID`/`TWILIO_AUTH_TOKEN`, `TNZ_AUTH_TOKEN`, or any credential-handling code.

TNZ's absence is a separate, third root cause again: no `TNZ_AUTH_TOKEN` is set at all (not
invalid, just never provisioned locally), and TNZ uses its own thin fetch-based client
(`src/lib/sms/tnz-client.ts`, per [[GTC-079]]), not `axios` — GTC-245 never touched its path
either way.

## Hypothesis to check — NOT a conclusion, unverified

**One possibility worth someone with account access checking: a prior credential rotation
(addressing leaked production secrets) may have left these local `.env` values stale** — i.e.
the values in this local environment could be *old* credentials that were deliberately
invalidated elsewhere, rather than credentials that were simply never valid or expired
naturally. This is speculative and **explicitly unverified** — I checked `git log` for any
recorded rotation incident touching Twilio/TNZ/Resend specifically and found none; the one
rotation incident on record in this repo (`7984652`, `GTC-220`) is about `CRON_SECRET` and URL
plaintext exposure, a different secret and a different concern, and doesn't establish this
hypothesis one way or the other. Recording it here only so whoever has account access checks it
as one possible explanation, not as something already established.

## Scope

**Fix here:** Not this ticket. This ticket documents the gap; resolving it means, per path:
- **Twilio:** obtain/rotate valid credentials for this environment (Test Credentials from the
  Twilio Console are the safer choice per `GATHER-BUILD-CONSTANTS.md`'s own guidance — they
  accept API calls but don't send real SMS).
- **TNZ:** obtain a `TNZ_AUTH_TOKEN` (TNZ Dashboard → Users → API tab, per
  `GATHER-BUILD-CONSTANTS.md`) and add it to `.env`.
- **Resend:** obtain/rotate a valid `RESEND_API_KEY` (resend.com/api-keys).

All three are credential/environment actions outside an executor's authority — **do not attempt
to fix, guess, or acquire credentials as part of this ticket.** Whoever holds the
Twilio/TNZ/Resend accounts needs to action this.

**Do not touch:** `src/lib/sms/*`, `src/lib/email.ts` — none of this code is implicated; this is
purely a local environment configuration gap. Do-Not-Touch Zone 2 (Magic-Link Auth Flow) and
Zone 7 (SMS opt-out logic) are not directly relevant (nothing here touches token/session logic
or opt-out enforcement) but noted per convention given the paths involved.
