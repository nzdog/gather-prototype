# GTC-051 — "Move to confirming" button does nothing — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** 3d37a97

### What was found

**Root cause:** The `SetupChecklistBanner` "Move to confirming" button's `onMoveToConfirming` callback incremented a `bannerGateCheckTrigger` counter, which was passed as `autoOpenTrigger` to the `GateCheck` component. When triggered, `GateCheck` would run the gate check and, if passed, render a `TransitionModal` inside its own JSX. However, the `GateCheck` component was rendered inside a `<div className="hidden">` wrapper (line ~1673 of `page.tsx`), which sets `display: none` on the parent. This caused the `TransitionModal` (despite using `position: fixed`) to be invisible — `display: none` on any ancestor hides all descendants regardless of their own CSS positioning.

The API route (`POST /api/events/[id]/transition`) and the transition logic (`transitionToConfirming` in `src/lib/workflow.ts`) both existed and were functional. The modal was rendering and working correctly — it was just hidden by CSS inheritance.

### What was changed

**`src/app/plan/[eventId]/page.tsx`**
- Added `TransitionModal` import
- Replaced `bannerGateCheckTrigger` state with `showTransitionModal` and `transitionLoading` state
- Added `handleBannerMoveToConfirming` handler that runs the gate check via fetch, then opens the transition modal at the page level (or shows an error toast if gate check fails)
- Wired the banner's `onMoveToConfirming` to the new handler with `transitionLoading` prop for loading state
- Rendered `TransitionModal` at the page level (outside the hidden div) alongside other modals
- Removed unused `autoOpenTrigger` prop from the hidden `GateCheck` instance

**`src/components/plan/SetupChecklistBanner.tsx`**
- Added `Loader2` import from lucide-react
- Added `transitionLoading` prop to interface
- Updated CTA button to show loading spinner and "Checking readiness..." text while gate check runs, with disabled state

### Known limitations / follow-up flags
- The `GateCheck` component still has the `autoOpenTrigger` prop in its interface — it's unused now from the banner flow but could be used by other callers. Left in place to avoid breaking changes.
- The hidden `GateCheck` instance still renders in the hidden div for the plan status expansion modal. Its own "Move to CONFIRMING" button works correctly there because the `SectionExpandModal` is not hidden.
