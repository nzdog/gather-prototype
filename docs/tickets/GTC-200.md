### Context

Epic A runs on an experiment branch and **merges as one unit** — [[GTC-168]] (A2) through
[[GTC-198]] (A3d). This ticket is that merge, in the GTC-145/146 shape
(`gather-experiment-methodology`).

Merging as one unit is not ceremony. A3a removes the lifecycle gates and A3b adds the ledger writes;
between those two commits, post-send mutations are allowed but unrecorded. That window must never
exist on `feat/moment-one-redesign`, which is why nothing lands piecemeal (plan §4.3).

### Gate — A3d's residue check must pass first

**This ticket does not start until [[GTC-198]] closes with a zero-match residue grep.** That grep is
the epic's completeness proof:

```bash
grep -rn "FROZEN" src --include="*.ts" --include="*.tsx" | grep -v lifecycle.ts
# expect: no output
```

A non-zero result means a consumer was missed and the epic is not finished. **Do not merge around
it** — send it back to whichever of A3a–d owns the site.

**[[GTC-201]] (A3b-2) is a hard gate too.** [[GTC-196]] wired every why-scope trigger and deferred
the bulk and non-trigger paths, so between A3b and A3b-2 the ledger is complete for changes that
touch someone and incomplete for some that touch nobody. Merging over that gap would ship a history
with holes in it. A3b-2's completeness sweep — *every mutation route produces at least one entry* —
is the check this merge inherits.
