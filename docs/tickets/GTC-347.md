# GTC-347 — the door's "Send it again" and address actions are not fenced like its text action

**Status:** Open — a stub, filed 2026-10-01 at [[GTC-340]] on founder instruction (plan ruling Q6:
*"file all three (findings 1, 3 and 4) as stubs, numbered from GTC-347, severity blank, none a
precondition"*). Not scoped. **Not a deploy precondition.**
**Severity:** not set at filing — the founder's to set.

---

### Signal

Slice 7b's door fences one action. "Send it as a text" is offered, and pressed, only while
`smsProviderConfiguredFor` answers true, which asks the live switch and the provider's
configuration (founder answer 1, 2026-09-19): *"This fence prevents a FALSE improvement: the red
clearing when nothing was sent and no provider was reached."*

The email actions have no such fence. In `resendToPerson` (`src/lib/press/resend.ts`), AGAIN checks
only that the guest has an address and that it is not blocked; EDIT checks only the address's form
and the block list. Neither asks the live switch or whether a Resend key exists, and there is no
email counterpart to `smsProviderConfiguredFor`.

So on a machine that cannot send email (the switch off, or no key):

- The host presses "Send it again" (or "Send to a different address", or since [[GTC-340]] "Send
  to an email address"). An EMAIL ask row is queued, and the red clears to amber, because the
  board reads the latest row (`latestRowByMembership`).
- The next drain's `getResendClient` throws; the sender returns no provider code; the drain records
  a rejection; `deliveryFactFrom` reads it `NOT_DELIVERED`. The guest is red again.
- Where nothing drains (a dev machine: no cron calls `/api/cron/outbound-dispatch`), the row sits
  unattempted and the guest reads amber, "Gather is chasing", indefinitely.
- EDIT's new address and its ledger entry persist; only the send fails.

[[GTC-340]] widens the reach: until texting is set up, a text guest with no email is offered EDIT
alone ("Send to an email address"), which is unfenced.

### Unknowns

1. Whether the email actions are withdrawn, disabled with a sentence, or left and the queued row
   shown as waiting.
2. What an email fence asks: the live switch alone, or also a key. `getResendClient` is the one
   place that knows both.
3. Whether EDIT should still save the address when the send cannot go.
