# GTC-429 - The six lockfile checks read the lockfile at 21a9577

> Filed by Claude Code on 30 Oct 2026, from the founder's prompt for
> two small tickets on one branch. Branch feat/tweaks-demo-note from
> origin/main at 4f91128. Part B of that prompt; Part A is
> [[GTC-430]], the "Under construction" note on /demo.

## Why

Batch 3's final gate (30 Oct 2026, [[GTC-428]]) found six checks red
on main itself, one in each of demo-tweaks 6 to 11. Each asks that
package-lock.json is the base's but for GTC-413's one qs entry (the
helper `lockfileIsBaseButQs`). They were the six GTC-413 lockfile
checks that [[GTC-414]] kept live on purpose: their "now" side was the
lockfile in the working folder. This morning's merges on main changed
the lockfile after 21a9577:

```
fabed8f Merge pull request #49 (postcss-selector-parser, tailwindcss)
7b227b5 Merge pull request #69 (esbuild, tsx)

        package-lock.json: 120 lines in, 130 out since 21a9577
```

## The founder's ruling (30 Oct 2026), verbatim

4. Part B: the six checks keep their meaning and strictness: they say
   the lockfile at the launch tip (21a9577, GTC-413) is the base's
   except for the one qs entry. Today they compare the lockfile NOW
   (the working tree) with the base, so any later lockfile change turns
   them red. Point the "now" side at the fixed commit 21a9577 instead.

Rulings 1 to 3 are [[GTC-430]]'s; all four are recorded there.

## The change

Each of the six files already holds 21a9577 in full as `T0_AT`
(GTC-414's fixed commit; `git rev-parse 21a9577` gives
21a9577bdc3b2f3d84617f096dd811e891f55305, the same hash). Each check
now reads the lockfile at T0_AT where it read the working folder's.
The base side, the paths, the qs rule (`QS_FROM`, `QS_TO`, byte, parsed
and entry comparisons) and the labels are unchanged.

```
tests/demo-tweaks-6-test.tsx:1240   U1 (last clause)
tests/demo-tweaks-7-test.tsx:1449   U1 (last clause)
tests/demo-tweaks-8-test.tsx:1690   U1 (last clause)
tests/demo-tweaks-9-test.tsx:966-967   U2
tests/demo-tweaks-10-test.tsx:389-390  U2
tests/demo-tweaks-11-test.tsx:1119-1120 U2
```

Old (dt-6, -7, -8):

```ts
      lockfileIsBaseButQs(read('package-lock.json'), atRef(BASE, 'package-lock.json')),
```

New:

```ts
      lockfileIsBaseButQs(atRef(T0_AT, 'package-lock.json'), atRef(BASE, 'package-lock.json')),
```

Old (dt-9, -10, -11):

```ts
    read('package-lock.json').length > 1000 &&
      lockfileIsBaseButQs(read('package-lock.json'), atRef(BASE, 'package-lock.json'))
```

New:

```ts
    atRef(T0_AT, 'package-lock.json').length > 1000 &&
      lockfileIsBaseButQs(atRef(T0_AT, 'package-lock.json'), atRef(BASE, 'package-lock.json'))
```

`atRef` is `git show <ref>:<path>`, and gives '' when git cannot read
it; the helper then fails to parse it and the check is red, so a wrong
hash cannot pass.
