### Why it is deferred, and how far

Postgres cannot drop an enum value while any row references it, so the data migration (step 4) and
the enum drop (step 5) are coupled and irreversible together. Epic A deliberately stops at step 3 —
enum values retained but never written, behind a compat shim in one function — because that buys a
fully revertible epic for the price of one dead enum value.

**Sequenced after Epic J** ([[GTC-192]]–[[GTC-194]]): the new surfaces should have been exercised
against real use before the escape hatch is welded shut. Do not pull this forward to tidy the schema.

## Scope

### 1. Data migration (step 4) — one-way

```sql
-- Every FROZEN/COMPLETE row already carries sentAt (backfilled in GTC-168).
-- Verify BEFORE updating; a row with status='FROZEN' and sentAt IS NULL is a stop.
UPDATE "Event" SET status = 'CONFIRMING' WHERE status IN ('FROZEN', 'COMPLETE');
```

COMPLETE rows are safe to move to CONFIRMING: `isComplete()` derives from `endDate`, so a past event
reads as COMPLETE regardless of its stored status. This is precisely what the derived model bought.

### 2. Remove the compat shim

`isSent()` drops its `|| status === 'FROZEN'` clause and becomes `sentAt != null`. One function, one
line — the whole point of centralising it in [[GTC-168]].

### 3. Schema drops (step 5) — one-way

| Drop | Was |
|---|---|
| `EventStatus.FROZEN` | The old lock ceremony |
| `EventStatus.COMPLETE` | Superseded by the calendar predicate |
| `Event.frozenAt` | Freeze timestamp; `sentAt` replaced it |
| `Event.complianceAtFreeze` | Threshold artefact |
| `Event.freezeReason` | Threshold artefact — the `<80%` demand for justification, deleted in A3a |
| `Person.inviteAnchorAt` | Moved to `PersonEvent.sentAt` in [[GTC-196]] |

`EventStatus` finishes with two values: `DRAFT`, `CONFIRMING`. Not collapsed further — `DRAFT →
CONFIRMING` is real, load-bearing work (gate check, `PlanSnapshot`, `structureMode: LOCKED`,
`AccessToken` generation) that neither spec touches, and turning it into a timestamp for symmetry
would add every DRAFT/CONFIRMING branch to a diff for zero product gain (plan §2).

⚠ `Person.nudge24hSentAt` / `nudge48hSentAt` are **not** dropped here. They carry the same
per-person-for-a-per-event-fact leak (plan §8.2) but their relocation belongs to [[GTC-178]] (E1),
zone-7-adjacent. If E1 has landed first, confirm they are gone and note it; do not touch them here.
