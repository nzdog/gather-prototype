# [[GTC-101]] — Schema: Household model for Moment 1 redesign — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** pending

### What was found

The codebase already had a `Household` model and `HouseholdMember` model from the earlier proxy-based household system. These were structurally different from the Moment 1 redesign spec — the old model linked households to a proxy `Person` via `proxyPersonId` and tracked individual `HouseholdMember` records with claim/nudge/escalation fields. The new model links households directly to `PersonEvent` records via `householdId` + `householdRole`, with children tracked as a count.

Six files referenced the old `HouseholdMember` model and old `Household` fields, causing TypeScript errors after the schema change:
- `src/app/api/events/[id]/households/route.ts`
- `src/app/api/events/[id]/households/[householdId]/claim/route.ts`
- `src/app/api/events/[id]/households/[householdId]/members/route.ts`
- `src/app/api/events/[id]/invite-status/route.ts`
- `src/lib/sms/proxy-nudge-eligibility.ts`
- `src/lib/sms/proxy-nudge-sender.ts`
- `src/lib/sms/nudge-scheduler.ts`
- `src/components/plan/InviteStatusSection.tsx`

### What was changed

**Schema (`prisma/schema.prisma`):**
- Replaced `Household` model: removed `proxyPersonId`, `proxyPerson`, `name`, `@@unique([eventId, proxyPersonId])`; changed `members` from `HouseholdMember[]` to `PersonEvent[]`; added `childCount Int @default(0)` and `updatedAt DateTime @updatedAt`
- Removed `HouseholdMember` model entirely
- Added `HouseholdRole` enum with `PRIMARY_CONTACT`, `PARTNER`, `GUEST`
- Added `householdId String?`, `household Household?`, `householdRole HouseholdRole?` to `PersonEvent`
- Removed `householdMember HouseholdMember?` from `PersonEvent`
- Removed `households Household[]` from `Person` model (Event already had it)

**Migration:** `20260412024438_add_household_model` — applied cleanly

**TypeScript fixes (minimum changes to compile):**
- `households/route.ts`: Rewrote GET/POST for new schema (members are PersonEvents, no proxyPersonId)
- `households/[householdId]/claim/route.ts`: Stubbed to 501 — old HouseholdMember claim flow doesn't map to new schema
- `households/[householdId]/members/route.ts`: Stubbed to 501 — same reason
- `invite-status/route.ts`: Simplified `proxyNudgeSummary` to `totalHouseholds`, `totalMembers`, `totalChildren`
- `proxy-nudge-eligibility.ts`: Rewrote for new schema; removed 24h/48h/escalation tiers (old tracking fields gone)
- `proxy-nudge-sender.ts`: Rewrote for new schema; removed `prisma.householdMember` references
- `nudge-scheduler.ts`: Updated interface and logic for simplified proxy nudge result shape
- `InviteStatusSection.tsx`: Updated type and UI for new proxyNudgeSummary shape

### Known limitations

- Household claim and member-add endpoints return 501 — need redesign for the new household model in a future ticket
- Proxy nudge scheduling lost per-member tracking (proxyNudgeCount, lastProxyNudgeAt, claimedAt, escalatedAt) — these fields were on the removed HouseholdMember model. Nudge frequency limiting needs redesign.
- Children are tracked as `childCount` on Household, not as individual records. Named children may be added later for Moment 3.
