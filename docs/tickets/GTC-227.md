# GTC-227 — Record deploy configuration in GATHER-BUILD-CONSTANTS.md

**Status:** Executed, awaiting commit approval. **Effort:** Low.

### Scope

Two facts in `GATHER-BUILD-CONSTANTS.md` were wrong or absent:

1. No record existed that Railway auto-deploy from `master` was turned off
   2026-08-10 (Nigel). Consequence not stated: merging to `master` no longer
   triggers a deploy.
2. The **Base Branch** section claimed `master` is where work branches from
   and merges back to. In practice `feat/moment-one-redesign` is the working
   trunk and `master` has not moved.

**Fix here:** `GATHER-BUILD-CONSTANTS.md` only — corrected the Base Branch
section and added a new Deploy section stating the auto-deploy change and its
consequence, plus the load-bearing caveat that disabling auto-deploy decouples
code from deploy *timing* but not from the *database*: migrations still apply
to production the moment code carrying them is deployed, so they must be
rehearsed against a copy first.

Not restating citation rules, per GTC-222 — this file already points at
`BUG-TICKET-TEMPLATE.md`'s Citations section and that pointer is untouched.
