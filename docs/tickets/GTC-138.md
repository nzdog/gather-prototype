# GTC-138 — Cake/Dessert cross-category overlap — CLOSED

**Status:** CLOSED (resolved by architecture change, no code required in this ticket)
**Resolved by:** GTC-146 (single-call AI generation architecture)

### Original hazard

Surfaced during GTC-133 sub-commit (g) browser verification (one of the six follow-ups filed as GTC-136 through GTC-141 — "AI-output bugs newly visible because the integration is now end-to-end", `docs/tickets/GTC-133.md`). Under per-section generation, Cake and Dessert were generated by **independent AI calls that could not see each other's output**, so the same celebratory items (cakes, trifles, pavlova variants) appeared in both categories — duplicated shopping, duplicated assignments.

### Resolving change

GTC-146 replaced per-section generation with a single `finalize-plan` call. The whole plan is produced in one response, and the system prompt (`buildPlanGenerationPrompt`, `src/lib/ai/prompts.ts`) enforces cross-category coordination explicitly: "Every item appears in exactly ONE category", "Avoid near-duplicates in the same role (e.g., do not list both 'Yule Log' and 'Chocolate Yule Log' in two different categories)", and "Dessert and Cake are distinct: if Cake is engaged, the celebratory cake lives there; Dessert holds other sweet items only." The duplication class is structurally impossible to miss now — the model sees both categories in the same context.

### Verification (this session)

Fresh V2 event, Christmas + Vegetarian + Gluten-free, engaged Mains + Sides + Dessert + Cake + Drinks + Snacks + Breakfast & Brunch. Generated plan: 40 items across 8 categories.

- Dessert: Pavlova, Berry Trifle, Chocolate Trifle, Strawberries/Cherries.
- Cake: Christmas Cake only.
- **Zero overlap between the two categories. RESOLVED.**
