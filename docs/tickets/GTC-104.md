# GTC-104 — Moment 1: Growing card list — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 1f94eaa

### What was found

- The GET `/api/events/[id]/households` endpoint already existed from GTC-103, returning households with members ordered by `createdAt asc`.
- The Moment1InputForm rendered as a full-screen overlay (`fixed inset-0`). This needed to be restructured so the parent page could wrap it in a two-column layout.
- The form's progress counter (`totalPeopleAdded`) used internal state that reset on re-render. It needed to derive from the card list state for accuracy across adds/edits.
- The `[householdId]` API directory already existed with stub `claim/` and `members/` routes (501 Not Implemented).

### What was changed

**New files:**
- `src/components/plan/HouseholdCardList.tsx` — Card list component with `SavedHousehold` interface, `+N` badge, emoji member summary (👫 partner, 🧒 children, 👤 guests), Edit link, and 200ms fade-in animation.
- `src/app/api/events/[id]/households/[householdId]/route.ts` — PUT endpoint that updates primary contact in place, deletes and recreates non-primary PersonEvent records, updates childCount.

**Modified files:**
- `src/components/plan/Moment1InputForm.tsx` — Added edit mode support: `editingHousehold`, `onEditSave`, `onCancelEdit`, `totalPeopleCount` props. Form populates from editing household data. Button switches between "+ Add another person" (add mode) and "Save changes" (edit mode). Removed `fixed inset-0` wrapper so parent controls layout.
- `src/app/plan/[eventId]/page.tsx` — Added `households` and `editingHousehold` state. Added `useEffect` to fetch households when Moment 1 opens. Added `apiHouseholdToSaved` helper. Restructured Moment 1 render: desktop shows two-column layout (form left, card list right with sticky scroll), mobile shows cards above form. Scroll-to-form on mobile after save. Progress counter derives from card list state.

### Known limitations

- No delete from card list (deferred per ticket spec).
- Edit mode does not support undo — only cancel or save.
- The PUT endpoint uses delete-and-recreate for non-primary members, which creates new PersonEvent IDs for partners/guests on each edit.
