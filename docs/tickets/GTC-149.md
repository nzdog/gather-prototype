### Phase 1 audit: V1 AI-generation surfaces found

**Surface A — V1 Generate pipeline.** Larger than the GTC-148 Phase 3 note suggested: **seven** UI entry points, all funneling through `setHostDescriptionModalOpen(true)` → `HostDescriptionModal` → `handleGeneratePlan` → `/api/events/[id]/generate`:

- A1. Header "Generate Plan" button (`page.tsx` ~2082, renders when `DRAFT && teams===0`)
- A2. Setup checklist step 4 "Create your plan" (`handleChecklistOpenCreatePlan`, ~1560; opened the generate modal when `teams===0`)
- A3/A4. PeopleSection empty-state CTA (`onGeneratePlan` props at ~2502 and ~3066; `PeopleSection.tsx:36` — prop optional, CTA renders only when provided)
- A5. Conflicts expansion empty state (~2681)
- A6. Items expansion empty state (~2846)
- A7. Teams expansion empty state (~3092)
- Plus the deferred-open effect (`page.tsx:504–508`, fires a pending 'generate' action after an expansion closes) and the modal render itself.

**Surface B — Regenerate / selective regenerate.** Already hidden by GTC-148; re-verified `setReviewMode(true)` still has exactly one call site, inside the hidden Regenerate path. No independent entry.

**Surface C — RevisionHistory restore.** Answers the ticket unknown: it showed **unconditionally** — no V1/V2-era discrimination. Three distinct render surfaces: the dashboard "Revision History" card (`page.tsx` ~2454, found only during browser verification — the initial grep-level audit missed it), the RevisionHistory component (hidden-section preload + history expansion), and the **History tab in ModalTabBar** (navigable from every expansion modal), plus a `?expand=history` URL deep link (`page.tsx:477–479`).

**Surface D — `/demo/review`.** Takes `?eventId=`, fires `/generate`; **zero inbound links in src/**; HOST-auth protected. Left unguarded per Nigel's scope decision — it dies with the V1 generate route in the reconciliation review's Tier-2 prune.

Scope confirmed by Nigel: fix A + C fully; B nothing to do; D documented non-action.

### What was changed (per surface)

`src/app/plan/[eventId]/page.tsx`:
- A1: `!event.setup &&` on the header button render.
- A2: `handleChecklistOpenCreatePlan` opens the generate modal only when `teams===0 && !event?.setup`; on V2 events it falls back to AddTeamModal (manual, non-AI — the same action it already used when teams exist), keeping the checklist functional.
- A3/A4: `onGeneratePlan={event?.setup ? undefined : …}` — PeopleSection's CTA self-hides when the prop is absent.
- A5–A7: `!event?.setup &&` added to each expansion empty-state CTA.
- Choke point: `HostDescriptionModal` gets `isOpen={hostDescriptionModalOpen && !event?.setup}` — no missed or future caller can open the V1 generate modal on a V2 event.
- C: dashboard Revision History card gated on `!event.setup`; RevisionHistory hidden-section instance gated; history `SectionExpandModal` gated via `isOpen={expandedSection === 'history' && !event?.setup}` (covers the `?expand=history` deep link); `buildTabBar` passes `hiddenTabs={event.setup ? ['history'] : undefined}`.

`src/components/plan/ModalTabBar.tsx`:
- New optional `hiddenTabs?: ModalTabId[]` prop, filtered after the existing `getTabsForStatus` filter (same pattern as the existing invites-in-DRAFT exclusion).

Not touched, per scope: V1 pipeline internals and routes, finalize-plan, non-AI dashboard controls, schema, GTC-148's Regenerate hide.

### Known limitations

- Revisions are still *written* on V2 events by the transition workflow snapshot (`workflow.ts:839`); they're now invisible on V2. Harmless data accumulation; goes away with the review's PlanRevision prune decision.

- V2 still has no regenerate of its own; the real V2 regenerate (finalize-plan re-entry) remains the future ticket flagged in GTC-148.
