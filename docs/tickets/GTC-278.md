## Why this is not merely housekeeping

**It is a precondition of any future Next 16 move.** `next lint` prints, on
every run:

```
`next lint` is deprecated and will be removed in Next.js 16.
```

`npm run lint` **is** `next lint`. If [[GTC-244]]'s Next 16 question is ever
answered yes without this ticket landing first, linting does not degrade — it
disappears. That coupling is the reason this is filed as a blocker on GTC-244
rather than as generic tech debt, and it is the reason not to let it sit
indefinitely just because the npm script currently works.

## What is actually broken, and what is not

Stated precisely, because the received version of this was wrong in a way that
mattered — see [[GTC-277]] Finding 5.

**Working:** `npm run lint`. Next's ESLint bridge forces the legacy eslintrc
path, so `.eslintrc.json` loads fine under `eslint@9.39.2`. It runs, and it has
been running — **phase 6 and the security tickets were lint-checked.** Current
output: 56 errors / 43 warnings across 46 files, exit 1, unchanged from
[[GTC-221]]'s 2026-08-23 measurement and byte-identical across GTC-277's
dependency bump.

**Broken:** the raw CLI. `./node_modules/.bin/eslint src/lib/vcard.ts` exits
with:

```
ESLint couldn't find an eslint.config.(js|mjs|cjs) file.
From ESLint v9.0.0, the default configuration file is now eslint.config.js.
```

So what is dark is **editor integration and anything that shells out to
`eslint` directly** — not the npm script. Note `lint-staged` in `package.json`
runs only Prettier, so nothing is silently passing on commit.

**Also broken, and a genuine config gap rather than a code problem:**
`src/lib/vcard.ts` carries an `eslint-disable-next-line` for
`@typescript-eslint/no-require-imports`, and lint reports *"Definition for rule
was not found"* — because `.eslintrc.json` extends `next/core-web-vitals` but
not `next/typescript`. **The TypeScript rule set has never run on this
codebase.** Expect this migration to surface a new backlog behind the existing
one; that is a finding to report, not to fix here.

## Approach — Option A, FlatCompat

Chosen over the alternative (pinning `eslint` back to `^8`) because ESLint 8
went end-of-life in October 2024 — that path adds a knowingly unsupported
package to fix a config-format problem, will itself start attracting
advisories, and still leaves this work owed before Next 16.

`eslint-config-next@15.5.22` ships **no flat-config export** — `main: index.js`,
no `exports` field, just `index.js` / `core-web-vitals.js` / `parser.js` /
`typescript.js`. A flat export only arrives in `eslint-config-next` 16, which
cannot be had while Next is 15. So the migration must wrap the existing
`extends` through `FlatCompat`.

`@eslint/eslintrc@3.3.3` is **already present in the tree** as a transitive, so
FlatCompat is available today.

## Scope

**Fix here:**
- New `eslint.config.mjs` at repo root, wrapping
  `["next/core-web-vitals", "prettier"]` through `FlatCompat`.
- Delete `.eslintrc.json`.
- Add `eslint` and `@eslint/eslintrc` as explicit `devDependencies` in
  `package.json`. `eslint` is currently in the tree **only** as an
  `eslint-config-next` peer, which is fragile — it should be declared.
- Decide and record whether `npm run lint` stays `next lint` or becomes
  `eslint .`.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md` are binding. Note
  **Zone 8 — do not add `"type": "commonjs"` to `package.json`.** This ticket
  edits `package.json`; that field must not appear. The `.mjs` extension on the
  config file is deliberate and sufficient.
- **`eslint-config-next` — must remain `^15.5.22`.** Binding per [[GTC-243]];
  moving it to `^16` reproduces the circular-JSON crash `b6e6e38` fixed.
- The lint findings themselves. **[[GTC-221]] owns the backlog; this ticket
  owns the config only.** Do not batch-autofix while here.
- `next.config.js` `eslint.ignoreDuringBuilds: true` — that flag names GTC-221
  as its end condition, not this ticket. Leave it.

## Acceptance

**Test gate** — Severity Medium: post-fix confirmation acceptable.

The real verification is an **A/B of the rule output**, not a pass/fail:

1. Capture `npm run lint` output before the change.
2. Apply the migration.
3. Capture again and `diff`.
4. **The rule set must produce the same findings, or every difference must be
   nameable.** FlatCompat around a config not designed for it is known to drop
   plugin rules quietly; the diff is what catches that.

**Assertions**
- [ ] Raw `npx eslint src/lib/vcard.ts` runs without the config-not-found error
- [ ] `npm run lint` still runs and still reports findings (does not silently
      no-op — the failure mode `b6e6e38` fixed)
- [ ] Zero occurrences of "circular" in lint output
- [ ] Lint findings identical to the pre-change 56/43, or each difference
      named and justified. Expect the `@typescript-eslint/no-require-imports`
      "rule not found" error in `src/lib/vcard.ts` to resolve; **if
      `next/typescript` is included, expect new TypeScript findings — report
      the count, do not fix them here, file them to [[GTC-221]]**
- [ ] `eslint-config-next` unchanged at `^15.5.22`
- [ ] No `"type": "commonjs"` in `package.json`
- [ ] `npm run typecheck` exit 0
- [ ] `npm run test:security` 148/148
- [ ] `npx next build` exit 0
- [ ] Adjacent flows unaffected: none expected — dev tooling only, no runtime
      code touched

**Evidence package**
- Before/after lint output and the diff between them
- Raw CLI invocation working
- Commit hash

## Unknowns

- Whether FlatCompat preserves every rule `next/core-web-vitals` contributes.
  The A/B diff is the instrument; if rules drop, STOP and report rather than
  accepting a quieter linter.
- Whether to include `next/typescript` in the migration. Including it is
  correct and fixes the `vcard.ts` rule gap, but will surface a TypeScript
  backlog that has never run. **Recommend including it and reporting the
  count** — a known backlog beats a silently absent rule set. Founder call if
  the count is large.

## Stop Conditions

Standard 8 from `BUG-TICKET-TEMPLATE.md`, plus:

9. If the A/B diff shows findings *disappearing* that were not explained by a
   named cause → STOP. A quieter linter is the failure mode this ticket exists
   to prevent, not its success criterion.
10. Do not touch `eslint-config-next` under any circumstance in this ticket.
