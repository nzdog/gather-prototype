### Where this comes from — the brief

The founder's brief (Cowork, 1 Nov 2026), quoted in full where it sets the
work and the rules:

> WHY THIS TICKET. I am adding a way for a host to load her contacts into
> Gather: a pasted list, a file, or the phone's contact picker. Loaded
> contacts are held in the host's browser only, and nothing reaches
> Gather's server until she adds a person to a household in the Moment 1
> form. This ticket is only the reading and checking code underneath that.
> It has no screen, no storage, no server route and no migration, and
> nothing is wired into any page. Later tickets build the screen, the
> browser store and the hand-off to the household form.
>
> WHAT THE CODE MUST DO (new files, probably under src/lib/contacts/;
> propose the exact place):
>
> 1. Paste reader. One person per line: name, then phone, then email,
>    separated by commas. Any part may be missing (an empty slot or a
>    trailing comma). It must cope with numbers written without a plus
>    sign, extra spaces, and text copied from a spreadsheet (tab-
>    separated). Names may be written Last, First, which clashes with the
>    commas, so say how you tell the parts apart (for example by
>    recognising a phone or an email by what it looks like rather than by
>    position) and what you do when unsure.
> 2. vCard reader. The existing parseVCF in src/lib/vcard.ts throws away
>    contacts with no email and no phone. I want those kept (a person with
>    no number or email is still a guest) and only contacts with no name
>    dropped, with a count of what was dropped. Say what it does today
>    when a contact has several numbers or emails, and recommend which to
>    keep.
> 3. File reader for CSV. It must handle commas, quotes and line breaks
>    inside quoted cells (today a quoted comma breaks a row), guess the
>    name, email and phone columns as ImportCSVModal.tsx does, and run in
>    the browser with no server imports.
> 4. Name tidy. Turn Last, First into First Last when loading. Be careful
>    with names that are not people (a business, a name with Jr or a
>    title). When unsure, leave the name as it was.
> 5. Number check. Use the existing normalizePhoneNumber and its
>    neighbours in src/lib/phone.ts without changing that file. Flag
>    numbers the household form would refuse (overseas or malformed)
>    instead of dropping them, with a plain-English reason.
> 6. Email check. A shared check with the same rule as the household form.
>    Do not edit Moment1InputForm.tsx or ImportCSVModal.tsx in this
>    ticket: GTC-436 and GTC-438 are filed against that form and its
>    summary, and the old import pop-up must keep working. Tell me what
>    duplicate this leaves and how to remove it later.
> 7. What comes out. Each loaded person has a name, an optional email, an
>    optional phone and a list of plain-English problems, and nothing
>    else. Propose the exact shape, including a temporary id.
>
> RULES THE CODE MUST KEEP:
>
> - Pure functions: no storage, no network, no logging of contact content,
>   no server-only imports. It must run in the browser.
> - It never decides that a contact is a child, and never guesses. Roles
>   are set only in the existing household form.
> - No duplicate merging in this ticket. Which duplicates to merge is
>   still undecided.
> - Tests use invented people, numbers and emails only. Never real ones.

- `src/lib/vcard.ts`. `parseVCF` (L220-263) splits cards on
  BEGIN:VCARD / END:VCARD (L46-70), takes the name from FN, else from N as

  card. `pickPreferred` (L164-185) takes a field whose TYPE holds PREF, or

  it checks validity, ignores TYPE=CELL, FAX and WORK, and drops the other
  values without a word or a count. A private `normalisePhone` (L202-215)
  strips separators and turns a leading 0 into +64; it is not phone.ts's

  "no name" drop (L249-253), and one `skippedCount` lumps together a parser
  error, nothing to contact and no name. It loads `vcard-parser` with a
  top-level `require` (L19); the pop-up is a client component and already

  Changing `parseVCF` would turn it red.

  its phone handling (L203-218, L419-437) nulls an overseas or malformed

- `src/components/plan/Moment1InputForm.tsx`. `validateEmail` (L198) trims,

#### What comes out (job 7; rulings 3, 4 and 7)

```ts
export type ContactPerson = {
  tempId: string;     // browser-only; never sent, never a Person id
  name: string;       // trimmed, single spaces, never empty
  email?: string;     // trimmed, lower-case; key missing when none
  phone?: string;     // +64 form if it passes; as typed if flagged
  problems: string[]; // plain English (W1 to W7); [] when none
};

export type ReadResult = {
  people: ContactPerson[];
  found: number;      // non-blank lines, rows or cards seen
  leftOut: { noName: number; unreadable: number };
  tidied: number;     // names the flip rule turned round
};

export type ReadOptions = { newId?: () => string };
```

- Absent email or phone means the key is missing, never `null` or `""`.
- `tempId` comes from `newId` if given; by default `crypto.randomUUID()`,
  with a counter-and-random fallback where it does not exist (a browser
  page that is not a secure context). Tests inject a counter.
- No role, child flag, source, row number or original text. A problem
  sentence carries no contact content, so it is safe to count or log. The
  result's numbers hold no contact content either.
- `tidied` counts people whose name the flip rule (job 4) turned from
  Last, First into First Last, once each. Names built from separate First
  and Last columns, or from a vCard's N field, were not turned round and
  are not counted (reading R1).
- No duplicate flags, no merging.

#### Job 1 — the paste reader (`readPaste(text, opts)`)

- Lines split on CRLF, CR or LF. Blank and whitespace-only lines are
  skipped and not counted in `found`.
- A first line whose every cell is a heading word (name, full name, first
  name, last name, phone, mobile, email, e-mail and the like) is skipped
  (ruling 9). Only the first line is tested.
- A line is split into cells on tabs if it has a tab, else on commas. Double
  quotes are honoured, so "Smith, John" stays one cell. Each cell is
  trimmed (NBSP too) and runs of spaces collapsed.
- Each cell is classed by what it looks like, never by position:
  - email: it contains "@". The form `Name <a@b.com>` is pulled apart into a
    name and an email (ruling 9);
  - phone: only digits, spaces, `+ ( ) - .` and at least six digits;
  - name text: letters, and none of the above;
  - anything else (no letters and no phone shape, for example `---`):
    unplaced, which gives W7 and is left out.
- Position decides only ties: the first email and first phone found are
  the candidates; extras drop under the chooser (ruling 5) with W4 or W5.
- The Last, First clash. A line has one name field, so two name-text cells
  mean a comma fell inside the name. They are joined back as typed and given
  to the name tidy. If it is sure, the name is flipped (`tidied` counts it);
  if it is not, the name stays exactly as typed and the person gets W6. It
  is never chosen by position and never guessed.
- A line with no name is not a person: it is left out and counted in
  `leftOut.noName` (ruling 8), whatever else it holds. A space-only line
  (`Jane Doe 021 555 0101 jane@example.com`) has no commas or tabs, so its
  "@" makes it an email cell, it has no name, and it is left out and
  counted. It is never split on spaces.
- Every phone and email goes through jobs 5 and 6.

#### Job 2 — the vCard reader (`readVCard(text, opts)`)

- Built beside `parseVCF` on `vcard.ts`'s own split, quoted-printable and
  name helpers (exported, ruling 2), reading the raw numbers and emails, not
  the private `normalisePhone`'s.
- A card with no email and no phone is KEPT (a person with no number or
  email is still a guest). A card with no name is dropped and counted in
  `leftOut.noName`, whether or not it has an email, a number or an
  organisation; it is never named from a company (ruling 8). A block the
  parser throws on is counted in `leftOut.unreadable`. `found` is the
  number of cards.
- A name from FN is given to the name tidy ("Smith, John"). A name
  assembled from N as Given Middle Family is already First Last and is not
  tidied.
- Several emails or numbers: one of each, by the chooser (ruling 5). W4 or
  W5 when extras are dropped.
- How `vcard-parser` treats grouped lines such as `item1.TEL` was not
  verified in the plan; check V11 records what it does.

#### Job 3 — the CSV reader (`readCsv(text, opts)`)

- A hand-written RFC-4180 reader, no library (a new dependency would touch
  package.json and the lockfile, which several lockfile suites watch): commas,
  double quotes, `""` for a quote, line breaks inside quoted cells, CRLF,
  a BOM, a final newline, blank lines. Cells past the header's width are
  ignored; a short row's missing cells are blank.
- `guessColumns(headers)` uses the pop-up's words and order (L293-330): first
  name, last name, full name, email, phone. Fixes (rulings 6 and 12): a
  column whose header says Label, Type or Phonetic is skipped, and the FIRST
  matching column for each field is taken, not the last non-empty one.
- `readCsv` hands back the guess with the people, so a later screen can show
  and change it. No name column found means every row is left out and
  counted in `leftOut.noName`.
- Separate First and Last columns build `First Last` directly, never
  `Last, First`. A single name cell is given to the name tidy.
- Several email or phone columns: one of each, by the chooser (ruling 5).

#### Job 4 — the name tidy (`tidyName(raw)`)

It flips only when ALL of these hold; anything else is left exactly as
typed, spaces collapsed only, and case is never changed:

- exactly one comma, with text on both sides;
- only letters (macrons included), apostrophes, hyphens and full stops;
  no digit, `&`, `/`, `@`, `+`, bracket or quote;
- no title (Mr, Mrs, Ms, Miss, Mx, Dr, Prof, Rev, Sir, Dame, Hon …) and no
  suffix (Jr, Sr, II, III, IV, Esq, PhD, MD, QC, KC …) on either side;
- no business word on either side (Ltd, Limited, Inc, LLC, Co, Company,
  Trust, Society, Club, School, Council, Services, Plumbing, Electrical,
  Dental, Medical, Centre, Group, Holdings, Cafe, Bakery, Restaurant,
  Pharmacy …);
- a left side of one word, or of two or three where the extra words are
  family-name particles (van, von, de, der, den, du, di, da, le, la, te,
  ter, ten, bin, al, el);
- a right side of one to three words.

One known limit, stated plainly: "Countdown, Albany" passes every guard
and would be flipped. The business-word list is the only defence there; a
word is added the first time a real file shows one. A flip adds to
`tidied`; nothing is written on the row (ruling 7).

#### Job 5 — the number check (`checkPhone(raw)`)

The same two calls in the same order as the form's `validatePhone`, on the
trimmed value: empty → none; `isInternationalNumber` → overseas;
`normalizePhoneNumber` null → malformed; else ok with the +64 form.
`phone.ts` is not changed. A passing phone is stored in the +64 form; an
overseas or malformed one is KEPT, as typed with spaces collapsed, and the
person gets W2 or W3 (ruling 4). The check is exactly as strict as the form
and no stricter: a US number written `4155550100` passes both (C8; check
H4 records it).

#### Job 6 — the email check (`checkEmail(raw)`)

Trim, then `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`, the form's rule. An email is
stored trimmed and lower-cased (ruling 4); a failing one is KEPT that way
and the person gets W1. The 40-string parity check (E5) holds the new check
to the form's `validateEmail`.

The duplicate this leaves: the pattern is then in eight places (C6). To
remove them later, once GTC-436 and GTC-438 have landed on the form and the
summary:

- the form's `validateEmail` calls the shared check;
- the pop-up (twice) and the three household routes import it;
- the copies are deleted and E5 becomes a one-source check;
- the copy in `src/app/api/auth/magic-link/route.ts` stays, because that
  folder is Zone 2.

The form's four-line `validatePhone` and the pop-up's two phone blocks go
the same way.

#### The chooser (ruling 5)

When a contact, line or row has several, one of each is kept, by the same
function in all three readers:

- email: one that passes the form's check, then the card's PREF, then the
  first listed;
- phone: one that passes the form's check, then a New Zealand mobile
  (+642…), then the card's PREF, then the first listed.

If none passes, the same order picks the one kept and flagged. Any dropped
extra gives the person W4 (emails) or W5 (numbers).

#### The shared builder (`makeContact`)

Takes a name, lists of candidate emails and numbers, and the options; runs
the tidy, the chooser and the two checks; collects the problems in order;
returns a person (or nothing, when there is no name, so the reader can
count it). Paste, CSV and vCard all end here, so every reader flags the same
way.
