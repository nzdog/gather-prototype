# [[GTC-071]] — Participant RSVP and item confirm in same flow — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** f21b92b

### What was found
- **RSVP Yes handler** (`handleRsvpResponse`): PATCHes `/api/p/[token]` then calls `fetchData()` for full re-fetch. This round-trip caused a visible "step" between the RSVP card disappearing and assignments appearing.
- **Item Accept/Decline mechanism**: Already existed in the assignments view — each assignment card has Accept/Decline buttons when `response === 'PENDING'`, with change-response support for already-responded items.
- **Current flow structure**: RSVP PENDING card and Assignments section rendered by separate conditionals. Clicking Yes → API call → re-fetch → RSVP card hides, assignments section appears. Two visually distinct steps.

### What was changed

**`src/app/p/[token]/page.tsx`** — Combined RSVP yes and item confirmation into a single continuous flow:

1. Added `viewPhase` state (`'rsvp' | 'items' | 'complete'`) to control the flow progression
2. **Optimistic RSVP transition**: Clicking Yes immediately sets `rsvpStatus` to YES and `viewPhase` to `'items'` — no waiting for the API round-trip. Items appear instantly.
3. **Optimistic item responses**: Clicking Accept/Decline on an item immediately updates the assignment's response in state. When all items are responded to, transitions to `'complete'` phase.
4. **Completion state**: Shows "You're all set. See you there." with a check icon, count of accepted items, and a "Review or change your responses" link (unless frozen).
5. **Initial load handling**: Returning visitors who already RSVP'd Yes land directly on the correct phase (items if pending responses remain, complete if all responded).
6. **Revert on failure**: If the API call fails after an optimistic update, `fetchData()` is called to restore server state.
7. **No/Not sure flows**: Completely unchanged — the `viewPhase` guard only applies to the PENDING RSVP card, and NOT_SURE assignments section renders independently of viewPhase.

### Known limitations / follow-up flags
- No CSS transition animation between RSVP and items phase — the switch is instant (React re-render). Could add a fade/slide transition in a follow-up if desired.
- The "Review or change your responses" link from the completion state goes back to items view but doesn't re-trigger completion check until an item is changed.
