# [[GTC-110]] — Auto-focus sub-form fields on open — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** ecd74e9

### What was found

- When Kate clicks "Add Partner", "Add Children", or "Add Guest", the sub-form appears but focus stays wherever it was. Kate has to manually click into the new input field.
- All three sub-forms are conditionally rendered (`showPartner`, `showChildren`, `guests` array), so `autoFocus` fires exactly once — when the input mounts into the DOM. No refs or effects needed.
- During edit mode population, the existing `useEffect` at line 141 calls `nameInputRef.current?.focus()` after render, correctly overriding any `autoFocus` on partner/children inputs back to the primary name field.

### What was changed

**`src/components/plan/Moment1InputForm.tsx`**
- Added `autoFocus` to the partner name `<input>` (line ~472) — focuses when "Add Partner" is clicked
- Added `autoFocus` to the children count `<input>` (line ~540) — focuses when "Add Children" is clicked
- Added `autoFocus={i === guests.length - 1}` to guest name `<input>` (line ~554) — focuses the newly added guest's name field when "Add Guest" is clicked; only the last guest input gets autoFocus, and since existing guests don't remount, only the new one fires

### Known limitations

- `autoFocus` can scroll the viewport on some mobile browsers. The existing mobile scroll logic (`scrollIntoView`) in page.tsx already handles this for the form container, so the effect is benign.
