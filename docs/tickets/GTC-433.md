# GTC-433 - "Save changes" says when it did not save

> Filed by Claude Code on 31 Oct 2026. Third of the five household
> save tickets (GTC-431 to GTC-435) on fix/household-save, after
> [[GTC-432]] (ef42569).

## The founder's ruling (31 Oct 2026)

3. "Give the 'Save changes' handler a catch that shows the same 'That
   didn't save' message as the other buttons."

## What happened before

`handleEditSave` in src/components/plan/Moment1InputForm.tsx was
try/finally with no catch. When the PUT failed (an error reply, which
the setup page turns into a thrown error; a network failure; a reply
that is not JSON) the button went back to "Save changes" with no words,
and the browser recorded an unhandled rejection. The other two Save
buttons already said "That didn't save — please try again."

## The change (one file, five lines)

`setSaveError(false)` before the save, and a `catch` that sets it.
No new words, no markup change; the setup page's handler is unchanged.

## What she sees when "Save changes" fails

- Above the Save buttons, in the same red line and place as the other
  two buttons: "That didn't save — please try again."
- The form stays open in edit mode exactly as she left it: every name,
  email and phone, all the children, the partner and the picker.
  Pressing "Save changes" again retries the same edit.
- The button reads "Save changes" again, and Cancel still works.
- Her saved household on the card list is unchanged: the PUT is one
  transaction, so the server stored nothing.
- The words stay until her next press (which clears them first) or a
  good save (which closes the form); typing in the name box clears
  them, as for the other buttons.
- No "Please fix" line: that is only for the form's own checks.
