# GTC-223 — STUB: the stale-doc registry is stale about GATHER-BUILD-CONSTANTS.md

**Status:** Open — stub, needs scoping when pulled. **Effort:** TBD (small).
**Severity:** Low — misleading, not breaking. But it misleads about a doctrine file.

*Source: [[GTC-222]], found while applying the approved Citations pointer to
`GATHER-BUILD-CONSTANTS.md` (2026-08-10). Read-only observation; nothing repaired.*

### Context

`gather-docs-and-writing` carries the STALE-DOC REGISTRY — the table an executor is told to
check **before trusting any doc**. Its rows about `GATHER-BUILD-CONSTANTS.md` are themselves
out of date. Three claims, all false as of `7984652`:

| The registry says | Actually |
|---|---|
| Header reads *"Last updated: 2026-03-05"* | Read `2026-08-06` before [[GTC-222]] touched it (now `2026-08-10`) |
| Preflight note *"lists P3005 schema drift as a live pre-existing issue"* | Fixed by [[GTC-215]] (`fedef16`). The note now reads "None currently open" and records the 2026-03-14 baselining plus a live re-confirmation on 2026-08-06 |
| Preamble step 2 *"references FEATURE/CHORE/SPIKE ticket templates that do not exist"* | Fixed by [[GTC-153]] (`9eb6069`). Step 2 now says no dedicated template exists and points feature/chore/spike work at `BUG-TICKET-TEMPLATE.md` |

Both "stale spots" the registry warns about were repaired months ago. The repairs landed;
the warning did not get the message.

This is [[GTC-222]]'s defect one level up. A correction document is written from a verified
read, the thing it describes is then fixed, and being *right at the time* is exactly what
makes it wrong later. The registry is the highest-leverage instance in the repo, because its
entire function is to be trusted about what not to trust.

### Scope

**Fix here:** to be ruled when pulled. Candidate: correct the three claims in
`gather-docs-and-writing` — the `GATHER-BUILD-CONSTANTS.md` freshness caveat in the
docs-of-record table, and the two registry rows — and record the resolving ticket and hash
per the registry's own convention (*"cite the ticket that changed reality"*).

**Explicitly not a registry-wide sweep unless ruled so.** Only the
`GATHER-BUILD-CONSTANTS.md` claims were checked. The other rows —
`moment-1-and-2-build-report.md`, `moment-2-flow-document.md`, the GTC-137/GTC-142 stale
frontmatter, the demo-event-name drift, the untracked-docs list — were **not** verified and
may be equally stale in either direction. Deciding whether this ticket re-verifies all of
them or only the two rows above is a scoping call, not an implementation detail.

### Needs a ruling when pulled

One genuinely stale spot in `GATHER-BUILD-CONSTANTS.md` that the registry does **not** list,
found in the same pass:

**Base Branch.** The file states *"`master` — all work branches off `master` and PRs merge
back to `master`."* In practice `feat/moment-one-redesign` is 156 commits ahead of `master`
and is the branch named by 60 ticket frontmatters — more than any other value. Whether the
constants file should describe the long-lived feature branch, or whether `master` remains
the nominal base and the file is correct as written, is a process question. Not this
ticket's call, and not corrected.

### Acceptance

To be defined when scoped. At minimum: the three false claims corrected with resolving
ticket and hash, and an explicit decision recorded on whether the rest of the registry gets
re-verified in the same pass.

### Stop Conditions

Standard eight from `BUG-TICKET-TEMPLATE.md`. Note that editing `gather-docs-and-writing` is
low-gravity, but any edit to `GATHER-BUILD-CONSTANTS.md` itself needs founder approval in
chat first.
