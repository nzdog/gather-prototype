# GTC-361 — "Check plan" raises false critical conflicts on Moment-flow events

**Status:** Open — a stub, filed 2026-10-03 on founder ruling ([[GTC-360]] plan, Q13: *"file the stub
as GTC-361, not a precondition. Its severity is mine to set later."*). Not scoped.
**Not a precondition of the deploy.**
**Severity:** not set — the founder's to set.

---

### Signal

Found by Claude Code planning [[GTC-360]], 2026-10-03 (read-only). On a pure Moment-flow path no
conflict ever exists: conflicts are created only by `POST /api/events/[id]/check`, which the Moment
flow never starts by itself. But once a check has run on an event — the old dashboard's "Check plan"
button, after which `lastCheckPlanAt` is set and Moment 3 and the dashboard re-run it — two kinds of
CRITICAL conflict appear that are not real for a Moment-flow plan, and the gate
([[GTC-360]]'s hold at "Move on →") refuses until each is acknowledged or dismissed on the old
dashboard.

### What the code shows (read 2026-10-03 at `0630027`)

1. **Every unassigned critical item is a CRITICAL conflict.** `src/lib/ai/check.ts:336-338`, the
   `unassigned-item` detector: `severity: isCritical ? 'CRITICAL' : 'ADVISORY'`. The gate itself says
   assignment never blocks (`src/lib/workflow.ts`: *"ALL_ITEMS_ASSIGNED check removed ... Assignment
   coverage is never enforced as a gate"*), but through this detector an unassigned critical item
   does block, once a check has run. A later check resolves it when the item is assigned.
2. **The dietary detectors read flags the Moment flow never sets.** `check.ts:201` and `:226` count
   items with `vegetarian: true` / `glutenFree: true`; Moment-flow generation
   (`src/lib/ai/plan-write.ts:153-154`) writes `dietaryTags` and never those booleans. So any
   Moment-flow event with a vegetarian or gluten-free requirement gets a CRITICAL "No Vegetarian
   Options" (or gluten-free) conflict the moment a check runs, whatever the plan holds.
3. A conflict that is dismissed or resolved and then detected again reopens (`check.ts:406-423`).

Measured on `gather_dev` the same day: 7 Moment-flow events, none with any conflict, because none had
been checked.

### Open, to scope with the founder one at a time

1. Whether an unassigned critical item should be CRITICAL at all, given the gate's own rule.
2. The dietary detectors: read `dietaryTags`, or both.
3. Whether the Moment flow should run the check at all before the hold, and how a block is shown.
