# [[GTC-099]] — "Run check again" button at top of ConflictList — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** a538e4a

### What was found

The conflict list only showed a "Check Plan" button in the empty/pre-check state. Once conflicts existed, there was no visible manual trigger to re-run the check without navigating away. The `onCheckPlan` prop was already wired through but only used in the pre-check empty state.

### What was changed

**`src/components/plan/ConflictList.tsx`** (lines 253–264):
- Added a "Run check again" button at the top of the conflict list, rendered when `hasRunCheck` is true AND `onCheckPlan` is provided (which only happens when `conflicts.length > 0`, since the return block at line 251 is only reached when conflicts exist).
- Button is right-aligned via `flex justify-end`.
- Uses secondary/ghost style: `px-4 py-2 bg-gray-200 text-gray-700 rounded-md hover:bg-gray-300`.
- Shows "Checking..." and disabled state when `isCheckingPlan` is true.
- Calls the existing `onCheckPlan` prop — no new props or handlers needed.

### Known limitations

None. The button reuses the existing check handler and follows the same disabled pattern as the initial Check Plan button.

### Assertions met

1. PASS — When conflicts exist and a check has been run, "Run check again" appears at the top of the conflict list (line 254: `hasRunCheck && onCheckPlan` guard, inside the `conflicts.length > 0` return block).
2. PASS — Clicking "Run check again" calls `onCheckPlan` (line 257: `onClick={onCheckPlan}`).
3. PASS — While checking, button shows "Checking..." and is disabled (line 258: `disabled={isCheckingPlan}`, line 261: ternary renders 'Checking...' when true).
4. PASS — Button does not appear when `conflicts.length === 0` (the entire return block at line 251 is only reached when `conflicts.length > 0`; the `conflicts.length === 0` cases return earlier at lines 160–248).
5. PASS — Button does not appear when `hasRunCheck` is false (line 254: `hasRunCheck && onCheckPlan` guard).
6. PASS — No console.log statements in src/ (count = 0).
7. PASS — No TypeScript errors (`tsc --noEmit` exits clean).
