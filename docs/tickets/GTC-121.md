# GTC-121 — Moment 2: Progressive AI generation — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 92d1e94

### What was found

- Existing plan generation used a monolithic `POST /api/events/[id]/generate` endpoint that generated the entire plan in one AI call.
- AI call cap tracking is simple: `Event.aiCallsUsed` integer, checked against `AI_CALL_LIMIT = 10`, incremented per call. No shared helper — logic is inline in each endpoint.
- EventSetup model already stored Kate's Step 1 input per-section (mainsData, sidesData, etc.). No `generatedData` field existed for caching progressive results.
- Plan items persist to Team/Item models with `aiGenerated`, `userConfirmed`, `generatedBatchId` flags.
- The Moment2Step1Modal used `setOpenAccordion` directly with no hook into accordion close events for generation.

### What was changed

**Schema:**
- Added `generatedData Json?` to `EventSetup` model — caches per-section AI output keyed by section name.
- Migration: `20260416083832_add_generated_data_to_event_setup`

**New API endpoints:**

1. `POST /api/events/[id]/generate-section` — generates items for a single accordion section via Anthropic API. Validates section, skips "still deciding" sections, stores result to `EventSetup.generatedData`, increments AI call counter. Section-specific prompts kept under 300 tokens input.

2. `POST /api/events/[id]/finalize-plan` — assembles pre-generated sections, fills gaps for missing sections, runs dietary coverage check, generates "Things to consider" checklist. Persists finalized items to Team/Item models. Each gap-fill and check counts as a separate AI call against the cap.

**New component:**
- `Moment2Step2Skeleton.tsx` — skeleton preview screen showing category headings with placeholder bars while plan generates. Items stream in category-by-category with 200ms stagger and fade animation. "Plan looks good" button disabled until fully rendered. Dietary coverage and Things to Consider sections appear after items.

**Updated Moment2Step1Modal:**
- Fires `POST /api/events/[id]/generate-section` in the background when an accordion closes (transitions from open to closed).
- Tracks per-section generation state: `idle | generating | generated | failed`.
- Shows subtle animated dot indicator while generating, green checkmark when done.
- Skips generation for "still deciding" sections.
- Re-generates section if Kate re-edits and closes again (tracks data hash to avoid re-generating unchanged data).
- Flushes pending debounced saves before firing generation.

**Updated page.tsx:**
- Added `showMoment2Step2Skeleton` and `moment2Plan` state.
- When Moment 2 Step 1 modal's "Generate plan" fires: transitions to skeleton screen immediately, calls finalize-plan endpoint, populates skeleton when response arrives.
- Skeleton screen's "Plan looks good" approval refreshes all data and returns to main plan view.
- Old `handleGeneratePlan` path preserved for non-Moment-2 events.

### Known limitations

- "Items stream in" effect is client-side stagger after full response — not true server-sent streaming. This is per the ticket's "if not feasible" fallback.
- The "3 remaining" AI call warning UI is not yet implemented (pre-existing — not in scope for this ticket).
- Things to Consider items are read-only in the skeleton screen — the real interactive checklist is GTC-122.
- Dietary coverage flags are display-only — no "add one?" action button yet.

**AI call cap handling:**
- Each `POST /generate-section` call = 1 AI call, incremented on success.
- `POST /finalize-plan` calls = 1 per gap-filled section + 1 for dietary coverage + 1 for Things to Consider.
- Cap checked before each call; if cap reached mid-flow, remaining calls are skipped.
- Progressive calls track data hashes — unchanged sections are not re-generated.
- Worst case: 6 sections + 1 finalize + 1 coverage + 1 consider = 9 calls (within 10 cap).
