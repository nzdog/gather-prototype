# GTC-148 — Hide V1 Regenerate button on V2 events — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** [pending approval]

**Severity:** High (user-facing incoherence on every V2 event)
**Surfaced by:** External code review (v1-v2 reconciliation review, section 1, Finding 2 — `docs/v1-v2-reconciliation-review.md`).

### What was found (Phase 1 audit)

The dashboard's "Regenerate Plan" button rendered for any non-demo DRAFT/CONFIRMING event with teams — the exact state of every approved V2 plan — and fired the V1 pipeline (`buildRegenerationPrompt`, hardcoded NZ rules) against V2-generated data, reading different persistence (Event dietary/venue columns) than the plan was built from (EventSetup).

Candidate V2-detection signals audited:

- **(a) EventSetup row presence — chosen.** Exactly one write site (`setup/route.ts:216` upsert, called only from Moment2Step1Modal); no migration backfills rows (all four EventSetup migrations are structure-only); `finalize-plan` 404s without a row, so every V2-generated plan implies one. Edge case accepted: a host who touches Step 1 then generates via the V1 button has a row + V1 plan → button hidden anyway (acceptable; nudges them back through V2).
- **(b) Event.source/version/flow field — does not exist** in the schema.
- **(c) Team.source — cannot distinguish**: both pipelines stamp `source: 'GENERATED'` (V1 `generate/route.ts:140,215,252`; V2 `finalize-plan/route.ts:287`).
- **(d) Timestamp heuristic — fragile**, noted as fallback only.
- **(e) `generatedBatchId` prefix** — pipelines use distinct formats (V1 `gen_`/`regen_`, V2 `m2-finalize-`), already present in the dashboard's items payload; tracks the pipeline of the *current* plan but is a string-prefix match on an ID format. Viable zero-query-change alternative; not chosen.

Signal confirmed by Nigel: **EventSetup presence**.

### Detection signal chosen

`event.setup` (EventSetup relation, `schema.prisma:91`), exposed by adding `setup: { select: { id: true } }` to the event query includes in `GET`/`PATCH /api/events/[id]` — both, so an Edit Details save doesn't drop the field from client state and resurface the button.

### What was changed

- `src/app/api/events/[id]/route.ts` — `setup: { select: { id: true } }` added to the GET and PATCH includes (additive response change; nothing else reads it).
- `src/app/plan/[eventId]/page.tsx` — `setup: { id: string } | null` added to the local `Event` interface; `!event.setup &&` added to the Regenerate button's render condition (previously `page.tsx:2105–2107`). The button is not rendered at all on V2 events — no CSS hiding. The V1 path is intact and verified live.

Not touched, per scope: the `/regenerate` route itself, finalize-plan, Moment2PlanView, schema, and all Phase 3 items below.

### Phase 3 findings (adjacent V1 controls — surfaced, not fixed)

1. **"Generate Plan" button** (`page.tsx:2082–2101`, renders when `DRAFT && teams.length === 0`) — fires the V1 pipeline; on a V2 event whose host abandons setup pre-generation this is the entry-side of the same incoherence. Candidate for the same `!event.setup` conditional. **Own ticket.**
2. **GenerationReviewPanel / selective regenerate** (`handleReviewRegenerateSelected` → `/generate`) — sole entry is `setReviewMode(true)` at `page.tsx:1003`, inside `handleRegeneratePlan`. **Closed by this fix on V2 events; no separate work needed.**
3. **RevisionHistory restore** (`revisions/[id]/restore` → `workflow.ts:910`) — not AI, but wholesale-replaces the plan from a V1-shape snapshot on V2 events (post-GTC-147 it no longer deletes people). **Own ticket.**
4. **Resolve with AI** (`conflicts/[id]/suggest-resolution`) — self-contained inline prompt reading current teams/items generically; roughly pipeline-neutral. **Note only.**
5. **Check Plan / conflicts** — rule-based (zero Claude calls in `lib/ai/check.ts`); coherent on V2 data. **No action.**
6. **`/demo/review`** (`demo/review/page.tsx:62`) — the other `/generate` consumer, off-dashboard; its fate is part of the Tier-2 prune decision in the reconciliation review. **Note only.**
