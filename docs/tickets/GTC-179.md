# GTC-179 — E2: Cadence controls — pre-flight pace + per-person go-gentle

**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** high

*Effort level is a proposal from the discovery-report ticket breakdown — run `/effort` manually
before execution.*

### Context

Moment 4 spec §10.3: cadence controls live where the people-decisions live. **Per-event pace**: at
the pre-flight (*nudge pace: standard / relaxed / off*) — a sending decision made where Kate
reviews how everyone is contacted. **Per-person**: a mark alongside the recipient picker (*go
gentle / don't chase*), set at Moment 1 or any time — a hosting judgement the system stores and
obeys. **Don't-chase is the far end** — the per-person off-switch (the mother, the bereaved, the
feuding cousin). Gentle means fewer/softer. **Not a settings page.**

Today: no cadence config field anywhere. The only "gentle" concept is `HostNudgeVariant`
(`warm|casual|gentle|direct`), a message *tone* choice for one-off manual nudges via
`NudgeComposer.tsx` — unrelated to adjusting automated cadence.

### Scope

**Fix here:**
- Per-event pace field (standard/relaxed/off), read by E1's (GTC-178) rebuilt cadence logic.
- Per-person go-gentle/don't-chase field, placed beside C1's (GTC-172) household contact picker.
- Wire E1's nudge scheduler to respect both — don't-chase means zero automated nudges for that
  person; gentle means fewer/softer per §10.3.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`, especially SMS opt-out (Zone 7) — this is
  a distinct, host-facing preference layered on top of opt-out, not a replacement for it.
- The pre-flight screen itself (I1's territory, GTC-188) — this ticket builds the field and the
  scheduler logic; I1 builds where it's surfaced to Kate.
- `HostNudgeVariant`/`NudgeComposer.tsx` — a separate, message-tone concept, not cadence.
