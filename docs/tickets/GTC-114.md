# [[GTC-114]] — Helper section ordering and auto-focus on prepend — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 9fda4c4

### What was found

Two bugs in `Moment1InputForm.tsx`, both caused by index-based React keys (`key={`helper-${i}`}`, `key={i}`):

**Bug 1 — Visual ordering:** When prepending a new helper or guest ([[GTC-113]]), React matched `key="helper-0"` to the previously-existing first element. Instead of mounting a new DOM node at the top, React updated the existing node's props in place. This made it appear as if new sub-forms rendered in the wrong position relative to partner.

**Bug 2 — Auto-focus on subsequent adds:** `autoFocus={i === 0}` targets the first array element, but since React reused the existing `key="helper-0"` DOM node (updating props rather than mounting), the `autoFocus` HTML attribute never fired. Only the very first helper got focus because that was a true mount.

### What was changed

**File:** `src/components/plan/Moment1InputForm.tsx`

- Added `id: string` field to `GuestForm` interface
- Added module-level counter (`formIdCounter`) to generate unique IDs
- `emptyGuest()` now includes a unique `id` field
- Edit-mode population assigns unique IDs to loaded helpers and guests
- Helper sub-forms use `key={helper.id}` instead of `key={`helper-${i}`}`
- Guest sub-forms use `key={guest.id}` instead of `key={i}`

With stable unique keys, React correctly mounts a new DOM element when prepending, which means:
- The new sub-form visually appears at the top of its section (correct ordering)
- `autoFocus` fires on the newly mounted element (correct focus)

### Known limitations

None. The `formIdCounter` is module-scoped and resets on page reload — this is fine since IDs only need to be unique within a single form session.
