# GTC-224 — STUB: TODOs cite spec sections instead of tickets

**Status:** Open — stub, needs scoping when pulled. **Effort:** TBD (small per instance;
the judgment is in what each one becomes, not in the edit).
**Severity:** Low — no behaviour impact.

*Source: [[GTC-222]] scope item 4, "Also observed". Read-only; nothing fixed.*

### Context

[[GTC-222]] establishes: **a deliberate temporary state carries the ticket ID that ends it.**
`eslint.ignoreDuringBuilds: true` in `next.config.js` is the compliant example — it names
[[GTC-221]] as its end condition.

Four instances predate the rule and violate it. Each marks work deliberately deferred, and
none names a ticket:

| Where | The deferred state | What it cites instead |
|---|---|---|
| `restoreFromRevision` in `src/lib/workflow.ts` | `TODO: Revision system - person ID mapping for restored team memberships` | "Section 9 of build spec" |
| `CloneTemplateModal` in `src/components/templates/CloneTemplateModal.tsx` | `TODO: QuantitiesProfile feature` — quantity scaling across templates | "Section 3.11 of build spec" |
| `CloneTemplateModal` in `src/components/templates/CloneTemplateModal.tsx` | "we'll skip this and rely on the clone endpoint to handle it" | nothing |
| `POST` in `src/app/api/templates/route.ts` | "For now, just store the base guest count" | nothing |

**A spec section has no lifecycle.** Nothing closes "Section 3.11", so nothing ever comes
back and removes the TODO. A ticket can be closed, and closing it is what makes the deferred
state end. That is the whole mechanism, and citing a spec section defeats it while looking
responsible — which is why these survived review.

The two uncited instances are worse in a quieter way: "for now" with no referent at all
cannot be distinguished from a permanent design decision by anyone reading it later.

### Scope

**Fix here:** to be ruled when pulled. This ticket is filing only.

**Each instance needs its own decision, and they are not the same decision.** The four fall
into at least three kinds and must not be swept with one pass:

- **Real deferred work** — mint a ticket, cite it from the comment. The `QuantitiesProfile`
  and revision-system person-ID-mapping TODOs look like this, but neither has been scoped
  and neither should be assumed to be wanted.
- **Already-resolved-elsewhere** — if the clone endpoint does in fact handle what
  `CloneTemplateModal` skips, the comment is not a temporary state at all; it is a stale
  note and should be deleted, not ticketed.
- **A settled design decision wearing "for now"** — if storing the base guest count is
  correct, the comment should say *why* it is correct and drop the temporary framing.
  [[GTC-222]]'s comment rule applies: record WHY, not WHAT.

Where a location has no symbol to cite, [[GTC-222]] rule 2 applies —
`// ANCHOR(GTC-nnn): short label`.

**Minting ticket IDs and scoping the underlying work is a founder call**, which is why
[[GTC-222]] filed this rather than resolving it.

### Acceptance

To be defined when scoped. At minimum: a per-instance decision recorded (ticket / delete /
rewrite as WHY), and no instance left citing a spec section.

### Stop Conditions

Standard eight from `BUG-TICKET-TEMPLATE.md`. Additionally: if scoping any instance turns
out to require a product decision about the deferred feature itself, stop and report —
this ticket is about the *citation*, not about building `QuantitiesProfile` or the revision
system.
