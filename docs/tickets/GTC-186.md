# GTC-186 — H1: Wrap-up as a once-only, Kate-reviewed offer

**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** high

*Effort level is a proposal from the discovery-report ticket breakdown — run `/effort` manually
before execution.*

### Context

Moment 4 spec §7/§10.1/§10.4: after the day, one optional reach — a thank-you, a day or two later,
**on Kate's request only** (the assistant may draft and offer; Kate says send). Specific gratitude
powered by the ownership records (*thank you for the pavlova*). §10.1: COMPLETE is
calendar-driven — the event date passing IS the transition, silently, no button. §10.4: the
thank-you is offered **once**, in standard register (*want me to send thank-yous? Here's the
draft*) — Kate-requested means she decides and reviews, never that she has to remember. One offer,
declinable, never repeated; quietly available afterward. Same one-message discipline as the
critical banner.

Today: `WrapUpLink`/`generateWrapUpLinks`/cron dispatch fire **automatically** the moment the host
transitions FROZEN→COMPLETE, for all guests, with no offer or review step — contradicts the ruling
outright. Message content is a thin proxy (`resolveGuestTaskItem` picks the first `ACCEPTED`
assignment's item name), not "specific gratitude powered by the ownership records" in the fuller
sense the spec describes.

### Scope

**Fix here:**
- Replace the automatic FROZEN→COMPLETE trigger with a date-passed-plus-1-to-2-days offer,
  contingent on A3 (GTC-169) having migrated COMPLETE to calendar-driven per §10.1.
- Build the offer-and-review step: the assistant drafts, Kate reviews, Kate sends — not automatic
  dispatch.
- One offer only — declinable, never repeated; quietly available afterward if declined.
- Upgrade the content beyond the current single-first-accepted-assignment proxy toward genuine
  ownership-record-powered gratitude, using H2's (GTC-187) dual-voice architecture.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`, especially SMS opt-out (Zone 7).
- The underlying SMS/email carrier (`WrapUpLink` dispatch mechanics) — reused as-is, not rebuilt.

### Dependencies

A3 (GTC-169) — COMPLETE's calendar-driven trigger must exist first. H2 (GTC-187) for the message
voice architecture.

### Acceptance

- [ ] Wrap-up no longer fires automatically on any host-driven transition.
- [ ] The offer appears once, a day or two after the event date passes (calendar-driven), in
      standard assistant register.
- [ ] Kate must explicitly send — no default auto-dispatch path remains.
- [ ] Declining the offer doesn't repeat it, but leaves it quietly available later.
- [ ] `npx tsc --noEmit` clean, build passes.
