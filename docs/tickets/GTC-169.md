# GTC-169 — A3: Migrate FROZEN consumers to the send-lock model

**Status:** Open | **Branch:** TBD (same experiment branch as A2, unless A1 recommends otherwise) | **Commit:** [pending] | **Effort:** xhigh

---

### Context

GTC-168 (A2) builds the new schema/ledger/versioning mechanism. This ticket migrates every
existing FROZEN consumer to it — replacing hard-block gating (`requireNotFrozen`,
`canMutate`'s blanket FROZEN denial) with the ruled model (always-allow, reason required only when
the why-scope rule says so) and replacing FROZEN-keyed UI branches with send-based ones.

**Flag for the executor before starting:** this is the largest single surface in Epic A. If A1's
sequencing (GTC-167) shows the ~30 sites splitting cleanly by layer, consider proposing a split
into sub-tickets (e.g. A3a — API routes/guards, A3b — UI components/god file) rather than forcing
one ticket across the whole surface. Raise that with Nigel before committing to one ticket if the
scoped diff looks large — this is explicitly anticipated, not a scope-creep flag.
