### Context

A2 built the predicates and the ledger, additively. This ticket is the first that **changes
behaviour**: every lifecycle-derived hard block is removed, and the nudge predicate inverts.

It is the smallest diff in Epic A and the only one that touches the security contract.

### ⚠ Zone 6 — explicit founder instruction on record

`gather-change-control` Do-Not-Touch zone 6 forbids weakening or skipping security-suite assertions.
**Nigel approved rewriting them for this ticket, 2026-08-03, in these terms:**

> "Security suite: APPROVED to rewrite — replace, never delete. The new assertions must hold the
> send-lock contract at equal strength: post-send mutations carry ledger entries, why-scope triggers
> fire, hard-blocks absent. Explicit instruction per zone 6; note it in the A3a ticket."

Approval is **scoped to this ticket and to that standard**. Assertions are *replaced at equal
strength*, never deleted to make a build pass. Any assertion that cannot be replaced at equal
strength is a stop-and-report.

| Removed assertion | Replacement (equal strength) |
|---|---|
| 1.2 `requireNotFrozen` blocks FROZEN (`security-validation.ts:62–108`) | A post-send coordinator mutation **succeeds AND writes a ledger entry** — asserts both halves |
| 1.4 `requireNotFrozen` allows FROZEN with override (`:160–206`) | No direct successor (override was a FROZEN concept). Replaced by: **no lifecycle-derived 4xx on any Layer-1 route post-send** |
| 3.4 Coordinator items route has frozen validation (`:386–403`) | Coordinator items route calls `recordChange()` on every mutation path |
| 3.5 Coordinator item edit route has frozen validation (`:414`) | Same, for PATCH and DELETE |
| — *(new)* | `touchesSomeone()` fires on T1–T5 and stays silent on every enumerated non-trigger |
| — *(new)* | `restoreFromRevision` is **refused post-send** — the only new post-send restriction (Hinge §2, no undo at the mechanism level) |
| — *(new)* | A touching-someone change **without** a reason still succeeds, recorded as `reasonRequired: true, reason: null` (§13.1, endorsed) |

`tests/security-fixtures.ts` `Security Test Event (FROZEN)` (`:205–212`) becomes
`Security Test Event (SENT)` with `sentAt` set.

### Ruling folded in: coordinators (Nigel, 2026-08-03)

> "(a) — same always-allow + ledger as the host. **No walls anywhere, ledger is actor-agnostic.**"

So `requireNotFrozen` is deleted outright rather than narrowed to a host-only bypass, and the

### RED → GREEN

Suite rewritten FIRST and run against unmigrated code (commit `8d799a4`): **38 tests, 29 passed,
9 failed** — every failure a real send-lock violation:

| # | RED failure | Cause |
|---|---|---|
| 1 | Legacy FROZEN event blocks mutation | `requireNotFrozen` |
| 2 | Guest cannot respond post-send | `p/ack` 400 "responses are locked" |
| 3 | Lifecycle hard-blocks remain on 6 mutation routes | structural |
| 4 | Coordinator blocked in SENT-LEGACY | `requireNotFrozen` |
| 5 | Coordinator authority not phase-invariant | consequence of 4 |
| 6 | Host assign route carries a lifecycle gate | `requireNotFrozen` |
| 7 | `restoreFromRevision` not refused post-send | undo was reachable |
| 8 | …and threw no recognisable refusal | consequence of 7 |
| 9 | **Two people would be nudged AFTER their event date** | `status: 'CONFIRMING'` filter |

After migration (commit `794e0ff`): **38 tests, 38 passed, 0 failed.**

Failure 9 deserves its own line: it is a live §10.1 violation ("Post-date: nudges dead") that no
test previously covered, it does not depend on FROZEN at all, and it is the strongest evidence that
the nudge-predicate inversion belonged in A3a rather than being deferred to E1.

### The suite is stronger, not merely different

| | Before | After |
|---|---|---|
| Tests | 16 | **38** |
| Route protection | 6 `fs.readFileSync` + substring checks | **real handlers invoked in-process, asserting HTTP status codes** |
| Token auth | grep for the import | unknown token 403, participant token on a coordinator route 403, cross-team coordinator 404, coordinator token on the participant ack route 403 |
| Lifecycle | `requireNotFrozen` unit tests | predicate tests + behavioural assertions across all four phases |

Token routes take their token from params and authenticate purely via `resolveToken` — no cookies,
no middleware — so the handlers are directly callable. That is what made the upgrade possible, and
it was verified by probe before the suite was written.

**The FROZEN fixture was repurposed, not orphaned.** It became `Security Test Event (SENT-LEGACY)`
and now proves the opposite property: a pre-migration FROZEN event must still *read* as sent through
the compat shim. Nothing previously covered the read-compatibility claim [[GTC-199]] (A4) depends on.
Four fixtures now scaffold the four lifecycle phases, each with two teams, coordinators,
participants, items, assignments and tokens.

One assertion of mine was badly designed and was fixed before the RED was recorded: the no-undo test
originally drove the restore *route*, which is session-authed, so it 500'd on `cookies()` outside a
request scope and could never have passed. The guard was moved into `restoreFromRevision()` itself —
no-undo is a domain invariant that must hold for every caller, not one HTTP path — and the test now
calls the function directly.

### Deviation from the plan's §12.1 table, taken deliberately

The A1 plan proposed asserting that a post-send coordinator mutation "succeeds **and writes a ledger
entry**". **The ledger half cannot be asserted in A3a** — `recordChange()` is uncalled here by
design, so the assertion would either fail or force ledger wiring into A3a and move the A3a/A3b seam
by drift. Nigel's instruction already corrected this ("succeed AND are gated correctly by actor
authority"). **[[GTC-196]] (A3b) owns the ledger-entry assertion**, and its acceptance already
requires it.

### Found during migration and handled

**Freezing used to be what prevented a second press.** Once an event was FROZEN,
`confirm-invites-sent` 400'd. Removing FROZEN removes that protection, so both routes gained an
explicit idempotency guard: `if (event.sentAt) → 400`. Hinge §7 — "The send happens once, for her."
People added afterwards get a mini-send, not a re-press. This is not scope creep; it replaces a
protection this ticket removed.

### `canMutate` deleted (plan recommendation, approved)

With the FROZEN and COMPLETE denials gone and the unreachable CONFIRMING critical-delete branch gone
(its only caller passed `itemCritical: false`), it returned `true` for every input. A gate that
always passes is worse than no gate — it reads as protection while providing none. Same reasoning
that removed the unwired `canFreeze()` in GTC-154. Five call sites removed with it.

### The A3a/A3b seam held

`grep -rn "recordChange" src | grep -v 'src/lib/ledger.ts'` → **0 matches.** Nothing in this ticket
required `recordChange` to be *correct* rather than merely gated; every un-gated route already calls

That is the designed window from plan §4.3, and it is why Epic A merges as one unit ([[GTC-200]]).
