# GTC-456 - Constants: production deploy notes

**Status: committed (a8882c7), approved by the founder 6 Nov 2026 (NZ time).** Docs only.

All dates are NZ time (the GTC-455 convention).

## What and why

On 6 Nov 2026 the founder released GTC-453 to GTC-455 to production. Two things in
`GATHER-BUILD-CONSTANTS.md` stopped being true that day:

1. **Production's automatic build.** GTC-455's note said it was off. The founder switched it on
   to release this work (live at 11:51). While it stays on, a merge to `main` deploys staging and
   production together: production's trigger branch is `main`, per the founder's deploy log and
   the founder's statement of 31 Oct 2026 (the Source setting itself was not seen). Whether it
   stays on is the founder's decision.
2. **Where migrations run.** A draft of this ticket read production's build log, saw no
   `prisma migrate deploy`, and wrongly concluded that a production deploy does not apply
   migrations. The founder corrected it: by their D8 ruling of 26 Oct 2026, migrations run in
   Railway's **pre-deploy** step, as `npm run db:migrate:deploy`, typed in Railway only and shown
   in the founder's 28 Oct 2026 screenshots of the production service. The custom build command
   (`node scripts/check-live-sends.mjs && npm run db:generate && npx next build`) leaves them out
   on purpose. A failed pre-deploy stops the deployment. A release that carries a migration still
   needs the usual rehearsal on a copy first. The repo does not record the D8 ruling or the
   pre-deploy command. They are the founder's records, in the Gather Build project docs:
   `claude/deploy-log-2026-10.md` (D8) and `claude/deploy-handoff-2026-10-26.md` (production as
   seen on 28 Oct). The constants file now cites them, as the founder's statement.
