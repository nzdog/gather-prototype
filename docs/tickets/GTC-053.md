# GTC-053 — Refresh button on Wrap-Up Status modal does nothing — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** 4a3ce91

### What was found

The Refresh button handler (`loadWrapUpStatus`) existed and was correctly wired to the button's `onClick`. However, two issues caused the appearance of "nothing happening":

1. **No `cache: 'no-store'` on the fetch** — the `GET /api/events/[id]/wrap-up/status` request used the browser's default fetch caching. On repeated calls to the same URL, the browser could serve a cached response without making a visible network request, explaining the "no network request visible in devtools" observation.

2. **No loading state feedback** — the function had no visual indicator (no spinner, no disabled state, no text change). Even when the fetch did fire, if the returned data was unchanged the user had no way to know a refresh occurred.

### What was changed

- `src/app/plan/[eventId]/page.tsx` — Three changes:
  1. Added `wrapUpStatusLoading` state variable (line 262)
  2. Updated `loadWrapUpStatus` to set loading state (`setWrapUpStatusLoading(true/false)`) and added `cache: 'no-store'` to the fetch options to bypass HTTP caching (lines 886–899)
  3. Updated the Refresh button to show "Refreshing…" text and `disabled` state while loading (lines 2784–2790)
  4. Updated the "Load dispatch status" button with matching loading state (lines 2868–2874)

### Known limitations / follow-up flags

None. The fix is scoped to the Wrap-Up Status modal's refresh mechanism only.
