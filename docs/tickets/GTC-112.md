# [[GTC-112]] — Two types of children: kids with jobs and kids without jobs — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** f27d607

### What was found

The Moment 1 household model stored all children as a single `childCount` integer on the Household record — no names, no individual records. This meant older children who could be assigned tasks in Moment 3 were indistinguishable from younger children who are just a headcount.

All `childCount` references were found across 10 files: schema, 2 API routes, 3 UI components, 1 plan page, 1 invite-status route, 1 test file, and 5 closed ticket docs (docs unchanged — historical record).

### What was changed

**Schema:**
- Added `CHILD` to `HouseholdRole` enum
- Renamed `childCount` to `littleCount` on Household model
- Migration: `20260414050000_add_child_role_rename_littlecount` — column rename preserves existing data

**API — POST `/api/events/[id]/households`:**
- Accepts `helpers` array (kids with jobs) and `littleCount` (kids without jobs)
- Each helper creates a Person + PersonEvent with `householdRole: CHILD`
- Helper name is required — validated server-side
- Email validation includes helpers

**API — PUT `/api/events/[id]/households/[householdId]`:**
- Same payload shape as POST
- Helpers follow the same delete-and-recreate pattern as partners and guests

**API — GET `/api/events/[id]/invite-status`:**
- `totalChildren` now reads `littleCount` instead of `childCount`

**UI — `SavedHousehold` type (`HouseholdCardList.tsx`):**
- Added `helpers: Array<{ name: string; email?: string; phone?: string }>`
- Renamed `childCount` to `littleCount`

**UI — `Moment1InputForm.tsx`:**
- Replaced single "Add Children" button with two buttons: "Kid with a job" and "Kid without a job"
- "Kid with a job" reveals a sub-form with name (required), email, phone — same blue-border pattern as partner/guest
- Multiple kids with jobs allowed — each click adds another sub-form
- Auto-focus on name field when added
- "Kid without a job" reveals number input for `littleCount` (1–20)
- Both types can coexist in one household
- Name validation prevents saving a kid with a job without a name
- `Moment1PersonInput` interface updated with `helpers` and `littleCount`

**UI — `HouseholdCardList.tsx`:**
- Shows 👦 [name] for each kid with a job
- Shows 🧒 [count] for kids without jobs (only when > 0)
- +N badge counts: partner + helpers + littles + guests

**UI — `Moment1Summary.tsx`:**
- Stats line shows separate "kids with jobs" and "kids without jobs" segments (omitted when zero)
- Missing contacts loop includes helpers
- Contact save flow handles helper updates

**UI — `page.tsx` (plan page):**
- `apiHouseholdToSaved` maps CHILD PersonEvent members to `helpers` array
- People count includes helpers and littles

**Tests — `moment1-input-test.ts`:**
- Updated from 24 to 32 tests
- Added: helper counting, helper name validation, helper email validation, helpers+littles coexistence, littleCount bounds

### Known limitations

- Existing households with `childCount > 0` migrate to `littleCount` (kids without jobs). No helpers are created from existing data — Kate would need to edit the household to add kids with jobs. This is the intended behavior per ticket.
- The invite-status route's `totalChildren` field now only counts littles, not helpers. Helpers are counted as regular PersonEvent members.
