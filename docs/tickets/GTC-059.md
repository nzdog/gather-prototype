### What was found
- **Auto-assign logic:** `src/app/api/events/[id]/people/auto-assign/route.ts` — assigns unassigned PARTICIPANTS to teams using even distribution. Did NOT assign items. Did NOT exclude host (relied on `role: 'PARTICIPANT'` filter, but host could have PARTICIPANT role in PersonEvent).
- **Item assignment API:** `src/app/api/events/[id]/items/[itemId]/assign/route.ts` — creates `Assignment` record linking `itemId` to `personId`, updates `Item.status` to `ASSIGNED`. Requires person to be in same team as item.
- **Host identification:** `Event.hostId` field on the Event model. `PersonEvent.role` may not be HOST if the host was added as a participant.

### What was changed

**`src/app/api/events/[id]/people/auto-assign/route.ts`**
- Fetches `Event.hostId` at the start of the route
- Forces host's `PersonEvent.role` to `HOST` via `updateMany` before participant query (fixes case where host was added as PARTICIPANT)
- Excludes host from unassigned participants query via `personId: { not: event.hostId }`
- After team assignments, distributes unassigned items among team members using round-robin within each team
- Creates `Assignment` records and sets `Item.status` to `ASSIGNED` for each distributed item
- Returns `itemsAssigned` count and `itemAssignments` details in response

**`src/components/plan/PeopleSection.tsx`**
- Updated success toast to include item assignment count when items were assigned

**`tests/auto-assign-items-host-test.ts`** (new)
- 10 assertions testing host exclusion, role enforcement, item distribution, cross-team integrity, and status updates

**`package.json`**
- Added `test:auto-assign` script

### Known limitations / follow-up flags
- Items distributed via round-robin (not by category or weight) — adequate for even distribution but doesn't consider item complexity
- If a team has items but no members after auto-assign, those items remain unassigned (edge case: more teams than people)
- No maximum items-per-person constraint enforced
