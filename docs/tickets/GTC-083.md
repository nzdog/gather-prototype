# GTC-083 — Import Contacts: Button Rename + Help Section — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** _pending_

### What was found

Pure UI/copy ticket. Two user-facing changes:

1. The People modal action bar exposed an `Import CSV` button
   (`src/components/plan/PeopleSection.tsx:302`), unchanged since before
   GTC-082 landed VCF support. The label no longer reflects what the
   button does (it now accepts both CSV and VCF).
2. The Step 1 screen of the import modal had brief format descriptions
   but no guidance on how to export contacts from iPhone, Android,
   Gmail, or Outlook.

Inventory grep of `"Import CSV"` across `src/`, `docs/`, and `public/`:
- `src/components/plan/PeopleSection.tsx:302` — user-facing button label (renamed)
- `src/components/plan/PeopleSection.tsx:296, 460` — JSX comments (internal, stripped at build; left alone per ticket scope)
- `docs/02_ux/COMPREHENSIVE_UI_MAP.md`, `docs/03_specs/csv-import-spec.md`,
  `docs/_archive/TEST_PHASE_2_RESULTS.md`, `SETUP_CHECKLIST_IMPLEMENTATION.md`
  — documentation / archived specs, not user-facing UI. Out of scope.

### What was changed

**`src/components/plan/PeopleSection.tsx`**
- Button label at line 302 renamed from `Import CSV` → `Import Contacts`.
- No `aria-label` was present on the button, so nothing else needed updating.
- JSX comments (`{/* Import CSV Button */}`, `{/* Import CSV Modal */}`)
  deliberately left unchanged — they are non-user-facing.

**`src/components/plan/ImportCSVModal.tsx`**
- Added a "Need help?" section at the bottom of the Step 1 (Upload)
  container, after the dashed-border upload dropzone and before the
  modal footer.
- Structure: a small uppercase heading "Need help exporting your contacts?"
  followed by a `<ul>` with four platform entries (iPhone, Android,
  Gmail / Google Contacts, Outlook).
- Each entry: platform name in a medium-weight paragraph, one plain-language
  instruction paragraph, one "Step-by-step guide →" link.
- All four links use `target="_blank" rel="noopener noreferrer"`.
- Visual treatment: `text-xs text-gray-500` for body text, `text-accent`
  for links, visually subordinate to the upload area per the ticket's
  "unobtrusive, smaller text, secondary colour" guidance.
- The Outlook entry explicitly states "Outlook exports contacts as a CSV
  file (not VCF)" so hosts know to expect a CSV and that this is correct.
- Static list — no collapsible accordion, no icons, no logos. Plain text
  and links only, per ticket.

### Known limitations

- Documentation files in `docs/03_specs/csv-import-spec.md` and others
  still refer to the button as "Import CSV". These are internal
  documentation describing historical state and were not in scope for
  this ticket.
- The `ImportCSVModal.tsx` component file name and `ImportCSVModalProps`
  interface name retain the CSV-centric naming. This is internal and
  intentionally not renamed per the "do NOT rename internal function
  names, variable names, or component names" instruction.
- The four external guide URLs are third-party pages. If any of them
  rot, the section copy will still remain instructive but the "Step-by-step
  guide →" links may 404. No monitoring is in place for this.
