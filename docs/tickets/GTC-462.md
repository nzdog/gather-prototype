# GTC-462 - The /demo checks and the 6bc9572 comparisons: stale, or is /demo broken?

**Status: open, filed 14 Nov 2026 on the founder's word, from GTC-461's full gate. Nothing
built, no branch.** The first job is to establish whether these checks are stale or the `/demo`
page is actually broken, and report that to the founder before any check or page is changed.

All dates are NZ time (NZDT, UTC+13).

**Before running any suite, read GTC-461's section "Read this before the next gate".** It holds
R1 (never run anything against gather_dev), the gate's set-up on gather_demo, the stale Prisma
client after a branch switch, and the cron secret that lands in the dev log and `.next/trace`.

## A lead from the record, not yet checked

GTC-457 (the closed explainer under "Try it yourself", 8 Nov) lists the same 13 `/demo` checks
under "Tests: red by design, not yet changed". Its change put the explainer under the button,
and these checks pin the page as one button and nothing else. It calls the change each needs "a
flip, not a weakening", left unedited until the founder rules, because the suites also carry
hash and commit pins (demo-note U1 to U5, demo-public C7). GTC-458 and GTC-459 say the 13 stay
red until they are flipped. None of the three lists C7 or C8, or says when they went red.

On that record the 13 checks are stale and the page is as intended. This ticket confirms it from
the page itself before anything changes.

## The first job: stale checks, or a broken page?

1. For each of the 13 checks, see what it found instead. The suites print the drawing cut at 200
   characters; print it whole (in a scratch copy, not the suite) and compare it with the page
   GTC-457 to GTC-459 describe: the heading, the "Try it yourself" button and the closed
   explainer. If the explainer is the only extra, the check is stale. Anything else (a second
   button, the note with the switch on, a fetch from `/demo`, the Sarah handler back, a door that
   opens the wrong page) means the page is broken.
2. Look at `/demo` in a browser, on gather_demo, guarded: development and a production build,
   the switch on and off. Screenshot each.
3. C7 and C8: list every file and script line that differs from 6bc9572 at `origin/main`, and
   name the commit and ticket that brought each (`git log 6bc9572..origin/main`). A difference no
   ticket accounts for is a finding to report, not something to allow.
4. Find when C7 and C8 first went red: run `test:demo-public` at each merge on main after
   6bc9572 (`git log --first-parent 6bc9572..origin/main`), same settings.
5. Report to the founder, check by check: stale or broken, with the evidence. Change nothing
   until the founder rules.

## Then, only on the founder's ruling

- **If stale:** flip each of the 13 checks to the page as it is now, at the same strength (a
  flip, not a weakening: GTC-457), and prove each flipped check goes red on a break. Re-base C7
  and C8 so they name every allowed file and script line, GTC-461's three files included.
- **If broken:** mend the page under its own ticket, and leave the checks as they are.

## Scope

In: the 13 `/demo` checks above, and `test:demo-public` C7 and C8. Out, unless the founder adds
it: `test:demo-tweaks-5` F4 ("across N source files no code (comments aside) says 'Fill in
typical answers'"), also red at untouched main, left alone by GTC-461's ruling 7.

## Stop conditions

1. Any check weakened rather than flipped, or deleted.
2. Anything run against gather_dev (R1), or any gate run not set up as GTC-461 records.
3. Any change in a Do-Not-Touch Zone.
4. Any commit, push or merge without the founder's approval.
