# GTC-130 — Align eslint-config-next with installed Next.js major version — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** b6e6e38 | **Effort:** medium

**Closure note (added 2026-08-23, during Dependabot triage GTC-243–246):** Path A was executed
by commit `b6e6e38` ("fix: correct eslint-config-next mismatch; decouple lint from build gate",
2026-08-06) — **without referencing this ticket**. The commit message independently rediscovers
this ticket's own root-cause diagnosis (the `eslint-config-next@^16` vs `next@15` mismatch
crashing ESLint with a circular-JSON error). Closing now, retroactively, with the commit that
already did the work. Path B (upgrade Next to 16.x) was **not** taken and remains a live,
undecided option — its analysis in this ticket is cited from
[[GTC-244]] rather than re-derived there.

### Context

GTC-128 surfaced a longstanding ESLint dependency drift while fixing the unrelated route-export build break. The error manifests as:

> `Converting circular structure to JSON ... property 'react' closes the circle`

during `next lint` and `next build`. The error is non-fatal — both commands exit 0 — but the warning is logged on every build.

Root cause: `eslint-config-next` is pinned to `^16.2.2` while `next` is on `^15.5.12`. The version mismatch causes the plugin/config graph to reference itself when ESLint walks it. Diagnosed during GTC-128 investigation.

### Scope

**Fix here:**

- Decide between two paths:
  - **Path A:** Downgrade `eslint-config-next` to `^15.x` to match the installed Next.js major version. Lower risk, more aligned with current Next version.
  - **Path B:** Upgrade Next.js from 15.5.12 to 16.x to match eslint-config-next. Higher risk (Next.js majors can have breaking changes), broader scope, but forward-moving.
- Apply the chosen path, verify `next lint` and `next build` produce no circular-structure warning.
- If Path B is chosen, run full regression check on Moment 1 and Moment 2 flows — Next.js major upgrades can affect routing, middleware, and React Server Components behaviour.

**Do not touch:**

- Any other dependencies unless directly required by the chosen path.
- Existing ESLint rules or config beyond the version alignment.

### Considerations

- Path A is the minimal-scope fix. Recommended unless there's a separate reason to upgrade Next.js.
- The build is currently green even with the warning, so this ticket is not launch-blocking — it's hygiene.
- Worth checking whether `next lint` is being deprecated in favour of the new ESLint flat config format, which may make this ticket moot if the project migrates to flat config separately.

### What was found (confirmed against commit b6e6e38, 2026-08-23)

Path A, exactly as this ticket specified: `eslint-config-next` downgraded from `^16.2.2` to
`^15.5.22` in `package.json`. `next lint` re-run live on 2026-08-23 confirms the circular-
structure crash is gone — real lint output (warnings/errors on actual source files), zero
occurrences of "circular" anywhere in the output. This ticket's stated verification goal is met.

`next lint` also now prints: `` `next lint` is deprecated and will be removed in Next.js 16. ``
— confirming this ticket's own "Considerations" note that flat-config migration could make the
underlying tooling moot; not yet acted on, just now independently confirmed true.

### What was changed (beyond this ticket's declared scope — flagged, not silently absorbed)

`b6e6e38` did one thing this ticket's "Do not touch" list explicitly excluded: it set
`eslint.ignoreDuringBuilds: true` in `next.config.js`. This wasn't optional scope creep — fixing
the version mismatch let ESLint actually run for the first time, which surfaced 68 pre-existing
lint errors this ticket had no way to anticipate (its own Considerations section assumed "the
build is currently green"). Rather than leaving those errors to block the build unexamined, the
commit gated them behind `ignoreDuringBuilds`, tracked the flag's removal under **GTC-221**
(cited both in the commit message and as a code comment in `next.config.js` — correct use of
this repo's "a deliberate temporary state carries the ticket ID that ends it" citation
convention), and left GTC-221 to actually clear the 68 errors. Recorded here for the audit
trail; GTC-221 is a separate, already-tracked piece of work, not owned by this ticket.
