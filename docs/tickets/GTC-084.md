# GTC-084 — Import Contacts: Accordion Help Section + Button-Style Guide Links — CLOSED
**Status:** Complete | **Branch:** master | **Commit:** [pending]

### What was found
- The "Need help exporting your contacts?" section in `src/components/plan/ImportCSVModal.tsx` (Step 1) was rendered as a static heading + unordered list, always visible when the modal opened.
- The four "Step-by-step guide →" links were rendered as plain anchor tags styled with `className="text-accent hover:underline"` — inline text, not button-like.
- Existing secondary/ghost button style in the app is the "View as Host" button at `src/app/plan/[eventId]/page.tsx:1454`, which uses the Tailwind utility pattern: `px-4 py-2 bg-gray-200 text-gray-700 rounded-md hover:bg-gray-300`.
- Existing expand/collapse pattern in the codebase uses `ChevronDown` / `ChevronRight` (or `ChevronUp`) icons from `lucide-react` (e.g. `src/components/plan/WhosMissing.tsx:107-117`). Unicode ▸/▾ is not used.

### What was changed
- Added `ChevronDown` to the `lucide-react` imports in `ImportCSVModal.tsx` (alongside the existing `ChevronRight`).
- Added `helpOpen` React local state (`useState<boolean>(false)`), defaulting to closed.
- `resetModal()` now also resets `helpOpen` to `false` so the accordion is closed the next time the modal opens.
- Converted the `<h3>` heading into a native `<button type="button">` with:
  - `onClick` toggling `helpOpen`
  - `aria-expanded={helpOpen}`
  - `aria-controls="import-help-content"`
  - A `ChevronRight` icon when closed and a `ChevronDown` icon when open (equivalent to ▸/▾)
  - The original uppercase small-caps styling preserved
- The `<ul>` content is now conditionally rendered on `helpOpen` and tagged with `id="import-help-content"`. All four platform entries and their copy are preserved exactly as written in GTC-083.
- Each of the four `<a>` "Step-by-step guide →" links now uses the exact secondary button class from the "View as Host" button: `inline-block mt-2 px-4 py-2 bg-gray-200 text-gray-700 rounded-md hover:bg-gray-300`. They remain `<a>` tags with `target="_blank"` and `rel="noopener noreferrer"`, and all four URLs are unchanged.

### Known limitations
- The show/hide is an instant swap (mount/unmount) rather than a height/opacity CSS transition. The ticket permitted a simple transition but did not require one, and the existing expand/collapse pattern in the codebase (`WhosMissing.tsx`) uses the same instant-swap approach, so this matches existing conventions.
- The accordion uses conditional rendering (`helpOpen && (...)`) rather than `hidden`/`aria-hidden`, which is consistent with accessibility expectations since `aria-expanded` on the toggle button communicates state to assistive tech.
