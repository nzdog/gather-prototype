## Signal

**Expected**
`GET /api/events` returns the same narrowed event shape that `GET` and `PATCH`
in `src/app/api/events/[id]/route.ts` return. [[GTC-267]] established that
contract and named the columns: a join credential, the Stripe columns, and the
check-plan telemetry do not go over the wire.

**Actual**
`GET` in `src/app/api/events/route.ts` calls `prisma.event.findMany` with an
`include` and **no top-level `select`**, so every scalar column on `Event` is
serialised for every event the caller holds a role on. That is the exact shape
[[GTC-267]] removed from the single-event route — `EVENT_WIRE_SELECT` was
introduced for it — and the list route was not part of that ticket's scope.

**Smallest failing case**
Call `GET /api/events` with any valid session and read `sharedLinkToken`,
`stripePaymentIntentId`, `paidAt`, `amountPaid` and the check-plan telemetry
out of the response for every event the user hosts.

---

## Evidence

`GET` in `src/app/api/events/route.ts`, verbatim shape at `9272222`:

```
const events = await prisma.event.findMany({
  where: { eventRoles: { some: { userId: user.id } } },
  include: {
    _count: { select: { teams: true, days: true } },
    eventRoles: { where: { userId: user.id }, select: { role: true } },
    setup: { select: { id: true } },
  },
  orderBy: { createdAt: 'desc' },
});
```

`include` without a sibling `select` means "all scalars, plus these
relations". The columns [[GTC-267]] named as forbidden are all scalars on
`Event`, so all of them are present.

**`sharedLinkToken` is the one that matters.** It is a declared credential
column in the route scanner's own list — `CREDENTIAL_COLUMNS` in
`tests/security-route-scan.ts` carries `{ model: 'event', field:
'sharedLinkToken' }` — and `POST /api/join/[token]/claim` authenticates on it.
So this route hands a join credential to anyone with a role on the event,
including a `COORDINATOR`, for every event in the list.

**What contains it, and it is a real containment, not an accident.** The route
calls `getUser` and filters on `eventRoles.some.userId`, so a caller sees only
events they already hold a role on. This is not the anonymous class
[[GTC-267]] closed. It is a response wider than the contract, reachable by a
legitimately authenticated caller.

## Scope

**Fix here:**
- `GET` in `src/app/api/events/route.ts` — a top-level `select`. **Reuse
  `EVENT_WIRE_SELECT`** rather than writing a second list; [[GTC-267]] created
  it for exactly this shape and two divergent narrowings would be worse than
  one wide one. It currently lives in `src/app/api/events/[id]/route.ts` and
  would need exporting, or moving to a shared module.
- Every caller of `GET /api/events` — `src/app/plan/events/page.tsx` is the
  one known consumer and must be checked against the narrowed shape before the
  narrowing lands, not after.
- `tests/security-validation.ts` — new assertions, adding and never weakening.
  Assert on a fixture where the forbidden columns are **populated**, so an
  absence is a drop and not a gap. That is [[GTC-267]]'s standard and it
  caught a real gap there.

**Do not touch:**
All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md` are binding. Zone 3
(AccessToken & scope system) is adjacent: this changes **what is serialised**,
never what a token is or how it is minted.

## Evidence (Executor-Completed)

**Root cause confirmed**

`GET` in `src/app/api/events/route.ts` passed `include` to `prisma.event.findMany`
with no sibling top-level `select`. In Prisma that means "every scalar on the row,
plus these relations", so all sixteen columns [[GTC-267]] forbids went out for every
event the caller holds a role on. Reproduced live before any change was made, signed
in as `nigel@mckorbett.co.nz`: **66 keys per event across 21 events, 34,260 bytes**,
all sixteen forbidden columns present, and nine events carrying real Stripe values
(`stripePaymentIntentId: "pi_3TJ8wPIP69tdO3sa0FydLR4F"`, `amountPaid: 1200`,
`paidAt: "2026-04-06T08:55:32.797Z"`).

Reported honestly: on this database `sharedLinkToken` was `null` on every one of that
host's events, so the **shape** was wrong but no live join credential was in flight.
The credential exposure is proven on a fixture where the column is populated — see
suite 13 below, which is why the ticket's "populate first" rule matters.

**Files changed**

- `src/lib/events/wire-select.ts` — **new**. Both wire shapes, one file. Holds
  `EVENT_WIRE_SELECT` (moved verbatim from the route below; the field list is
  byte-for-byte what [[GTC-267]] shipped, verified by diff against HEAD) and the new
  `EVENT_LIST_WIRE_SELECT`. One file because two narrowings in two files are two
  narrowings that will disagree; two constants because the two routes answer two
  different questions and a single union would be a superset of both.
- `src/app/api/events/route.ts` — `GET` now passes a top-level `select`:
  `EVENT_LIST_WIRE_SELECT` spread, plus `eventRoles` composed on top because its
  `where` is bound to the calling user. `POST` untouched.
- `src/app/api/events/[id]/route.ts` — `EVENT_WIRE_SELECT` definition removed, now
  imported. No behavioural change; the constant only changed address.
- `tests/security-validation.ts` — suite 13 added (13 assertions) and registered in
  `main()`; `randomBytes` imported for the coordinator fixture. Nothing weakened or
  removed; Zone 6 respected.

**The field list, and where it came from**

Built from the route's callers, not from the single-event route's list. **`EVENT_WIRE_SELECT`
did not fit, in either direction** — it lacks `archived` and `createdAt`, which
`/plan/events` filters and renders, and it carries ~20 venue/dietary/guest-count
fields the index never reads, multiplied by every event in the list.

- `src/app/plan/events/page.tsx` (`loadEvents`), the only application caller —
  `id`, `name`, `status`, `startDate`, `endDate`, `guestCount`, `occasionType`,
  `archived`, `createdAt`, `_count.teams`, `setup`.
- `testSuite11_DemoSessionScope` in `tests/security-validation.ts`, which enumerates
  the demo session's blast radius off this same route — `id`, `name`, `isDemo`. So
  `isDemo` is load-bearing for a security assertion, not scenery.

`_count.days` is selected and read by nobody; kept because the page's own `Event`
interface declares it and a select that makes a declared type lie is a worse trap than
an unread aggregate. `eventRoles` also has no reader in the tree; kept because it is a
two-field relation with no column exposure, so dropping it would spend risk on
something this contract is not about. Both recorded here rather than silently trimmed.

Result: **66 keys → 13, 34,260 bytes → 7,497** (a 78% smaller response), zero
forbidden columns.
