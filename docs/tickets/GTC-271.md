## Signal

**Expected**
`GET /api/events` returns the same narrowed event shape that `GET` and `PATCH`
in `src/app/api/events/[id]/route.ts` return. [[GTC-267]] established that
contract and named the columns: a join credential, the Stripe columns, and the
check-plan telemetry do not go over the wire.

**Actual**
`GET` in `src/app/api/events/route.ts` calls `prisma.event.findMany` with an
`include` and **no top-level `select`**, so every scalar column on `Event` is
serialised for every event the caller holds a role on. That is the exact shape
[[GTC-267]] removed from the single-event route — `EVENT_WIRE_SELECT` was
introduced for it — and the list route was not part of that ticket's scope.

**Smallest failing case**
Call `GET /api/events` with any valid session and read `sharedLinkToken`,
`stripePaymentIntentId`, `paidAt`, `amountPaid` and the check-plan telemetry
out of the response for every event the user hosts.

---

## Evidence

`GET` in `src/app/api/events/route.ts`, verbatim shape at `9272222`:

```
const events = await prisma.event.findMany({
  where: { eventRoles: { some: { userId: user.id } } },
  include: {
    _count: { select: { teams: true, days: true } },
    eventRoles: { where: { userId: user.id }, select: { role: true } },
    setup: { select: { id: true } },
  },
  orderBy: { createdAt: 'desc' },
});
```

`include` without a sibling `select` means "all scalars, plus these
relations". The columns [[GTC-267]] named as forbidden are all scalars on
`Event`, so all of them are present.

**`sharedLinkToken` is the one that matters.** It is a declared credential
column in the route scanner's own list — `CREDENTIAL_COLUMNS` in
`tests/security-route-scan.ts` carries `{ model: 'event', field:
'sharedLinkToken' }` — and `POST /api/join/[token]/claim` authenticates on it.
So this route hands a join credential to anyone with a role on the event,
including a `COORDINATOR`, for every event in the list.

**What contains it, and it is a real containment, not an accident.** The route
calls `getUser` and filters on `eventRoles.some.userId`, so a caller sees only
events they already hold a role on. This is not the anonymous class
[[GTC-267]] closed. It is a response wider than the contract, reachable by a
legitimately authenticated caller.

## Scope

**Fix here:**
- `GET` in `src/app/api/events/route.ts` — a top-level `select`. **Reuse
  `EVENT_WIRE_SELECT`** rather than writing a second list; [[GTC-267]] created
  it for exactly this shape and two divergent narrowings would be worse than
  one wide one. It currently lives in `src/app/api/events/[id]/route.ts` and
  would need exporting, or moving to a shared module.
- Every caller of `GET /api/events` — `src/app/plan/events/page.tsx` is the
  one known consumer and must be checked against the narrowed shape before the
  narrowing lands, not after.
- `tests/security-validation.ts` — new assertions, adding and never weakening.
  Assert on a fixture where the forbidden columns are **populated**, so an
  absence is a drop and not a gap. That is [[GTC-267]]'s standard and it
  caught a real gap there.

**Do not touch:**
All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md` are binding. Zone 3
(AccessToken & scope system) is adjacent: this changes **what is serialised**,
never what a token is or how it is minted.
