# GTC-170 — B1: Wire criticality into the live finalize-plan AI path

**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** high

*Effort level is a proposal from the discovery-report ticket breakdown (`docs/04_roadmap/moment4-hinge-discovery-report.md`) — run `/effort` manually before execution.*

### Context

Moment 4 spec §5/§8.2: criticality is decided at the menu, in Moment 2 (the lamb roast, the
birthday cake: critical; two bags of ice: not); the grid shows it as a badge, explicitly "no
float-to-top, no message-only."

Schema fully supports it: `Item.critical`, `criticalReason`, `criticalSource`
(`AI | HOST | RULE`), `criticalOverride` (`NONE | ADDED | REMOVED`). The legacy AI prompt path
(`buildGenerationPrompt`, `PLAN_GENERATION_SYSTEM_PROMPT`) sets it correctly, with the "3-5 items
max, never-critical list" rules documented in `gather-domain-reference`. But the **live** path
(`buildPlanGenerationPrompt` / `finalize-plan/route.ts`, GTC-145/146's single-call architecture)
has no `critical` field in its output schema at all — every AI-generated item defaults
`critical: false`.

Separately, `src/app/c/[token]/page.tsx` (coordinator view) sorts unassigned critical items to
the top of the list — directly contradicting §8.2's explicit ruling, even though the badge
rendering itself is correct in the god file and `h/[token]`.

### Scope

**Fix here:**
- Add `critical`/`criticalReason` to `buildPlanGenerationPrompt`'s output JSON schema and to
  `finalize-plan/route.ts`'s item-creation write.
- Port the "only 3-5 items per plan may be critical, maximum" + never-critical list rules
  (sauces, condiments, bread, drinks, setup, cleanup, side dishes, extra desserts) from the V1
  system prompt into the V2 prompt — check both paths stay consistent per `gather-ai-generation`.
- Remove the float-to-top sort in `src/app/c/[token]/page.tsx`; replace with the badge-only
  rendering pattern already correct in the god file / `h/[token]`.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`.
- The V1 prompt path itself (`generate`/`regenerate` routes) — separate concern, not in scope.
- `AI_CALL_LIMIT` values.

### Dependencies

None. Sequenced before J1/J2 (the Moment 4 screen renders this data).

### Acceptance

- [ ] `finalize-plan` output includes `critical`/`criticalReason` for AI-generated items,
      following the same 3-5-max + never-critical-list discipline as the V1 prompt.
- [ ] `c/[token]/page.tsx` no longer sorts critical items to the top; badge rendering matches the
      god file / `h/[token]` pattern.
- [ ] `npx tsc --noEmit` clean, build passes.
- [ ] Browser walk: generate a plan via Moment 2, confirm critical items are flagged and the
      coordinator view shows a badge without reordering.
