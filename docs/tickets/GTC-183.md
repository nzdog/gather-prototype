# GTC-183 — F1: Material-change re-ask (date/venue) + wrong-date-send recovery

**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** high

### Context

Moment 4 spec §8.5: opt-out reconfirmation. When Kate changes the date or venue, the system
re-asks everyone (*the date's moved to the 27th — still good for the pavlova?*), and **claims hold
unless people object** — silence means still-in; "can't anymore" releases them through the normal
machinery. Nobody's yes is deleted; the grid never flushes to yellow; a sorted event doesn't
un-sort because the venue moved. The system decides when a change is material enough to trigger
the re-ask (derived-with-override), and Kate can set the weight per change — downgrade to
just-tell-them, or upgrade to a hard re-confirm. The ledger rule (why + version, per Hinge §2)
sits underneath all of it.

Hinge spec §2 (ruled gap #1) makes this ticket also the answer to "how does a wrong-date send get
fixed": there is no unsend, even at the mechanism level. **A wrong-date send is recovered entirely
through this machinery** — the moment Kate fixes the date, everyone is re-asked against the
correction. The mistake becomes a correction everyone sees, not an event that pretends it didn't
happen.

### Scope

**Fix here:**
- Date/venue change detection on the event.
- Materiality-weighting logic (derived-with-override) — Kate can downgrade to just-tell-them or
  upgrade to a hard re-confirm per change.
- The re-ask message send, reusing D1's (GTC-174) response model — claims hold unless objected.
- Confirm this same machinery is what a host reaches for when correcting a wrong-date send (no
  separate "undo" code path should exist or be built).

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`, especially SMS opt-out (Zone 7).
- The ledger mechanism itself (A2's territory, GTC-168) — this ticket consumes it via the
  mandatory why-capture, doesn't rebuild it.
- The send/press machinery itself (I2's territory, GTC-189) — this reuses message dispatch,
  doesn't rebuild it.
