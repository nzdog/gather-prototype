# GTC-137 — Dietary as pure input — CLOSED

**Status:** Code complete; pending baseline (Phase 2a) + verify (Phase 5) browser walks + commit approval | **Branch:** feat/moment-one-redesign | **Commit:** [pending]

### Phase 1: Architecture audit findings (in summary)

- The `dietary` branch in `buildSectionPrompt` (`prompts.ts:730`) was the source of duplication: it asked the AI to *generate complete food items* keyed off the requirements list — a parallel-alternatives pattern.
- Food prompts already received `dietaryRequirements` as a context line, but with no integration instruction; the constraint was whisper-quiet.
- `buildDietaryCoveragePrompt` was already gap-shaped — the contract was right; the prompt wording needed tightening to recognise naturally-suitable items.
- `dietaryData` shape (`{requirements, other}`) is already pure inputs in all three places it's typed (`Moment2Step1Modal`, `setup` route, `finalize-plan` route). No items have ever been stored in it. Legacy generated dietary items live in `EventSetup.generatedData['dietary']` and as a `Team` row named "Dietary" — handled by deprecate-by-disuse + one-shot cleanup at finalize.
- Free-text "Other dietary needs" was not threaded into food prompts (only into the doomed dietary-section prompt). Real bug; fixed.
- `Moment2PlanView` does not consume `dietaryCoverage` — finalize-plan returns it but no UI surfaces it. Display wiring filed as follow-up.

### What was changed

**Phase 2 — Dietary input-only (gated on both client and server)**
- `Moment2Step1Modal.tsx`: `generateSection` short-circuits when `sectionId === 'dietary'`. Closing the dietary accordion no longer fires `POST /api/events/[id]/generate-section`.
- `generate-section/route.ts`: explicit 400 when `body.section === 'dietary'` — defensive against any other caller.
- `finalize-plan/route.ts`: `'dietary'` removed from `FOOD_SECTIONS`; gap-fill loop will not touch it.
- `finalize-plan/route.ts`: any pre-existing `generatedData.dietary` array is dropped before category assembly (deprecate-by-disuse for legacy events).
- `finalize-plan/route.ts`: `prisma.team.deleteMany({ where: { eventId, name: 'Dietary' } })` runs before the team-creation block — drops stale Dietary teams from prior runs (Item rows cascade-delete via FK).
- `prompts.ts`: dietary branch in `buildSectionPrompt` marked DEPRECATED with a comment; left in place for `Moment2Section` enum back-compat (per Q3).

**Phase 3 — Food prompts dietary-aware + free-text threaded**
- `prompts.ts` (`buildSectionPrompt`, food branch): dietary requirements now appear as a stronger generation constraint with the integration directive ("a roasted vegetable side that is already vegetarian … prefer integrated items over parallel alternatives"). Item shape extended to include optional `dietaryTags`.
- `prompts.ts` (`buildGapPrompt`): same integration directive added.
- `Moment2Step1Modal.tsx`: `dietaryRequirements` sent to generate-section now includes `Other: <free-text>` when the free-text field is populated. Combined-string approach — no signature change to prompt builders.
- `finalize-plan/route.ts`: same combined-string approach applied to the `dietaryRequirements` value passed into `buildGapPrompt` and `buildDietaryCoveragePrompt`.

**Phase 4 — Coverage check tightened**
- `buildDietaryCoveragePrompt`: added the "naturally suitable" instruction verbatim from your specification, plus "use common-sense culinary knowledge of typical preparation. Only mark a requirement as not covered when no naturally-suitable item exists across the whole plan." Output shape unchanged.
- `flaggedItems` semantic clarified in the prompt: covers-it-when-covered or conflicts/reason-when-not.
