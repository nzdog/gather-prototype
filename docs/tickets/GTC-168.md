### Context

Implements whatever GTC-167 (A1) decides for: `EventStatus.FROZEN`/`COMPLETE` disposition, the
unified ledger (`AuditEntry` vs `InviteEvent`), per-change versioning (`PlanRevision` auto-trigger
and the removal of its 5-item display cap in favor of "complete history always reachable" per
Hinge §2), the why-scope rule, and the mini-send data shape. **This ticket cannot be scoped in
detail until A1 lands** — treat the "Scope" section below as the known shape from the discovery
report; the executor must reconcile it against A1's actual decisions before writing any migration.

### Scope (subject to A1's decisions)

**Fix here (expected, pending A1):**
- Schema migration(s) implementing A1's chosen model for FROZEN/COMPLETE, the ledger, and
  versioning granularity.
- Reason-capture wiring on whichever mutation paths A1's why-scope rule names (reassignment,
  removal, claimed-quantity changes, date/venue changes at minimum, per Hinge §2).
- `PlanRevision` (or its replacement) auto-triggering on every in-scope mutation, uncapped
  history retrieval.
- Migration path for the FROZEN→CONFIRMING unfreeze route's removal (per A1 — do not build Epic
  F's material-change re-ask machinery here; only remove/redirect the dead path per A1's plan).

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md` — Stripe (zone 4) and SMS opt-out (zone 7)
  are not expected to be touched by this ticket; if scoping reveals otherwise, stop (Stop
  Condition 5) and flag for explicit approval rather than proceeding silently.
- The ~30 FROZEN consumer call sites themselves — that is GTC-169 (A3). This ticket changes the
  schema and the ledger/versioning mechanism underneath them; A3 migrates the call sites to use it.
- Epic B–K territory (criticality, task rows, dietary, recipient toggle, nudge cadence, etc.) —
  out of scope even where adjacent.

### Approach

Per GTC-167's accepted approach: this ticket runs on the experiment branch A1 names, following the
GTC-145/146 shape (`gather-experiment-methodology`) — schema changes of this magnitude get a
dedicated branch and a separate merge ticket, not a direct landing on `feat/moment-one-redesign`.

**Stop Condition 7 applies literally here — DB schema migration required.** Per
`gather-change-control`: surface the migration for sign-off, then `prisma migrate dev` only after
approval. Load `gather-data-model-and-migrations` before writing it.
