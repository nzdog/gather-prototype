# GTC-080 — Prisma v7 upgrade (deferred)

**Status:** Deferred — stub only
**Severity:** Medium (technical debt / deprecation track)
**Filed from:** GTC-079 Dependabot follow-up (2026-04-09)

---

## Why deferred

The immediate security need (two high-severity Dependabot alerts) was
resolved by the patch bump to `prisma@6.19.3`, which carries
`effect@3.21.0` and `defu@6.1.7` transitively. The v7 upgrade is a
separate piece of work because it touches runtime client
instantiation, configuration layout, and CI/build env loading — none
of which can be safely bundled into a security-patch commit.

Running `npm run build` against `prisma@6.19.3` also emits this
deprecation warning that foreshadows v7 work:

```
warn The configuration property `package.json#prisma` is deprecated and
will be removed in Prisma 7. Please migrate to a Prisma config file
(e.g., `prisma.config.ts`).
```

## Current state

- `prisma` / `@prisma/client`: **6.19.3**
- `prisma` v7 latest: **7.7.0**
- Schema: `provider = "prisma-client-js"`, `datasource db { url = env("DATABASE_URL") }`
- No `prisma.config.ts` exists.
- `PrismaClient` is instantiated with no arguments in two places:
  - `src/lib/prisma.ts:7`
  - `src/lib/ai/check.ts:15`
- `.env` auto-loading by the Prisma CLI is relied on in every
  `prisma`-invoking npm script.
- Pre-existing P3005 drift (documented in `GATHER-BUILD-CONSTANTS.md`)
  is still in the background and should be baselined before or during
  this upgrade.

## Breaking changes relevant to this codebase

Confirmed from the Prisma 7.0.0 release notes. Each item below is
something this repo will have to actively handle.

1. **`new PrismaClient()` with no arguments is no longer supported.**
   v7 requires either a driver adapter (e.g. `@prisma/adapter-pg`) or
   `accelerateUrl`. Both current instantiation sites will need to be
   rewritten. Decision required: pick an adapter (Postgres adapter is
   the likely default) or move to Accelerate.
   - `src/lib/prisma.ts:7`
   - `src/lib/ai/check.ts:15`

2. **`datasource.url` moves out of `schema.prisma`.** v7 requires
   `url` (and `shadowDatabaseUrl`) to live in a new `prisma.config.ts`
   file. `directUrl` is removed entirely. The current datasource
   block must be trimmed and a `prisma.config.ts` authored.

3. **`package.json#prisma` block is removed.** Already deprecated in
   6.19.3; v7 fully removes it. Any settings from that block need to
   move to `prisma.config.ts`.

4. **Generated client location must be explicit.** v7 does not emit
   to `node_modules` by default. Either:
   - Keep `provider = "prisma-client-js"` and install
     `@prisma/client-runtime-utils`, or
   - Switch to `provider = "prisma-client"` with an explicit `output`
     path (e.g. `../src/generated/prisma`) and update every import
     site accordingly.

5. **CLI no longer auto-loads `.env`.** Every Prisma-invoking script
   must be wrapped in a `dotenv` loader (e.g. `dotenv-cli`) or run
   through a context that provides env vars (`railway run`, CI
   secrets). Affected scripts in `package.json`:
   - `build`: `prisma generate && prisma migrate deploy && next build`
   - `db:migrate`: `prisma migrate dev`
   - `db:migrate:deploy`: `prisma migrate deploy`
   - `db:reset`: `prisma migrate reset`
   - `railway:setup`: `prisma migrate deploy && prisma db seed`

6. **Implicit command execution removed.** `prisma migrate dev` and
   `prisma migrate deploy` no longer auto-run `prisma generate` or
   `prisma db seed`. Scripts must chain explicitly. The `build`
   script already chains `prisma generate`, but `db:migrate:
   "prisma migrate dev"` will silently stop regenerating the client
   under v7 and needs `&& prisma generate` appended.

7. **Client engines removed.** `LibraryEngine`, `BinaryEngine`,
   `DataProxyEngine`, and `AccelerateEngine` are replaced by a new
   `RemoteExecutor` model. This is the root cause of (1) — there is
   no "default local engine" in v7; an adapter must be brought.

8. **Several `PRISMA_*` env vars removed.** Audit the Railway
   environment (and `.env.example`) for any of these before upgrading:
   `PRISMA_CLI_QUERY_ENGINE_TYPE`, `PRISMA_CLIENT_ENGINE_TYPE`,
   `PRISMA_QUERY_ENGINE_BINARY`, `PRISMA_QUERY_ENGINE_LIBRARY`,
   `PRISMA_GENERATE_SKIP_AUTOINSTALL`, `PRISMA_SKIP_POSTINSTALL_GENERATE`,
   `PRISMA_GENERATE_IN_POSTINSTALL`, `PRISMA_GENERATE_DATAPROXY`,
   `PRISMA_GENERATE_NO_ENGINE`, `PRISMA_CLIENT_NO_RETRY`,
   `PRISMA_MIGRATE_SKIP_GENERATE`, `PRISMA_MIGRATE_SKIP_SEED`.

9. **URL validation logic removed.** v7 release notes: "users
   responsible for security." Worth reviewing how `DATABASE_URL` is
   constructed/validated.

## Not a concern for this repo

- **MongoDB** — v7 drops MongoDB support; this repo is Postgres-only.
- **React Native generator** — unused here.
- **`prisma introspect` command** — not used in any script.

## Suggested execution order (when picked up)

1. Create `prisma.config.ts`, move `url` and any `package.json#prisma`
   settings into it.
2. Decide on adapter vs Accelerate; install the chosen package.
3. Rewrite both `new PrismaClient()` sites to pass the adapter.
4. Update `schema.prisma` generator block (output path or
   `@prisma/client-runtime-utils`).
5. Add `dotenv-cli` (or equivalent) to every Prisma-invoking script.
6. Append `&& prisma generate` to `db:migrate`.
7. Audit Railway env vars against the removed list.
8. Baseline the existing schema to clear the P3005 drift **before**
   running v7 migrations.
9. `npm install prisma@7 @prisma/client@7`.
10. Run the security suite, a full build, and a dev smoke test
    (participant view, host view, plan generation, SMS send) before
    merging.
