# GTC-146 — Single-call architecture brought to feat/moment-one-redesign

**Status:** Cleanup commit landed (verification pending) | **Branch:** feat/moment-one-redesign

This ticket merges the experimental single-call AI generation pattern from
`experiment/single-ai-call` (GTC-145, commit `a27f781`) onto
`feat/moment-one-redesign` as the canonical Moment 2 generation pattern, and
removes the deprecated per-section infrastructure that the experiment had
left in place (deprecated-by-comment) for back-compat.

## Phase 1 — Cherry-pick result

Cherry-picked `a27f781` cleanly onto `feat/moment-one-redesign` (no
conflicts; the experiment branch had been exactly one commit ahead of
`feat/moment-one-redesign`, so the cherry-pick was effectively a fast-forward
in content). 6 files changed, 538 insertions, 502 deletions. The commit
message was amended to remove the `[EXPERIMENTAL]` tag and to reference
GTC-146 as the merge ticket; `[EXPERIMENTAL]`-era language about a future
"merge ticket" was dropped from the body.

The cherry-pick brought `docs/tickets/GTC-145.md` along as a new file. It
sits alongside this doc as the experiment's historical closed summary.

## Phase 2 — Cleanup commit

Removed dead code that the experiment had left deprecated-by-comment:

**`src/lib/ai/prompts.ts`:**
- `buildSectionPrompt` (per-section food generation, including its DEPRECATED
  dietary branch from GTC-137)
- `buildGapPrompt` (per-section gap-fill)
- `buildDietaryCoveragePrompt` (replaced by single-call's bundled
  `dietaryCoverage` field in the JSON response)
- `buildThingsToConsiderPrompt` (replaced by single-call's bundled
  `thingsToConsider` field)
- Dead support code: local `flattenSelections` helper, `MOMENT2_SECTION_LABELS`
  table, `SECTION_KEY_TO_FAMILY` table
- Dead types: `Moment2Section`, `VALID_MOMENT2_SECTIONS`, `Moment2GeneratedItem`,
  `Moment2HouseholdData`, `Moment2SectionHouseholdData`, `Moment2SectionInput`
- Removed unused `getSectionReferenceItems` import (still imported separately
  by `finalize-plan/route.ts`)

Kept in `prompts.ts`: `buildPlanGenerationPrompt`, its input types
(`PlanGenerationCategoryInput`, `PlanGenerationInput`), the shared
`OptionTreeLevelSelection` and `OptionTreeSelections` types (used by
finalize-plan), and the entire legacy v1 surface
(`PLAN_GENERATION_SYSTEM_PROMPT`, `PLAN_REGENERATION_SYSTEM_PROMPT`,
`EXPLANATION_SYSTEM_PROMPT`, `SELECTIVE_REGENERATION_SYSTEM_PROMPT`,
`buildGenerationPrompt`, `buildRegenerationPrompt`, `buildExplanationPrompt`,
`buildSelectiveRegenerationPrompt`) which is still imported by `generate.ts`.

**`src/lib/ai/token-limits.ts`:**
- Removed `MAX_TOKENS_SECTION_GENERATION`, `MAX_TOKENS_GAP_FILL`,
  `MAX_TOKENS_DIETARY_COVERAGE`, `MAX_TOKENS_CONSIDERATIONS`
- Tightened the file-level docstring to reflect that `MAX_TOKENS_FULL_PLAN`
  is now the only Moment 2 cap

**`src/app/api/events/[id]/generate-section/route.ts`:** entire file deleted
(the 410-Gone stub from the experiment is no longer useful — the route
shouldn't exist at all). Empty parent directory removed.

## Phase 2d — Audit: regenerate routes

`src/app/api/events/[id]/regenerate/route.ts` and
`src/app/api/events/[id]/regenerate/preview/route.ts` were audited. Both
routes call `regeneratePlan` from `@/lib/ai/generate` (the legacy v1 path).
Neither imports `buildSectionPrompt`, `buildGapPrompt`, or any of the
deleted symbols. They use `buildRegenerationPrompt` +
`PLAN_REGENERATION_SYSTEM_PROMPT` via the legacy v1 path — none of which
were touched by this ticket. **No changes required.**

Side note (out of scope): both routes use `console.error` for error logging;
if a future hygiene ticket sweeps `console.*` usage, those are candidates.

## Modal / AccordionShell — no-op

The cherry-pick already removed all per-section state machinery from
`Moment2Step1Modal.tsx`. There is no separate `AccordionShell.tsx` shared
component file — the modal has its own local `AccordionShell` function
(line 727), which has no `generationStatus` prop. The ticket's worklist for
both files is a no-op.

## Schema decision

`EventSetup.generatedData Json?` is no longer written by the single-call
finalize-plan route. The column is left in place (deprecate-by-disuse,
matching the pattern used for `setupCleanupData`/`sidesData`/etc.). A
migration to drop the column is a separate hygiene ticket.
