# GTC-413 - qs 6.16.0 to 6.16.1 in the lockfile, so the deploy check passes

> Filed by Claude Code on 28 Oct 2026, from the founder's prompt (the FULL
> PROCESS, two small tickets on one branch, one final gate). Branch
> feat/final-fixes, after GTC-412. Status: built, not pushed.

## What was wrong

The deploy-day check (node scripts/check-deploy-audit.mjs, GTC-359 and
GTC-397) failed on 28 Oct 2026 with one new line:

```
twilio <- qs: GHSA-6pq8-jhm2-2vcw moderate
```

qs is a small library that turns an object into the text of a web
address or a form ("a=1&b=2"). Gather never calls it. Stripe 20.2.0 and
Twilio 5.12.0 both bring it in (both ask for ^6.14.1), and the lockfile
held one copy, 6.16.0.

## The advisory, in plain English

GHSA-6pq8-jhm2-2vcw (moderate): in qs up to 6.16.0, if you ask qs to
join a list with commas (the option arrayFormat: 'comma') and one item
in the list is an object with no working toString (for example one made
with Object.create(null)), qs throws an error instead of writing text.
If nothing catches that error, the program stops: a crash, not a leak.
The fix is qs 6.16.1 (14 Oct 2026).

Why Gather's use is not reached:

- Gather's own code (src, scripts) never imports qs.
- Only two installed packages load qs: Stripe (node_modules/stripe
  cjs/utils.js and esm/utils.js) and Twilio (lib/base/RequestClient.js).
- Stripe calls it with arrayFormat 'indices', Twilio with arrayFormat
  'repeat'. Neither ever asks for 'comma', so the faulty path is not
  run. Both turn request data that Gather builds into text; neither
  reads text that someone else sent.

So the move is to clear the deploy check, not to close a live hole.

## The founder's rulings (28 Oct 2026, in Cowork)

1. (GTC-412's ruling, recorded in GTC-412.)
2. Option 1 of the scoping run: a lockfile-only move of qs to exactly
   6.16.1 (not 6.16.2, not 6.17.0, which npm update would pick). No
   overrides entry. No allow-list in the deploy check. No change to
   package.json's dependencies, to Stripe or Twilio themselves, or to
   anything under src/lib/stripe*, src/app/api/billing or the webhook.
3. npm ci (never npm install) may be run inside this repo after the
   lockfile commit, so the gate tests the new qs.
4. One final full gate at the end, for both tickets.
