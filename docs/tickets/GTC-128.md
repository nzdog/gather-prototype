# GTC-128 — Fix build regression: extract prompt builders from route files + ESLint circular config — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** [pending]

### What was found

Two distinct build errors:

1. **Disallowed Next.js route exports (introduced by GTC-127, commit 9ba5eaa).**
   `src/app/api/events/[id]/finalize-plan/route.ts` exported three helpers:
   `buildGapPrompt`, `buildDietaryCoveragePrompt`, `buildThingsToConsiderPrompt`.
   `src/app/api/events/[id]/generate-section/route.ts` exported `buildSectionPrompt`.
   Next.js App Router only allows a fixed allowlist of exports from `route.ts`
   files (`POST`, `GET`, `runtime`, `dynamic`, `maxDuration`, etc.). The four
   prompt builders broke the typed-route check and aborted the build:
   > `"buildGapPrompt" is not a valid Route export field.`

2. **Pre-existing ESLint circular structure error (NOT GTC-127-related).**
   `next lint` walks the plugin/config graph and serialises it to JSON,
   which crashes with `Converting circular structure to JSON … property
   'react' closes the circle`. Root cause: `eslint-config-next` is pinned to
   `^16.2.2` while `next` is on `^15.5.12`. The version mismatch is a
   long-standing dependency drift — `.eslintrc.json` was last touched in
   commit `f9448ca` ("Add linting, formatting, and GitHub Actions CI"),
   well before GTC-127. The error is logged with `⨯` but is non-fatal:
   `next build` and `next lint` both exit 0.

### What was changed

**Phase 1 — Prompt builders extracted** (this ticket's primary fix):

- Added four functions to `src/lib/ai/prompts.ts` (the existing AI prompts
  module — no new file needed): `buildSectionPrompt`, `buildGapPrompt`,
  `buildDietaryCoveragePrompt`, `buildThingsToConsiderPrompt`. Function
  bodies are byte-for-byte identical to the originals; only the
  enclosing module changed.
- Added supporting types alongside (`Moment2Section`, `Moment2GeneratedItem`,
  `Moment2HouseholdData`, `Moment2SectionHouseholdData`, `Moment2SectionInput`)
  and imported `getNzNotes`/`getSectionReferenceItems` at the top of the
  prompts module.
- Removed the four function definitions from the two route files. Both
  routes now `import { ... } from '@/lib/ai/prompts'` and call the
  functions exactly as before. Local types (`HouseholdData`, `SectionInput`,
  `RequestBody`, `Section`, `GeneratedItem`) inside each route file are
  retained — they are still used by the route handler bodies.
- Updated `tests/measure-moment2-prompts.ts` to import all four builders
  from `../src/lib/ai/prompts` (removing the two route-file imports).

**Phase 2 — ESLint circular config (DEFERRED to follow-up).**

- Investigated and identified the root cause as `eslint-config-next@^16.2.2`
  paired with `next@^15.5.12`. The proper fix is a dependency change
  (downgrade `eslint-config-next` to `^15.x` or upgrade Next to 16). Per
  the ticket's instruction to flag dependency changes for confirmation,
  this is left for a separate ticket. The error is non-fatal; the build
  is unblocked by Phase 1 alone.

### Known limitations

- ESLint circular-structure warning persists during `next build` and
  `next lint`. Both commands exit 0; the warning is logged but does not
  fail the build. Recommended follow-up ticket: align
  `eslint-config-next` with the installed Next.js major version (or
  migrate to the new ESLint CLI per the deprecation notice from
  `next lint`).
- Found one additional `export type InviteStatus` in
  `src/app/api/events/[id]/invite-status/route.ts`. This is a type-only
  export that TypeScript erases at compile time, so it does not trigger
  Next.js's runtime route-export validation. Build passes; left in place.
- Browser end-to-end verification of the regenerate-plan flow on the
  Kate test event was not performed in this session. The fix is a
  pure code-organisation change with byte-identical function bodies and
  unchanged call sites, so behaviour is provably inert; this was
  validated structurally (tsc + measurement script + build) rather than
  in a browser.
