# GTC-140 — Quantity unit confusion in generated items — CLOSED

**Status:** CLOSED (resolved by architecture change, no code required in this ticket)
**Resolved by:** GTC-146 (single-call AI generation architecture)

### Original hazard

Surfaced during GTC-133 sub-commit (g) browser verification (one of the six follow-ups filed as GTC-136 through GTC-141). Under per-section generation, items came back with wildly wrong or mismatched units — quantities that made no physical sense for the item (weights where counts belong, implausible magnitudes) — because each fragmented per-section call produced its own quantity conventions with no shared frame.

### Resolving change

GTC-146's single-call architecture generates all quantities in one response under one set of rules. The system prompt (`buildPlanGenerationPrompt`, `src/lib/ai/prompts.ts`) specifies realistic portion math — sensible per-person figures (proteins ~150–200g/adult, sides ~150g/adult, desserts ~1 portion/person), kids counted at smaller quantities — and constrains output to real-world units ("kg, g, L, ml, count, packs, trays, bottles, bowls"), with a single JSON schema carrying `quantity`/`unit`/`servingSize` per item.

Fresh V2 event, Christmas + Vegetarian + Gluten-free, engaged Mains + Sides + Dessert + Cake + Drinks + Snacks + Breakfast & Brunch. Generated plan: 40 items across 8 categories.

- All quantities scanned: no wildly wrong units.
- kg/g/L/count all sensible for their items. **RESOLVED.**
