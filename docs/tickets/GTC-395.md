## The rollback structure

- Built on a NEW branch, `feat/demo-tweaks-2`, made from `e4add64` (the
  tip of `feat/demo-tweaks`, GTC-394 with its backfill).
- A local tag, `demo-tweaks-good`, names `e4add64`: the last version the
  founder looked at. Not pushed.
- `feat/demo-sandbox` and `feat/demo-tweaks` are never committed to,
  merged into, moved or force-pushed. No `git fetch --prune`; main,
  legacy-master, the tag `demo-ab-good` and the remote-tracking names are
  not touched.
- One commit for this ticket first, then one commit per item in the
  order below, each made when that item's own checks are green. Staged
  by name, never the two untracked scripts (`scripts/dev-login.ts`,
  `scripts/print-host-link.ts`). A last commit updates this ticket. No
  push, no tag push, no merge, no pull request: the founder pushes
  himself.
- So the founder can roll back the lot (reset to `demo-tweaks-good`, or
  `git switch feat/demo-tweaks`) or any one item (`git revert <hash>`).
  The report lists, for every commit, the files it touched and which
  later commits touch the same files.
