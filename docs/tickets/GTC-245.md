## Context

Seven packages from `npm audit` on `feat/moment-one-redesign`, none directly declared in
`package.json` — all pulled in transitively by three vendor SDKs:

| Package | Prod/Dev | Parent chain | Sev | Vuln class |
|---|---|---|---|---|
| `axios` (1.15.0) | prod, transitive ← `twilio` | — | High | Prototype pollution (`validateStatus`, `parseReviver`), SSRF/NO_PROXY bypass |
| `follow-redirects` (1.15.11) | prod, transitive ← `twilio` → `axios` | — | Moderate | Info disclosure — auth header leak on cross-domain redirect |
| `form-data` (4.0.5) | prod, transitive ← `twilio` → `axios` | — | High | CRLF injection via unescaped multipart field/filenames |
| `qs` (6.15.0) | prod, transitive ← **both** `stripe` and `twilio` | — | Moderate | DoS — crash on malformed comma-format array input |
| `resend` (6.7.0) | prod, **direct** | — | Moderate | Inherits svix→uuid buffer-bounds issue |
| `svix` (1.84.1) | prod, transitive ← `resend` | — | Moderate | Inherits uuid buffer-bounds issue |
| `uuid` (10.0.0) | prod, transitive ← `resend` → `svix` | — | Moderate | Missing buffer bounds check (v3/v5/v6 with `buf` provided) |

**Note `qs` has two independent parents** (`stripe` and `twilio`) — a single lockfile
re-resolution of `qs` affects both vendor chains at once; do not split it across two separate
fixes.

**Path relevance, per the audit's flagging criteria:**
- `axios` / `follow-redirects` / `form-data` / `qs` (twilio branch) sit in the **SMS/TNZ path**
  in the dependency graph — `twilio` is the fallback SMS provider for non-NZ/AU destinations
  (TNZ handles NZ/AU per `GATHER-BUILD-CONSTANTS.md`). None of these packages are imported
  directly by this app's own SMS code (`src/lib/sms/`); they're internal to the `twilio` SDK.
- `qs` (stripe branch) sits in the **payment path** — internal to the `stripe` SDK, not directly
  imported by `src/lib/stripe*`.
- `resend` / `svix` / `uuid` sit in the **magic-link delivery path** — `resend` is the
  transactional-email vendor used to send magic links (`RESEND_API_KEY` in
  `GATHER-BUILD-CONSTANTS.md`). This is the email *delivery* mechanism, not the auth logic
  itself — none of these three touch `src/lib/auth*`, `middleware.ts`, or the
  `AccessToken`/session-cookie system (Do-Not-Touch Zones 1–3). Flagged here because it's in the
  magic-link path per the audit's criteria, not because it risks the token/session invariants.

All seven have non-major fixes available per `npm audit`'s `fixAvailable` field — none require
a major-version bump. The open question is not "can this be fixed cleanly" but "does bumping a
transitive dependency underneath `twilio`/`stripe`/`resend` risk behavior those SDKs depend on
being pinned" — hence deciding this as one reviewed ticket rather than an automatic bundle,
per the audit's flagging criteria for the SMS/payment/auth path.

## Scope

**No fix attempted in this ticket.** Decision needed on whether to bump these seven packages
(single `package-lock.json` re-resolution, no `package.json` change expected) after confirming
the SDKs they sit under (`twilio`, `stripe`, `resend`) don't pin narrower ranges than currently
resolved, and after a smoke test of at least one live send/charge/link-issue path per vendor in
a safe/test mode.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md` are binding — in particular Zone 4
  (Stripe integration) and Zone 7 (SMS opt-out logic). This ticket's packages sit underneath
  those systems, not inside them, but any verification work must not touch webhook signature
  verification, billing-status transitions, or opt-out enforcement code.
- `src/lib/auth*`, `middleware.ts`, `AccessToken`/session-cookie logic (Zones 1–3) — not
  implicated by `resend`/`svix`/`uuid`, but called out explicitly given the "auth path" framing.
