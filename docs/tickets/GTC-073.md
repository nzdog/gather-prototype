# GTC-073 — Item confirmation status visible to host — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** 9de1691

### What was found
The confirmation status data was already available. The `Assignment` model in Prisma has a `response` field with enum values `PENDING`, `ACCEPTED`, and `DECLINED`. The host items API (`/api/h/[token]/team/[teamId]`) already returns `assignment.response` for each item. The `Item` interface in the plan page already typed this field. No schema or API changes were required — this was purely a display issue.

The existing `ItemStatusBadges` component only distinguished "Confirmed" (green) vs "Not confirmed" (yellow), collapsing PENDING and DECLINED into a single state. The Items & Quantities table had no Status column at all.

### What was changed

**`src/app/plan/[eventId]/page.tsx`**
- Added a "Status" column to the Items & Quantities table header
- Added a Status cell to each item row showing:
  - **Confirmed** (green badge) — `assignment.response === 'ACCEPTED'`
  - **Declined** (red badge) — `assignment.response === 'DECLINED'`
  - **Pending** (amber badge) — `assignment.response === 'PENDING'`
  - **Unassigned** (gray italic) — `assignment === null`
- Each badge also shows the assigned person's name for context
- Fixed the print/PDF view to distinguish Declined (red) from Pending (amber) — previously both rendered as "Pending"

**`src/components/plan/ItemStatusBadges.tsx`**
- Updated the confirmation badge to show three distinct states instead of two:
  - Confirmed → green
  - Declined → red
  - Pending → amber
  - Unassigned → gray

### Known limitations / follow-up flags
- None. The data flow is complete: guest confirms/declines via `/api/p/[token]/ack/[assignmentId]`, the host view auto-refreshes every 5 seconds and picks up the updated `assignment.response` value.
