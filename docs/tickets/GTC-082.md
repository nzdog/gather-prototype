# [[GTC-082]] — VCF Contact Import — CLOSED

**Status:** Complete | **Branch:** chore/prisma-6.19.3 | **Commit:** _pending_

### What was found

Gather's People modal only accepted `.csv` imports. The import wizard
(`src/components/plan/ImportCSVModal.tsx`) is a three-step flow: upload →
column mapping → review & select → import. Step 3 and the import pipeline
are format-agnostic — they operate on a `{ name, email, phone }` row shape.
Step 2 (column mapping) only exists because CSV column names are unpredictable.
VCF files have a fixed, self-describing schema, so mapping is not needed.

### What was changed

**New parser module: `src/lib/vcard.ts`**
- Wraps the `vcard-parser` npm package (version `1.0.0`, zero runtime deps).
- Splits multi-contact `.vcf` files on `BEGIN:VCARD` / `END:VCARD` blocks
  before parsing each card individually — `vcard-parser`'s `parse()` is
  single-card and would otherwise merge fields across all cards.
- Decodes `ENCODING=QUOTED-PRINTABLE` values (with configurable `CHARSET`,
  default UTF-8) using a manual hex decoder + `TextDecoder`. Required for
  vCard 3.0 exports from older Outlook/Android that encode non-ASCII names
  (common with NZ Māori macron characters like Māui, Tūhoe).
- Extracts name from `FN` (preferred), falling back to assembling `N`
  (family;given;…) as "Given Family".
- Selects a single email and phone per contact using PREF preference:
  - vCard 3.0: `TYPE=HOME,PREF` — detected by splitting comma-joined TYPE
    values and matching `PREF`.
  - vCard 4.0: `PREF=` parameter — detected via `meta.pref`.
  - No PREF → first-listed wins.
- Normalises phone numbers: leading `0` → `+64` (NZ), preserves other prefixes
  as-is. Matches the existing CSV import's behaviour and delegates to the
  downstream `normalizePhoneNumber` path for final validation.
- Skips any vCard with no name, or with neither email nor phone, and surfaces
  the skip count via `VCFParseResult.skippedCount`.

**Modal extension: `src/components/plan/ImportCSVModal.tsx`**
- Added a `sourceFormat: 'csv' | 'vcf'` state and a `vcfSkippedCount` state.
- `handleFileChange` now detects `.vcf` / `text/vcard` / `text/x-vcard`
  alongside `.csv` and branches to a new `parseVcfFile()` handler.
- `parseVcfFile()` calls `parseVCF()`, runs the same phone/email normalisation
  and duplicate-detection logic as the CSV path, then jumps directly to
  step 3 (Review & Select). The column-mapping step is bypassed for VCF.
- The file input's `accept` attribute now permits `.csv,.vcf` plus the
  corresponding MIME types.
- Upload step copy updated to describe both formats.
- Modal header renumbers to "Step N of 2" when VCF is in use.
- Step 3 header shows a banner like "47 contacts found — select to add.
  3 skipped — no email or phone found." when VCF is the source.
- The "Back" button from step 3 returns to step 1 (not the non-existent
  mapping step) when `sourceFormat === 'vcf'`.
- The existing 5MB `MAX_FILE_SIZE` guard applies to both CSV and VCF
  uploads — the check runs before format branching.

**Test: `tests/vcf-import-test.ts`**
- 29 assertions across 7 sections. Runs via `npm run test:vcf-import`.
- Uses inline VCF fixtures (no file I/O) — pure-function tests of
  `parseVCF()`. No DB, no React.

**Existing CSV pipeline: untouched**
- `parseCSV()`, the mapping step, and the `handleProceedToReview` flow are
  unchanged. Per ticket scope, CSV was extended, not refactored.

### Known limitations

- `vcard-parser` does not handle hard-wrapped quoted-printable (soft line
  break `=` with no leading whitespace on the next line). Modern exports
  from iPhone, Android, and Gmail use either plain UTF-8 or the
  space-indented fold, both of which work. Outlook legacy exports were
  verified manually by fixture.
- Only the first `EMAIL` and first `TEL` per contact are imported (PREF
  or first-listed). Multi-row-per-contact expansion was explicitly out
  of scope per ticket.
- International phone numbers trigger the existing CSV-import warning
  ("International number (will be skipped)") and are dropped rather than
  imported as-is. This is consistent with the existing CSV behaviour the
  ticket said to reuse; the ticket note "store as-is" is overridden by
  "apply the same phone normalisation logic already used elsewhere".
- `vcard-parser@1.0.0` last published June 2022. It has zero runtime deps
  and its implementation has been exercised by the test fixtures against
  vCard 3.0, vCard 4.0, line folding, quoted-printable, and multi-value
  fields. The healthier alternative considered (`vcf@2.1.2`) was rejected
  because it transitively pulls in `axios <1.15.0` which has a critical
  SSRF CVE (GHSA-3p68-rc4w-qgx5).
