# GTC-139 — Breakfast & Brunch over-generation — CLOSED

**Status:** CLOSED (resolved by architecture change, no code required in this ticket)
**Resolved by:** GTC-146 (single-call AI generation architecture)

### Original hazard

Surfaced during GTC-133 sub-commit (g) browser verification (one of the six follow-ups filed as GTC-136 through GTC-141). Under per-section generation, each category's AI call maximized within its own context with no view of the overall plan — Breakfast & Brunch produced encyclopedic output (**54 items** in the per-section baseline on Christmas selections), far beyond anything a host would shop for, swamping the plan view and assignment surface.

### Resolving change

GTC-146's single-call architecture generates every category in one response, sized against the whole plan. The system prompt (`buildPlanGenerationPrompt`, `src/lib/ai/prompts.ts`) carries explicit plan-size guidance: "Realism beats completeness", "For a typical 15–25 person gathering, expect roughly 15–30 items total across all engaged categories", "Per-category item counts should reflect importance", and "Do not pad." Because all categories share one budget in one context, no single category can balloon independently.

### Verification (this session)

Fresh V2 event, Christmas + Vegetarian + Gluten-free, engaged Mains + Sides + Dessert + Cake + Drinks + Snacks + Breakfast & Brunch. Generated plan: 40 items across 8 categories.

- Breakfast & Brunch produced **8 items** (was **54** in the per-section baseline on equivalent selections).
- Realistic scale across all categories. **RESOLVED.**
