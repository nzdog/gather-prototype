### Scope

Releasing a guest from an item makes them eligible for the **wrong** message.

`findNudgeCandidates` computes `hasResponded` from *remaining* assignments —
`nudge-eligibility.ts:177-179`:

```ts
const hasResponded = person.assignments.some(
  (a: any) => a.item.team.eventId === event.id && a.response !== 'PENDING'
);
```

Deleting an assignment therefore flips `hasResponded` back to `false`. The 48h gate
(`nudge-eligibility.ts:207-213`) is `anchorAt <= 48h ago && !hasResponded && !nudge48hSentAt`.

**The exposed population is exactly D3's target audience.** `nudge48hSentAt` is stamped only on
a successful send (`nudge-sender.ts:74-82` — the update sits inside `if (result.success)`), so
anyone still unstamped past 48h must have had `hasResponded` true throughout. That means the
people this can fire on are precisely those who **accepted, then were released**. They receive
`get48hNudgeMessage` (`nudge-templates.ts:39-43`):

> `Reminder: ${hostName} needs your response for ${eventName}. Please confirm: ${link} — Reply STOP to opt out`

— the exact opposite of D3's intended *"all good, the pavlova's covered."*

**It is not only the 15-minute cron.** `src/app/api/events/[id]/trigger-nudges/route.ts:31`
calls `processNudges` directly from a host-authenticated POST, so **a host can fire this on
demand, seconds after reassigning.** (The first audit's inventory of outbound entry points
missed this route entirely.)

**Latent for NZ, gated on TNZ go-live.** Two independent gates stand in front of a real
delivery today: `trigger-nudges/route.ts:24` short-circuits on `isSmsEnabled()` (Twilio-only —
see **GTC-214**), and `send-sms.ts:98-105` returns `blocked: 'SMS_DISABLED'` for any `+64`
destination without `TNZ_AUTH_TOKEN`. Every nudge candidate is forced to `+64`
(`nudge-eligibility.ts:164`, `:315`; `isValidNZNumber` = `/^\+64\d{8,10}$/`, `phone.ts:34-38`).
So this becomes live for NZ when TNZ does — which is also when GTC-214's cleanup lands. Scope it
alongside them, not as a current-sprint outage.

Related: this is the strongest argument **for** GTC-211 / GTC-176 (D3). Until the release
message exists, the release path's only outbound consequence is the wrong message.
