**In one line: the glance announces departures and never arrivals.**

⚠ **THIS IS NOT A PHASE 7 REGRESSION AND PHASE 7 IS UNAFFECTED.** It was found in the founder's
own browser walk after [[GTC-192]]'s phase 7 rulings, but every mechanism involved predates
that phase: the acting panel is phase 4's, the summary sentence is Ruling 2's, the assistant's
message is §3's, and the reassign route is older than the glance. Phase 7 added the reading
panel, which is the only place an arrival is visible at all.

⚠ **NO SOLUTION IS PROPOSED HERE, DELIBERATELY.** What the board should say instead is a design
question and it is the founder's. See *What was NOT decided*.

---

### Signal

**Expected**
After moving a row from one person to another, the host can see where it went.

**Actual**
She cannot, without opening the receiving person. The move itself is correct at every layer —
the row lands on the new holder and the ledger records it. What the board does is remove four
visible things at once and add nothing:

- the **red strip** goes (the sender is now empty-handed and derives AMBER);
- the **why-line** goes with it (*"— handed it back"*);
- **§3's assistant message** naming the item goes (it fires on a critical red row held by a
  RED person, and the new holder is not red);
- the **summary count** goes (*"1 needs you."* → *"Nothing needs you."*).

**The receiving strip does not change at all** if she was already amber. Same tint, same text,
same position. The item is one click deep, inside a panel the board gives no reason to open.

**Smallest failing case**
Move a critical row from a red person to an amber person, and watch the board. Everything that
named the item disappears; nothing anywhere says where it went.

### Reproduce

**Required state**
- Auth: a session with a HOST or COHOST `EventRole` on the event.
- Event state: CONFIRMING. Any board carrying a red person who holds a row, and an amber
  person to receive it.
- Multi-actor: [ ] Yes [x] No — one host, one surface.

**Steps**
1. Open `/plan/[eventId]/glance`.
2. Tap a red strip. The acting surface (`PersonSurface` in
   `src/components/glance/PersonSurface.tsx`) opens.
3. Pick another person in *Move to…* and press *Move*.
4. Look at the board.

**Observe:** the red strip is gone, the assistant's sentence is gone, the summary reads
*"Nothing needs you."*, and no strip anywhere indicates that a row arrived.

**Data setup**
`npx tsx scripts/seed-gtc192-phase7.ts` builds the board used for the measurements below
(`gtc192-phase7-variants`, host `nigel@mckorbett.co.nz`). It is idempotent. See
`scripts/README-gtc192-phase7.md`.

### Evidence — measured against the real route, not read off the code

Both cases were driven through `POST /api/events/[id]/items/[itemId]/assign` — the route
`reassignRequest` and `takeOverRequest` in `src/lib/glance/actions.ts` both build, and which
the panel actually calls. Row dumps are `psql` against `gather_dev`.

#### Case 1 — a move to another person

**Before:**

```
id        gtc192-phase7-variants-assign-thebirthdaycake
itemId    gtc192-phase7-variants-item-thebirthdaycake
personId  gtc192-phase7-variants-person-grace   (Grace Nguyen)
response  DECLINED
```

**After** (`{"personId": "…-person-chloe"}`, HTTP 200):

```
id        cmtweym4t0005rjctte6iczzm
itemId    gtc192-phase7-variants-item-thebirthdaycake
personId  gtc192-phase7-variants-person-chloe   (Chloe Nguyen)
response  PENDING
```

⚠ **THE ASSIGNMENT `id` CHANGES, AND THAT IS BY DESIGN RATHER THAN A DEFECT.** The route
`delete`s the released row and `create`s a new one inside one transaction, then logs
`MOVE_ASSIGNMENT` against the NEW id. `itemId` never changes. Recorded because a reader
hunting by assignment id will not find the row and may reach for "lost"; the founder's own
move produced `cmtwev1ix0001rjctj63rpzxe`, and the seeded id no longer existed.

**Where the item is afterwards**, read off `readEventGlance` in `src/lib/glance/read.ts`:

```
Chloe Nguyen   AMBER   reading   rows=2
     The trifle             AMBER MAYBE_LIVE
     The birthday cake      AMBER AWAITING_REPLY  critical
```

- **Under the new holder's strip:** NO. A strip renders a name, plus state-words for a red or
  an OUT person (`stripStateWords` in `src/components/glance/strip.ts`). It never lists rows.
  Chloe's strip reads exactly `Chloe Nguyen`, before and after.
- **In her reading panel:** YES, and this is the only place it appears —
  *Chloe Nguyen | No answer yet | nudge Mon*, then the two rows.
- **In the alert strip:** NO, correctly. Ruling 8's strip is for criticals with **no holder**.
- **Anywhere else:** NO.

**The board's full response to the move**, measured:

```
before   summary {"needYou":1,"withGather":4,"settled":4}   Grace RED "— handed it back"
after    summary {"needYou":0,"withGather":5,"settled":4}   Grace AMBER, no words
         assistant message: present before, absent after
```

#### Case 2 — a take-over by the host ("I'll do it")

Same route, same body shape, `personId` set to the host. From a clean re-seed:

```
before   gtc192-phase7-variants-assign-thebirthdaycake / Grace Nguyen / DECLINED
after    cmtwez7nb0009rjctxjzud10h / nigel (host) / PENDING
```

**And on the board:**

```
nigel   GREEN   reading   rows=1
     The birthday cake   GREEN ACCEPTED  critical
```

⚠ **THIS IS THE WORSE OF THE TWO.** Her own strip stays GREEN and the row derives **ACCEPTED**,
so the critical counts as **settled**. The summary reads *"Nothing needs you."* with a critical
item sitting under her own name. In case 1 the item at least still counts toward
*"Gather is on 5"*; taken over by the host, the board goes quiet about it entirely.

### None of the contributing rules is wrong

**This is the finding, and it is why the ticket is about the silence rather than about a
defect.** Each rule below is correct on its own terms and none should be changed to fix this.

- **A moved row resets to PENDING.** The predecessor's *no* is not the successor's answer. The
  route sets the schema default on the new row; nothing infers an answer for someone who has
  not been asked.
- **An empty-handed person derives AMBER** — [[GTC-192]] Ruling 16, verbatim: *"The ask is real
  even when the hands are empty… Attendance-only is a state of the ask, not an absence from the
  board."* `derivePersonState` in `src/lib/glance/state.ts`.
- **A host's PENDING row is settled** — [[GTC-256]] Ruling 5: no ask is ever made to her, so a
  row of hers awaiting nobody is not being chased. `deriveItemState` in the same file.
- **The assistant speaks only for a critical red row held by a red person** — §3's one plain
  message. `assistantMessage` and `findCriticalRedHits` in
  `src/components/glance/assistant.ts`.
- **The summary counts people by derived state** — Ruling 2. `summarisePeople` in
  `src/lib/glance/state.ts`. A loose item is not a person and the sentence never counted one.
- **A strip carries a why only when it is red** — Ruling 4. `whyLineFor` in
  `src/components/glance/strip.ts`.

**Each is right. The silence is what they make together.**

### The live half — an arrival is invisible even with the board open

`paintStrip` in `src/components/glance/paint.ts` swaps a strip's TINT and nothing else; that
module's governing rule is *"values, never structure"*, and `setWords` beside it is the one
stated exception. So a poll that finds a row has arrived on an already-amber person has
**nothing to repaint**: her tint did not move, her words did not change, and the panel behind
her is server-rendered from page-load state.

**Consequence: with the board open and polling, an arrival on an unchanged tint is invisible
until the next full load.** This is not a second bug; it is the same gap arriving through
[[GTC-192]] phase 6's live path rather than through a reload.
