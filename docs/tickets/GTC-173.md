# GTC-173 — C2: Preserve recipient-toggle fields through household edits

**Status:** Open | **Branch:** TBD | **Commit:** [pending] (filed `e5f6e82`) | **Effort:** medium

*Effort level is a proposal from the discovery-report ticket breakdown — run `/effort` manually
before execution.*

### Context

`reconcileMembers.ts` (GTC-159's diff-based household PUT, replacing the old delete-and-recreate
pattern) has no `$transaction` wrapping — a mid-request failure leaves a partial write. C1
(GTC-172) adds new channel/toggle fields at household capture that must survive edits through
this same path, or the recipient model silently degrades every time a host edits a household.

### Scope

**Fix here:**
- Extend `reconcileMembers.ts`'s upsert matching to carry C1's new channel/toggle fields through
  household edits without loss.
- If the non-transactional write pattern proves to be the actual root cause of any loss found
  during testing, flag it rather than silently expanding this ticket's scope to add a full
  `$transaction` wrap — that is a larger fix than "preserve these fields" and may warrant its own
  ticket.

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`.
- The broader household delete-and-recreate history beyond what C1 introduced — this ticket is
  scoped to the new fields, not a general audit of `reconcileMembers.ts`.

### Dependencies

C1 (GTC-172).

### Acceptance

- [ ] A household edit (add member, remove member, edit existing member) preserves C1's
      channel/toggle field values for unaffected members.
- [ ] Regression test covering an edit cycle that previously would have lost the field.
- [ ] `npx tsc --noEmit` clean, build passes.

### Stop Conditions

Standard eight from `BUG-TICKET-TEMPLATE.md`, plus:
9. Testing reveals the fix requires a full transaction wrap of `reconcileMembers.ts` — stop and
   propose that as a separate ticket rather than silently expanding scope.

## Preflight found bullet 1 already true

A fresh-session preflight against the accuracy audit
(`docs/04_roadmap/moment4-hinge-report-accuracy-audit-2026-08-04.md`, cluster C) re-verified,
directly in code rather than trusting the audit's prose, that `reconcileHouseholdMembers`
already preserves C1's toggle fields through an edit:

- `updateExistingMember` (`reconcileMembers.ts:186-217`) only ever writes
  `name`/`email`/`phone`, `householdRole`, `isYoungPerson`, and reachability on an in-place
  update — it never touches `teamId`/`rsvpStatus`/NudgeLog.
- `householdRole` is correctly re-derived from `adultRoled` on every edit
  (`reconcileMembers.ts:172-180`).
- `contactPersonEventId` round-trips all three states (`undefined` = leave alone, explicit
  value = set, `null` = clear) at `reconcileMembers.ts:300-318`.
- This already runs inside `prisma.$transaction` from the PUT route
  (`households/[householdId]/route.ts:171`) — the GTC-201 fix.

No test exercised any of this. **C2's real remaining work was the regression test, not a
fix** — confirmed rather than assumed: the preflight also independently verified the audit's
two claimed gaps directly in code (both real, both spun into GTC-217/GTC-218 below) before
ruling C2 itself scope-complete.

## What was built

`tests/household-edit-preserves-toggle-fields-test.ts` (`npm run

`householdRole: GUEST`, `isYoungPerson: true`) with its contact channel pointing
**cross-household** at household B's primary contact (Grandma) — exercising §10.7's
cross-household-capable channel design, not just the same-household case. Drives three edits
through the real reconcile seam (same steps the PUT route performs: load household, resolve
primary member, call `reconcileHouseholdMembers`):

1. No membership change, `contactPersonEventId` omitted (`undefined`) — asserts the
   adultRoled-derived role and `isYoungPerson` survive, the channel is left alone, and a
   non-toggle field (phone) still updates normally.
2. `contactPersonEventId` explicitly re-set to the same target — asserts set-and-kept, and
   that the role still survives a second edit.
3. `contactPersonEventId` explicitly `null` — asserts the channel clears.

No source file was changed. Two gaps the same preflight found in `reconcileMembers.ts` and
`households/route.ts` were confirmed real but are explicitly **not** this ticket's scope
(Stop Condition 9) — spun out as [[GTC-217]] (household CREATE path non-transactional,
resilience) and [[GTC-218]] (cross-household channel self-heal is single-household-scoped, a
live proxy-nudge correctness hole — higher priority than GTC-217).
