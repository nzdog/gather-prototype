# [[GTC-119]] — Food accordion item checkboxes — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** fa0fc1f

### What was found

- Food accordion items in `Moment2Step1Modal.tsx` used a flat `string[]` for `SectionData.items`. Each item only had a name and an x to remove it entirely. There was no way for Kate to exclude an item but keep it in the list for later re-inclusion.
- The `FOOD_DEFAULTS` constant and `handleEventTypeSelect` both produced plain string arrays.
- The `fetchSetup` hydration reads from the EventSetup API which stores `SectionData` as JSON — existing records may contain the old `string[]` format, requiring migration on load.

### What was changed

**File modified:** `src/components/plan/Moment2Step1Modal.tsx`

1. **New `FoodItem` interface** — `{ name: string; included: boolean }` replaces bare strings in `SectionData.items`.

2. **`FOOD_DEFAULTS` updated** — All default arrays now use a `toItems()` helper that produces `FoodItem[]` with `included: true`.

3. **`FoodAccordion` component updated:**
   - Each item now renders a checkbox (left of name) controlling `included` state.
   - Checked = included in plan, unchecked = excluded but still visible (greyed out, line-through).
   - The x button remains for permanent removal.
   - "Add your own" creates items with `included: true` by default.

4. **Data migration on mount** — `migrateSectionData()` in the `fetchSetup` effect converts old `string[]` items to `FoodItem[]` with `included: true`, so existing EventSetup records load correctly.

5. **`handleEventTypeSelect`** — Already works correctly since `FOOD_DEFAULTS` now returns `FoodItem[]`.

### Known limitations

- Old EventSetup records stored as `string[]` are migrated in-memory on load. The persisted JSON is updated on the next debounced save, but if Kate never triggers a save the old format remains in the DB until next visit.
