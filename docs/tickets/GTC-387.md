## Scope (Nigel's words quoted; Cowork's findings after each)

### 69. The board's door, "Add a way to reach them"

His words: "At the moment can only add emails when there is nowhere to send. Allow phones too.
Instead of button saying add a way to reach them,, have two fields - email and mobile and save
works on either. When saved button changes to close".

Found:
- The door is `doorSection()` in `src/components/glance/PersonSurface.tsx`: a "Send to" email
  box and one button per action. On the "nowhere to send" red (`UNREACHABLE`) the one action is
  EDIT, worded "Add a way to reach them" (`DOOR_WORDS` in `src/lib/press/resend-door.ts`; the
  founder's own words of 2026-09-19).

  `/api/events/[id]/people/[personId]/resend` (host only) -> `resendToPerson` in
  `src/lib/press/resend.ts`. The EDIT branch accepts only an address with an "@", writes
  `Person.email`, records an `EDIT_PERSON_CONTACT` ledger entry, and queues one `ASK` message
  with channel EMAIL, all in one transaction. Nothing is sent by the route; the two-minute job
  sends. The strip goes amber at the next refresh.
- A text can be queued today only by the PHONE action, which needs a number the guest already
  has, a number Gather can text, no STOP, and texting set up and live (`facts.textReach`,
  `facts.textingConfigured`). Nothing today saves a mobile number from this door.
- `tests/glance-actions-test.ts` counts the `/api/` paths `actions.ts` names: how many
  endpoints the board's surface can reach. Adding a second endpoint changes that invariant on
  purpose; extending the existing resend route does not.

### Corrections to the scope (checked against the repo at HEAD)

1. "Three the chooser cannot produce today" is six, and more for children.
   The code marks six unreachable (`ask-preview-compose.ts` L466-474): three in
   `ADULT_WHY` (HOST_HOUSEHOLD_CHILD, NO_CARRIER, HOUSEHOLD_MUTED) and three in
   `CHILD_WHY` (NO_CHANNEL, SMS_OPTED_OUT, PHONE_UNUSABLE). The four EMAIL_*
   child words are unreachable too, and so is `CHILD_WHY.EMAIL_OPTED_OUT`: a
   child refused for a channel reason always has a carrier, and
   `hostListReason` then says "X would pass it on, but I can't reach X". So an
   ADULT can be in group A for any of the eight channel reasons, and a CHILD
   only as a carried child (that sentence), HOST_HOUSEHOLD_CHILD, NO_CARRIER or
   HOUSEHOLD_MUTED.
2. "Nowhere to send" is not only "no email or mobile". The board's door opens
   on the UNREACHABLE red, which seven withheld reasons produce
   (`WITHHELD_MEANS_UNREACHABLE`, `delivery-fact.ts` L45-102): NO_CHANNEL,
   SMS_OPTED_OUT, OPTED_OUT, PHONE_UNUSABLE, INVALID_NUMBER, EMAIL_BLOCKED and
   EMAIL_BLOCKED_SMS_OPTED_OUT. So the board's door meets people who opted out
   of texts too, and needs the same "which boxes" rule as the pre-flight. One
   of them (a blocked email and a mobile Gather can text, the strip reads
   "can't email") already has "Send it as a text" beside the edit.
3. "Texting set up and live" (ruling 1) is never true on a Mac. The fence the
   door uses, `smsProviderConfiguredFor` (`send-sms.ts` L46), asks the live
   switch too, and `GATHER_LIVE_SENDS` is only `on` in production. So on the
   dev server a mobile-only save on the board is always refused "can't send
   texts". Nigel will not see a mobile-only save succeed on his own machine;
   the tests reach the success through the existing test seam.
4. The PATCH Cowork names (`/api/events/[id]/people/[personId]`) is not fit
   for the box as it stands. HOST and COORDINATOR (a co-host is refused), no
   ledger entry, no check of opt-outs or blocks, and an unreadable number is

   `phoneNumber: null`, so a typo wipes a number. The plan does not use it
   and does not change it.
5. Step 4's names come from `GET /api/events/[id]/pre-flight/message` (HOST
   and COHOST), not from the pre-flight route; part 3 is page.tsx L1686-1726.

   is opened. The pre-flight GET route is not touched (unlike GTC-386, so

6. A spam report is not "an email that bounced or is blocked". EMAIL_REPORTED

   refused anyway. The plan puts it with the opt-outs (plain text).
7. More rulings than three are superseded by item 70. Besides GTC-192 Rulings
   7, 17 (second sentence) and 32: GTC-350 plan Q-G ("without replies both
   stay sealed"), Ruling 31 as `GlancePersonReading` records it ("no controls
