# GTC-338 — retire the bounce door's ADDRESS_TAKEN arm

**Status:** Open — a stub, filed 2026-09-29 at [[GTC-293]], on founder ruling Q5: leave the dead
arm in place there and file the follow-up as a stub. Not scoped.

---

### Signal

[[GTC-189]] slice 7b gave the bounce door's EDIT AND SEND a catch for `P2002` on the
`Person.email` write in `resendToPerson` (`src/lib/press/resend.ts`), answered as `ADDRESS_TAKEN`
with the words in `RESEND_REFUSAL_WORDS` (`src/lib/press/resend-door.ts`). The violation was
[[GTC-293]]'s: `Person.email` was `@unique`.

[[GTC-293]] dropped the constraint (migration `gtc293_person_email_not_unique`). No `Person`
column other than the primary key is unique now, so the catch cannot fire and the code is never
produced. `test:bounce-door` asserts the new truth — an edit onto an address another Person
holds is accepted — and no longer asserts the refusal.

### The retirement, named and not designed

Remove the `P2002` arm, `ADDRESS_TAKEN` from `ResendRefusalCode`, and its entry in
`RESEND_REFUSAL_WORDS`, and correct `ResendRefused`'s docstring, which names GTC-293's violation
as the case it carries.

### Unknowns

1. Whether any client or panel reads `ADDRESS_TAKEN` by name (search the door's UI before
   removing it).
