# [[GTC-095]] — Auto-recheck conflicts after any data-changing action — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** 8ffe659

### What was found

- The inline auto-recheck logic existed only in `executeRegenerate` (line ~865). No other data-changing handler triggered a conflict re-check.
- `onTeamsChanged` and `onItemsChanged` do not exist as named callback props. Team and item mutations are handled by dedicated functions: `handleAddTeam`, `handleAddItem`, `handleSaveEditItem`, `handleDeleteItem`, `handleDeleteTeam`.
- `handleMovePerson` has its own reload sequence (loadPeople, loadTeams, gateCheckRefresh) and does not delegate to `onPeopleChanged`.
- `onPeopleChanged` exists as an inline callback in two instances (dashboard PeopleSection at line ~1913 and modal PeopleSection at line ~2478).

### What was changed

**`src/app/plan/[eventId]/page.tsx`:**

1. **Extracted `autoRecheck` function** (after `handleCheckPlan`):
   - Guards on `event?.lastCheckPlanAt` — only runs if host has previously run a manual check.
   - POSTs to `/api/events/{eventId}/check`, then reloads event, conflicts, and gate check.
   - Silent failure via empty `catch` — never blocks the calling action, no toast, no console.error.

2. **Added `autoRecheck()` (fire-and-forget) to 8 data-changing handlers:**
   - `handleAddTeam` — after team creation
   - `handleAddItem` — after item creation
   - `handleSaveEditItem` — after item edit
   - `handleDeleteItem` — after item deletion
   - `handleDeleteTeam` — after team deletion
   - `handleMovePerson` — after person moved between teams
   - `onPeopleChanged` (dashboard instance) — after any people change
   - `onPeopleChanged` (modal instance) — after any people change

3. **Replaced inline recheck in `executeRegenerate`** with `await autoRecheck()`. Removed the old `console.error` and try/catch block.

### Known limitations

- Auto-recheck is best-effort and fire-and-forget (except in `executeRegenerate` where it's awaited). If the check API is slow, the conflict list may take a few seconds to update after the data change.
- `autoRecheck` calls the full `POST /check` endpoint which re-runs all conflict detection logic. For events with many teams/items, this adds a background API call after each data change. This is acceptable for now but could be optimised with a lighter-weight conflict refresh in the future.
- Events that have never been manually checked will not auto-recheck — by design, to avoid surprising the host with conflicts they didn't ask for.
