# GTC-234 — Convert the wrap-up operational `console.log` to the project's logging convention

**Status:** Complete | **Effort:** trivial — one line

*Filed 2026-08-22, blocking [[GTC-233]]. Surfaced by the preflight `console.log` gate during
the GTC-233 executor preamble.*

## Signal

**Expected:** `grep -r "console\.log" src/ --include="*.ts" --include="*.tsx" | wc -l`
returns `0`. This is a preflight gate in the executor preamble; a non-zero count is a
STOP condition for every ticket.

**Actual:** returns `1`. The sole occurrence is in `dispatchPendingWrapUpMessages` in
`src/lib/wrap-up.ts`, inside the `isQuietHours(now)` guard:

```
console.log(
  `[WrapUp] Quiet hours — deferring ${pendingLinks.length} message(s), ~${deferredUntilMinutes} min until send window`
);
```

**Smallest failing case:** run the grep above on a clean tree.

## Root cause

Introduced by `a4fa742` (*fix(GTC-210): add quiet-hours guard to the wrap-up send path*,
2026-08-05). It is **legitimate operational logging, not debug residue** — the guard's own
comment records that this deferral, unlike the two sibling guards in
`src/lib/sms/nudge-sender.ts` and `src/lib/sms/proxy-nudge-sender.ts`, writes no
`InviteEvent` row (no `InviteEventType` wrap-up equivalent of `NUDGE_DEFERRED_QUIET`;
adding one is an enum migration, deliberately deferred to keep GTC-210 schema-free).

The defect is the **method**, not the logging. `console.log` is the one console method the
preflight gate bans; GTC-210 reached for it where the codebase everywhere else uses
`console.warn`.

## The convention this adopts

**There is no logger module in this repo.** No `src/lib/log*`, and no logging dependency
in `package.json` (checked: pino, winston, bunyan, loglevel, consola, debug — none). The
convention is bare `console`, and the counts define it:

| method | occurrences in `src/` |
|---|---|
| `console.error` | 217 |
| `console.warn` | 22 |
| `console.log` | 1 ← this ticket |

The nearest precedent is structurally identical: `sendSms` in `src/lib/sms/send-sms.ts`
logs an operational **suppression** condition in the SMS send path with `console.warn` and
a bracketed prefix, then returns a structured result. `[AI Generate]` in
`src/lib/ai/generate.ts` uses the same bracketed-prefix style for fallback conditions.

A suppressed batch of outbound messages is a notable-but-normal condition — `warn`, not
`error`, and not `log`.

## Scope

**Fix here:** the single `console.log` call in `dispatchPendingWrapUpMessages` in
`src/lib/wrap-up.ts` → `console.warn`. Message text, guard logic, return shape, and the
explanatory comment block all unchanged.

**Do not touch:** the quiet-hours guard's behaviour (GTC-210's fix), `isQuietHours` /
`getMinutesUntilQuietEnd`, the sibling nudge senders, the `InviteEventType` enum, the
returned `deferred` / `deferredUntilMinutes` fields, and all Do-Not-Touch Zones in
`GATHER-BUILD-CONSTANTS.md`.

The wrap-up deferral remains observable only in server logs and the cron's JSON response —
it still writes no `InviteEvent` row, so it is not durably auditable the way nudge
deferrals are. That gap belongs to GTC-210's deliberate schema-free scoping and is
unchanged here. Filing an `InviteEventType` wrap-up deferral value is a separate ticket if
the audit trail is ever wanted.
