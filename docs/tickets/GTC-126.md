# GTC-126 — Moment 2 polish: per-call toast duration + food accordion default unchecked — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** ea6f3ae

### What was found

**Issue A — Toast duration is globally fixed.** `ToastContext.tsx` had a single `TOAST_DURATION = 4000` constant used unconditionally in `setTimeout`. No per-call override existed, so GTC-124's "Updated." / "Removed." / "Added." confirmations stayed 4 s — flagged as PARTIAL in GTC-124 assertion 15.

**Issue B — Food accordion defaults to opt-out.** Pre-populated food items in `Moment2Step1Modal.tsx` came from `config-loader.ts`'s `getAccordionDefaults()`. All four food sections (mains, sides, desserts, drinks) hard-coded `included: true`, forcing users to uncheck anything they didn't want. Three other `included: true` sites exist in the codebase (legacy string-array migration, "Other notes" restore, user-typed "+ Add your own") — each is behaviourally distinct and correctly stays opt-in / already-chosen. Only the fresh-event config-loader defaults needed to flip.

### What was changed

**`src/contexts/ToastContext.tsx`:**

- Added `ToastOptions` interface with optional `duration?: number`.
- Extended `toast.success` / `toast.error` / `toast.warning` / `toast.info` to accept an optional second argument `options?: ToastOptions`. Types updated on `ToastContextValue.toast` so the new arg is discoverable.
- `addToast` now takes the options, resolves `duration ?? TOAST_DURATION`, and uses it in `setTimeout`. `TOAST_DURATION` constant is unchanged — omitting the argument preserves 4 s behaviour for every existing caller.

**`src/components/plan/Moment2PlanView.tsx`:**

Five short-acknowledgement toasts now pass `{ duration: 2000 }`:

| Handler | Toast |
|---|---|
| `handleSaveEdit` | `toast.success('Updated.', { duration: 2000 })` |
| `handleRemove` | `toast.success('Removed.', { duration: 2000 })` |
| `handleQuantitySave` | `toast.success('Updated.', { duration: 2000 })` |
| `handleAdd` | `toast.success('Added.', { duration: 2000 })` |
| `handleAddCategory` | `toast.success('Added.', { duration: 2000 })` |

No other toast copy or logic changed.

**`src/lib/ai/config-loader.ts`:**

Flipped the four food-category defaults from `included: true` to `included: false` in `getAccordionDefaults()`, with an inline comment noting that user-typed items (`"+ Add your own"`) still default `included: true` — if the user typed it, they want it.

### Known limitations

- **Other Moment 2 toasts are unchanged.** "Plan approved." (parent page) and the Step 1 modal's AI-cap / generation-failure toasts remain at the default 4 s. Per ticket scope, only the GTC-124 Plan View toasts move to 2 s.
- **`included: true` on three remaining sites.** Preserved deliberately:
  1. Legacy migration path (`Moment2Step1Modal.tsx:191`) — old DB entries that saved as plain strings represent items the user had previously chosen, so marking them checked on load matches prior intent.
  2. "Other notes" restore (`Moment2Step1Modal.tsx:293`) — user-provided note content, should appear as selected.
  3. "+ Add your own" (`Moment2Step1Modal.tsx:682`) — user explicitly typed this item, so it's clearly opt-in.
