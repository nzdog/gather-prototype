### Signal

On pushing [[GTC-355]] (`a417827..84f22e7`, 2026-10-03), Claude Code reported, verbatim: *"On the
push, GitHub reported 79 Dependabot alerts on the repo's default branch (2 critical, 36 high, 36
moderate, 5 low). They were already there; this work didn't add a dependency."*

### What Cowork measured (2026-10-03, read-only)

`npm audit --package-lock-only` was run on copies of each branch's `package.json` and
`package-lock.json`, outside the repo; nothing in the repo changed. npm groups findings by package
and Dependabot counts alerts per advisory, so the totals differ.

- **The default branch, `master`** (local view `ebc21d9`, 2026-08-10; the live app runs code of
  about that date): `next` 15.5.14. 29 packages flagged: 1 critical, 19 high, 7 moderate, 2 low.
  The critical is `next` itself, carrying the two critical advisories of Next.js's August 2026
  security release (fixed in 15.5.24):
  - GHSA-p293-qw3h-jr36 (CVE-2026-75604), remote code execution on Windows-hosted servers. The
    release notes: "Linux and macOS are not affected by this issue."
  - GHSA-2xp9-vwfh-vxw4, remote code execution "when Next.js optimizes an attacker-controlled AVIF
    image". On `master`, `next.config.js` is empty (no `images.remotePatterns` or `domains`), so
    the optimizer serves only the app's own images, and the repo holds no AVIF file. Cowork found
    no way to hand it an attacker's image, but did not prove there is none.
  - Besides these, high advisories (middleware bypasses, server-side request forgery, denial of
    service), each fixed in 15.5.24 or earlier.
- **The launch branch, `feat/moment-one-redesign`** (`84f22e7`): `next` 15.5.25, past every advisory
  above. 15 packages flagged: 0 critical, 14 high, 1 moderate. Of the 14 high, 13 handle nothing a
  visitor sends: lint and build tools (`eslint-config-next`, `@next/eslint-plugin-next`,
  `lint-staged`, `tailwindcss`, the copy of `postcss` 8.4.31 that `next` ships for compiling CSS,
  and the glob libraries under them: `fast-glob`, `micromatch`, `braces`, `brace-expansion`,
  `chokidar`) and the `prisma` CLI used for migrations (`prisma`, `@prisma/config`, `deepmerge-ts`).
  The one in the running app's own code paths is `axios` 1.19.0 (prototype-pollution gadgets),
  brought in by `twilio` 5.12.0, whose client `src/lib/sms/twilio-client.ts` is still imported by
  `src/lib/sms/send-sms.ts`, `nudge-scheduler.ts` and `decide-by-scheduler.ts`.
- **GitHub's alerts** read the default branch, `master`, so they describe the old code, not the
  launch branch, until [[GTC-279]]'s branch decision.

Sources: the Next.js August 2026 security release,
https://nextjs.org/blog/august-2026-security-release; GitLab's copy of GHSA-2xp9-vwfh-vxw4,
https://advisories.gitlab.com/npm/next/GHSA-2xp9-vwfh-vxw4/.

### The ruling

Asked in Cowork, 2026-10-03, verbatim:

> GitHub's 79 security alerts are for the old code the live app runs, not this work. I checked the
> code you'll launch: no critical ones. Its 14 'high' ones are almost all in tools that only build
> and check the code, plus one that comes in with the old Twilio texting library. Should a security
> check be a must-do before launch?

The founder's answer, verbatim: **"Yes, a small check (Recommended)"**. The option read: *"I file a
small ticket. Before the deploy, the check is re-run on the launch code and must show no critical
ones. The Twilio library's issue gets fixed or the library removed. And once the branch decision
(GTC-279) is made, GitHub's alerts will cover the code that's actually live."*

⚠ *2026-10-08: the sign-in hole is [[GTC-369]], not this check.* Found while planning [[GTC-367]]:
the sign-in check (`POST /api/auth/verify`) takes the person from the link. That is Gather's own code,
not a package, so this check would never find it; it is not left to this check. By founder ruling of
2026-10-08 (verbatim in [[GTC-369]] and in [[GTC-189]]'s gathered list, *Fifth ruling*) it is its own
ticket and a precondition of the deploy, built straight after batch 5.

  takes none from outside).

### For the build

- **The three updates, and nothing else:** `next` to 15.5.27, `sharp` to 0.35.5 and `axios` to
  1.20.0, in `package.json` (the floors raised, so a fresh install cannot fall below them: `next`
  `^15.5.27`, the `axios` override `^1.20.0`, and `sharp` as the build proposes, an override or
  the lockfile alone) and `package-lock.json`. `twilio` stays 5.12.0. No Gather source changes; if
  one turns out to be needed, stop and say why. Never `npm audit fix --force`.
- **A check to re-run at the deploy:** a script (not a route) that runs `npm audit
  --package-lock-only` on the lockfile and fails on any critical, and on any advisory in `next`,
  `sharp`, `axios` or `twilio`; it prints package names, severities and advisory ids only. It goes
  on the deploy-day list.
- **Every test:** the full gate list, `test:security`, `security:routes`, typecheck, lint against
  the known 62, `format:check`, and `npm run build` with the dev server stopped. A `next` patch
  release can change what pages render, so the Chrome suites matter most.
- **Not in this ticket:** the tool-only highs (after launch), removing the Twilio library (after
  launch, if ever), the live app (left until the deploy, as ruled), and Dependabot's view, which
  follows [[GTC-279]]'s branch decision.
