### What was found

**Assignment API pattern:** Individual item assignments use `POST /api/events/[id]/items/[itemId]/assign` (assign) and `DELETE /api/events/[id]/items/[itemId]/assign` (unassign). No batch endpoint exists.

**Source of reload:** The `handleQuickAssign` function in `src/app/plan/[eventId]/page.tsx` made an immediate API call on every dropdown `onChange`, then called `loadTeamItems()` and `loadTeams()` to reload data — resetting the expanded team state and preventing batch editing.

**Local state approach:** Replaced immediate API calls with `pendingAssignments` state (`Record<itemId, { personId, teamId }>`). Dropdown changes update local state only. A sticky Save bar appears when pending changes exist, and commits all assignments sequentially on Save. If the user attempts to close the modal with unsaved changes, a confirmation dialog warns them.

### What was changed

**`src/app/plan/[eventId]/page.tsx`:**
- Added three new state variables: `pendingAssignments`, `showDiscardWarning`, `savingAssignments`
- Added `handleStageAssignment()` — updates local pending state without API calls; auto-removes entries that match original server state
- Added `handleSaveAllAssignments()` — iterates pending assignments, calls assign/unassign API sequentially, reloads affected teams/items on success
- Added `handleTeamsModalClose()` — intercepts close when pending changes exist, shows discard warning
- Added `handleDiscardAndClose()` — clears pending state and closes
- Removed `handleQuickAssign()` — no longer used
- Updated Teams modal `onClose` from `handleCloseExpansion` to `handleTeamsModalClose`
- Updated quick-assign dropdown: reads from `pendingAssignments` if present (with amber highlight), falls back to server state; calls `handleStageAssignment` on change
- Added sticky Save bar at bottom of Teams modal (shows count, Discard + Save All buttons)
- Added unsaved changes warning dialog (Go Back / Discard & Close)

### Known limitations / follow-up flags
- Assignments are saved sequentially (not a single batch API call) since no batch endpoint exists. For most realistic team sizes this is fine.
- The EditItemModal still saves assignments immediately on its own Save (unchanged, out of scope).
