# [[GTC-062]] — Plan Status unassigned items by name with assign path — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** 06ab440

### What was found
- The TransitionModal (Plan Status modal) fetched only from `/api/events/[id]/summary`, which returns aggregate counts (`criticalUnassignedCount`) but no item names.
- The items API at `/api/events/[id]/items` already returns full item data including `assignment` (null when unassigned), `name`, `critical`, and `team.name`.
- No additional API route or schema change was needed — the existing items endpoint provides everything required.

### What was changed

**`src/components/plan/TransitionModal.tsx`**
- Added `UnassignedItem` interface and `onGoToAssign` optional callback prop
- Added `unassignedItems` state
- Modified `fetchPlanSummary` to fetch items in parallel with summary using `Promise.all`
- Filters items client-side for `!item.assignment` to build unassigned list
- Added new "Unassigned Items" section between Plan Summary grid and "What Happens Next"
- Lists each unassigned item by name with team name and critical badge
- Shows up to 8 items with overflow indicator
- "Go to Teams to assign" link (when `onGoToAssign` provided) closes modal and navigates to teams section
- When all items assigned and items exist, shows green "All items assigned" indicator
- When no items exist, section is hidden entirely

**`src/app/plan/[eventId]/page.tsx`**
- Passed `onGoToAssign` callback to TransitionModal that closes modal and expands the Teams section via `handleExpandSection('teams')`

### Known limitations / follow-up flags
- Used link-to-teams approach rather than inline person selector — inline would require loading team members per item inside the modal, adding significant complexity for marginal UX gain.
- The `onGoToAssign` prop is optional, so other TransitionModal usages (GateCheck, FreezeCheck, InviteStatusSection, host page) show the unassigned list but without the navigation link. These could be wired up in follow-up tickets if needed.
- Items list capped at 8 visible to prevent modal overflow; full count shown.
