# GTC-098 — Add conflict detection: critical items with no assignee — CLOSED

**Status:** Complete | **Branch:** master | **Commit:** TBD

### What was found

- The `detectConflicts` query in `src/lib/ai/check.ts` loaded team items with only `day: true` in the include — the `assignment` relation was not included.
- The Item model has no `assignedToId` field. Assignment is handled via a separate `Assignment` relation model (one-to-one on `Item.assignment`).
- `ItemStatus` has only `ASSIGNED`/`UNASSIGNED` — no `CONFIRMED` status exists. The ticket's `status !== 'CONFIRMED'` condition is not applicable; instead, the presence of an `assignment` record is the authoritative check.
- `critical` and `status` are scalar fields on Item and are always returned by Prisma without explicit include.
- The `ConflictData` interface did not include `canDelegate` — added it as an optional boolean.

### Known limitations

- The ticket specified `item.assignedToId === null` and `item.status !== 'CONFIRMED'`, but neither field exists in the schema. Adapted to check `!item.assignment` (no Assignment record), which is the correct equivalent.
- No `suggestion` field added (per GTC-097 removal).
