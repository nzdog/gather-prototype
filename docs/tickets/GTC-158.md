# GTC-158 — Re-anchor line-number code references in skills to symbol anchors — CLOSED

## Problem

Six references across the skill library cite workflow.ts by line number
(canTransition :243, canMutate :265, logAudit :289, runGateCheck :440,
checkFreezeReadiness :107, EPIC 4 :73). Every edit above a referenced line
shifts the numbers and forces a manual re-verification sweep — this has
already happened twice in two days (GTC-154: −19 lines; GTC-156: comment
deletions). The V1/V2 reconciliation campaign Phase 4 decomposes this exact
god-file, which will invalidate every line reference at once and possibly
relocate the functions to new files.

Line numbers are a snapshot pretending to be a rule — the same volatile-fact
problem the review pass flagged for migration counts and demo names.

## Fix

1. Find every line-number file reference across .claude/skills/ — not just
   workflow.ts. Inventory first, show the list before editing.
2. Replace each with a function-name (or export-name) anchor, e.g.
   "workflow.ts — canTransition()" instead of "workflow.ts:243". Where a
   reference points at something with no stable symbol, anchor to the nearest
   named symbol plus a relative cue.
3. Do NOT change what the references say about behavior — re-anchoring only.
   Any reference whose surrounding claim looks wrong: list it, don't fix it.
4. Update the skill-authoring guidance: cite by symbol name, never by line
   number; line numbers only with an as-of commit hash.
5. Verify each new anchor resolves: grep confirms every named symbol exists in
   the cited file. Symbols appearing more than once need a disambiguating cue.
6. One commit, skills only. Typecheck as a free regression check.

## Sequencing

Landed after GTC-157 (commit 3e599fe) — anchored against the post-157 file.
Must land before reconciliation Phase 4 begins.

## Out of scope

- Behavioral corrections to any reference (none surfaced — zero suspect claims).
- References in docs/ outside .claude/skills/.
- References TO `.md` docs by line (e.g. `GTC-145.md:87`,
  `GATHER-BUILD-CONSTANTS.md (~line 200)`) — ticket scope is code refs only.
- Grep-recipe recon annotations (`grep -n "..." # was :376`) — the grep command
  is the durable anchor; the `# line/was :NNN` is an explicit as-written
  snapshot, which is the sanctioned "line + context" form, not the anti-pattern.
