# GTC-464 - The privacy page says only what Gather does

**Status: built; full gate passed; not yet pushed or merged.**
Branch `fix/gtc-464-privacy-words` from origin/main 290f828 (the merge
of pull request #100), not tracking main. Words only: no code change,
no migration.

All dates are NZ time (NZDT, UTC+13).

## Why

The privacy page (`src/app/privacy/page.tsx`, at `/privacy`) promised
page-visit records, analytics, a single cookie and deletion after 12
months. None of those is what the code does. A code check on 15 Nov
2026 found the disagreements; [[GTC-463]] stopped sending browser text
to the host. This ticket changes the page's words so they say only what
Gather does.

The page is in no Do-Not-Touch Zone and is not frozen by
`tests/tweaks-guard-test.ts`. It reads `GATHER_CONTACT_EMAIL` from
`src/lib/email-footer.ts` (zone 9), which this ticket does not touch.

## The W9 check (before using W9)

- The thank-you reaches a +61 number through TNZ: it picks text for
  any number not opted out or blocked (`src/lib/wrap-up.ts:166-167`)
  and sends through `sendSms` (line 346), which checks only the
  number's format (`src/lib/sms/send-sms.ts:96`, `src/lib/phone.ts:88-90`)
  and gives +64 and +61 to TNZ (send-sms.ts:16-20, 115, 236; TNZ gets
  the number as it is, `src/lib/sms/tnz-client.ts:66`).
- A number outside +64 and +61 is not sent today: with no Twilio
  settings `sendSms` returns "not sent", "Twilio not configured for
  non-NZ/AU destination", before any network (send-sms.ts:179-186).
  The thank-you records the text as refused (wrap-up.ts:353-358), then
  goes by email if it can (370-381), or is marked failed (383, 412),
  or, if the guest said no to email, is counted as held back (362-368).
  Never a text reported as sent.
- No sending path checks for a mobile: the thank-you texts any +61
  number, and invitations and reminders take any +64 number of 8 to 10
  digits (`src/lib/eligibility/channel-chooser.ts:332, 406`,
  `src/lib/sms/nudge-eligibility.ts:269`, the rule at
  `src/lib/phone.ts:44-47`, which lets landlines through). So
  "mobile" was dropped from both sentences (the ruling above).
- The page's other claim about which numbers are texted, "We send SMS
  nudges to phone numbers provided by event hosts" (line 143), is left
  as it is: it does not overstate. A route exists that would let a
  guest add their own number (lines 47-52 of
  `src/app/api/p/[token]/contact-info/route.ts`), but no screen calls
  it. "mobile" appears nowhere else on the page.

## The host link check (before relying on W1 and W2)

- `src/app/api/h/[token]/route.ts` stores nothing when a host link is
  opened. It only reads the guests' links' `openedAt` (lines 143-146)
  to show each guest's status (line 166). Nothing under `src/app/h/`
  or `src/app/api/h/` reads the browser text or an internet address.
- The only link-open writes in src are the guest and coordinator
  routes (`src/app/api/p/[token]/route.ts:109-123`,
  `src/app/api/c/[token]/route.ts:37-52`: the open time and the
  browser text, cut to 200), and the shared-link claim, which marks
  the link opened when a name is claimed
  (`src/app/api/join/[token]/claim/route.ts:195`; no browser text
  since GTC-463).
- A host link's only trace is its 8-hour cookie (`gather_h_token`,
  `middleware.ts:34-38, 66-74`), which W6 covers.
- So the host route stores nothing W2 does not cover: not a stop. W1
  and W2 say a little more than the code does for host links and the
  shared link: nothing is kept for a host link's open, and no browser
  text for a shared-link claim.

## The words (final, as ruled)

Each line: the old words, the new words, and why. Apostrophes are
written `&apos;` in the page's source.

- **W0 (the date)**
  - OLD: "Last updated: 3 October 2026"
  - NEW: "Last updated: 16 November 2026"
  - Why: the page changes (Q13: the day it is edited).
- **W1 (What We Collect, the usage item)**
  - OLD: "Usage data: page visits, link opens, response timestamps"
  - NEW: "Usage data: when someone first opens a link we sent them,
    and when they answer"
  - Why: ruling 1; only a link's first open is recorded.
- **W2 (What We Collect, a new item right after W1)**
  - NEW: "Browser details: when someone first opens a link we sent
    them, we keep the description their browser sends of itself (such
    as the browser and device type), cut to 200 characters. Hosts do
    not see it."
  - Why: ruling 2. No reason is given for keeping it (Q7).
- **W3 (What We Collect, the cookies item)**
  - OLD: "Cookies: a single session cookie for authentication (no
    tracking cookies)"
  - NEW: "Cookies: a sign-in cookie, and a cookie for the invitation
    link you opened (no tracking cookies)"
  - Why: four cookie names, not one.
- **W4 (What We Collect, the analytics item): removed**
  - OLD: "Analytics: usage data may be collected via analytics
    services"
  - Why: ruling 1; there is no analytics code or package.
- **W5 (Data Retention, the first bullet becomes three)**
  - OLD: "Event data is retained for 12 months after the event date,
    then deleted"
  - NEW:
    - "Event data is kept until the host deletes the event, or until
      you ask us to delete it. Nothing deletes it automatically."
    - "Deleting an event removes its plan, guest list, answers,
      invitation links, messages and text replies. People's names and
      contact details are kept."
    - "Sample events made on the demo page are deleted by Gather the
      next day."
  - Why: ruling 5.
- **W6 (Cookies, the first bullet becomes two)**
  - OLD: "We use a single session cookie for authentication"
  - NEW:
    - "A sign-in cookie keeps you signed in. It lasts 30 days, or 2
      hours for a sample event. Signing out removes it."
    - "When you open an invitation link, your browser keeps that
      link's code in a cookie for 8 hours. It is sent only to Gather's
      pages for that kind of link."
  - Why: the four cookies' real names and lifetimes.
- **W7 (Cookies, the analytics bullet): removed**
  - OLD: "Analytics cookies may be used"
  - Why: ruling 1; no code sets any other cookie.
- **W8 (What We Collect, the payment item)**
  - OLD: "Payment data: Stripe handles payment processing. We store
    only the Stripe session ID, not card details."
  - NEW: "Payment data: Stripe handles payment processing. Card details
    go to Stripe, not to Gather. We keep Stripe's reference numbers for
    your payment or subscription, the amount paid and the dates."
  - Why: no session id is stored; other Stripe ids are.
- **W9 (SMS Communications)**
  - OLD: "We only send to New Zealand mobile numbers"
  - NEW: "Invitations and reminders are texted only to New Zealand
    numbers. A thank-you after the event can also go to an Australian
    number."
  - Why: the thank-you is texted to any number, and TNZ takes +61. No
    path checks for a mobile, so "mobile" is dropped (see "The W9
    check"). Production has no TWILIO variables (the founder, 16 Nov
    2026), so nothing outside +64 and +61 is texted.
- **W10 (Cookies, a new bullet after "No tracking cookies", where the
  analytics bullet was)**
  - NEW: "Gather also saves some things in your own browser so you
    don't lose them: an unsaved household form for up to 7 days, and
    a new event's details until you finish creating it."
- **W11 (What We Collect, the last item, after the cookies item, where
  the analytics item was)**
  - NEW: "Sample events: if you start one on the demo page, Gather
    keeps a short code made from your internet address with a secret
    key, to allow 3 samples an hour. It is deleted with the sample.
    Your internet address itself is not stored."
  - Placed last: the list goes from what any link-holder leaves to the
    one case that is the demo's alone.
- **W12 (Data Retention, a new bullet after the SMS opt-out bullet)**
  - NEW: "Records of email addresses and phone numbers that cannot
    receive our messages are kept permanently, so we stop trying
    them."
- **W13 (Who We Share It With, the Anthropic line)**
  - OLD: "Anthropic — AI plan generation (event details sent to
    generate plans)"
  - NEW: "Anthropic — AI plan making (event details and dietary needs;
    sometimes the names of guests bringing items)"
  - The dash is the page's own em dash (—).

Unchanged: everything else on the page, including "No tracking
cookies", "Account data is retained while the account is active", "SMS
opt-out records are retained permanently to respect opt-out
preferences", the text-reply bullet (GTC-350), the household sentence
(GTC-356), and the TNZ, Resend, Stripe and Railway lines.
