## How existing setup data is fetched and populated on mount

On mount, the component calls `GET /api/events/${eventId}/setup`. If a setup record exists (`data.setup` is non-null), each field is merged into local state with fallbacks to initial defaults for any missing fields. The `loaded` flag gates rendering to prevent flash of empty state.

## How debounced persistence is implemented

Every call to `updateState()` triggers `scheduleSave()`, which stores the latest state in `pendingRef` and sets a 500ms timeout. If another change occurs within 500ms, the timeout resets. When the timeout fires, it POSTs the full state to `/api/events/${eventId}/setup`. The `handleGenerate` callback flushes any pending save synchronously before calling `onGenerate()`.
