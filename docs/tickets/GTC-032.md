# GTC-032 — Plan/Generate: Guided Plan Builder — Engine

**Type:** Feature
**Severity:** P2

---

## The Person

A host creating a Christmas event for 43 guests. They click "Generate Plan" and see a single text box. They don't know what to write. They skip it. Claude generates a generic plan that misses half the things they actually needed — no entrée, wrong number of mains, no dessert breakdown.

The host needed guidance. The product didn't offer any.

---

## The Broken Promise

Generate Plan implies Claude will produce a plan tailored to this event. In practice, without structured input, Claude is guessing. A host who knows exactly what they want — traditional roast mains, pavlova dessert, no clean-up items — has no way to tell Claude that without writing an essay.

Worse: the event already knows the occasion type, guest count, dietary requirements, and venue. None of this is surfaced during plan generation.

---

## The Cost

Plans require significant rework. Hosts lose confidence in the AI. The core value proposition (AI that does the heavy lifting) is undermined on first use.

---

## The Fix

Add a "Guided Build" path alongside the existing "Quick Generate" path. The guided builder walks the host through a structured option tree — occasion-aware, pre-populated with event data, non-linear, with persistent state and breadcrumb navigation — and compiles their selections into a rich structured prompt before sending to Claude.

---

### Entry point

The existing "Tell us about your event" modal becomes a choice screen:

> **How would you like to generate your plan?**
> - **Quick Generate** — describe your event in your own words (current flow, unchanged)
> - **Guided Build** — choose what you want step by step

---

### Pre-populated context panel

At the top of the Guided Build (and visible throughout navigation), show a summary of what the event already knows:

> 🎄 Christmas · 43 guests · 29 May 2026
> 🏡 Grand Hall · Kitchen access: Full
> ⚠️ Dietary: Gluten free required

This data comes from the existing event record — no new input required from the host. It must:
- Pre-select or highlight relevant options (e.g. "Gluten free option needed" pre-checked where dietary flags exist on the event)
- Feed into the compiled prompt automatically alongside the host's guided selections
- Be visible throughout the guided builder so the host always has context

---

### Guided Build component (`GuidedPlanBuilder`)

Architecture:
- Reads from a JSON config file: `src/lib/ai/plan-option-tree-config.json`
- Config-driven — component logic must not hardcode occasion content
- Non-linear navigation — host can move between categories and levels freely
- Persistent state — selections survive navigation within the session
- Breadcrumb trail — shows current path (e.g. "Mains → Traditional Christmas → Specific dishes"), allows jumping back to any level
- Per-category progress indicator — shows which categories are configured vs untouched
- Free text field at every level — always optional, never blocks progression
- "Show more categories" option — expands beyond occasion-pre-populated defaults
- Final review step — summary of all selections before generating, with edit links back to any category

---

### Prompt compiler

New function `compileGuidedPrompt(eventParams, selections)` in `src/lib/ai/generate.ts`:
- Takes the host's structured selections from the Guided Build
- Takes existing event data (occasion, guest count, dietary requirements, venue)
- Compiles both into a rich natural language prompt
- Passes the compiled prompt to the existing `generatePlan` function in place of `hostDescription`

Example compiled output:
> "Christmas event, 43 guests, Grand Hall venue with full kitchen access. Gluten free option required. Mains: traditional roast style — glazed ham and roast lamb, gluten free option needed. Dessert: pavlova (classic NZ). Sides: green salads and roasted vegetables. Drinks: non-alcoholic only — juices and sparkling water. No clean-up items or furniture needed."

## Evidence Package

**What was built**

Added a Guided Build path to the plan generation flow. The existing `HostDescriptionModal` now opens to a choice screen (Quick Generate / Guided Build) rather than directly to the textarea. The Quick Generate path is byte-for-byte unchanged in behaviour — selecting it shows the original textarea and Skip/Generate buttons. The Guided Build path renders `GuidedPlanBuilder`, a new config-driven component that reads from `plan-option-tree-config.json`.

The guided builder shows a persistent event context panel (occasion, guest count, date, venue, kitchen access, dietary flags) throughout all navigation. Dietary requirements from the event (gluten free, dairy free) auto-pre-select matching options in the tree. The host navigates an overview of occasion-appropriate categories, drills into each category's multi-level question tree, and returns to the overview at will. Breadcrumbs allow jumping back to any level. All selections persist within the session. A "Show more categories" button expands the visible list to all 14 globally available categories. A review screen summarises all selections with inline edit links. On submit, selections are compiled by an inline prompt-builder function into a rich natural-language string that is passed to the existing API as `hostDescription` — no API changes required.

`compileGuidedPrompt`, `GuidedEventContext`, `GuidedSelections`, and `GuidedLevelSelection` were added to `generate.ts` as specified. The component uses `import type` to reference these interfaces without bundling the server-side Anthropic SDK into the client bundle — the compilation logic is mirrored inline in `GuidedPlanBuilder.tsx` as a pure function.
