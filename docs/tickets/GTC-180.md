**Status:** Open | **Branch:** TBD | **Commit:** [pending] | **Effort:** high

*Effort level is a proposal from the discovery-report ticket breakdown — run `/effort` manually
before execution.*

### Context

Moment 4 spec §8.1/§10.2: there is a point where "I'm still nudging" stops being true because
there's no time left for nudging to work — and that point is set by Kate. The system enforces her
line; it never judges how close is too close (relationship knowledge, not the system's to have).
Red's exhaustion semantics survive intact — the calendar is a second way to exhaust, not a new
meaning for red. §10.2: this shares its derivation with D2's (GTC-175) maybe decide-by clock —
keyed to **needed-by** (item drop-off time, else event date), landing far enough before needed-by
for a nudge to realistically work. **The exact constant is settled at ticket time with Nigel's
sign-off** — this ticket must not invent a default unilaterally.

Today: no deadline/stop-nudging field on `Event` or `Person`. No derived-with-override pattern
exists for this concept.

### Scope

**Fix here:**
- Derivation logic per the needed-by formula shape — coordinate with D2 (GTC-175) on a single
  shared helper rather than two divergent implementations of the same formula.
- Per-event, per-person, and per-item override capability.
- Truncate E1's (GTC-178) nudge schedule at this line — "no nudge fires when there's no time left
  for it to work."

**Do not touch:**
- All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md`.
- Red's exhaustion semantics themselves — the calendar is a second way to exhaust, not a
  redefinition of what red means.

### Dependencies

E1 (GTC-178). Shares derivation logic with D2 (GTC-175) — build the shared helper once.
