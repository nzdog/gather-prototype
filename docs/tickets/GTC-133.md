## Sub-commit (d) — Restructure Moment 2 Step 1: retire Setup & Cleanup, add Food/Other-jobs split

**Status:** Ready for approval
**Branch:** feat/moment-one-redesign
**Commit:** [pending]

### What was found

1. **Old structure was a flat 7-accordion list.** `Moment2Step1Modal.tsx` rendered Dietary, Mains, Sides, Dessert, Drinks, Setup & Cleanup, Other in one continuous list with no semantic grouping. The "Setup & Cleanup" accordion mixed three boolean toggles (setupCrew, cleanupCrew, kidsOnDishes) — labour-planning UI that the Lichen Protocol architectural review concluded belongs to Moment 3, not Moment 2.

2. **Moment 2's purpose is "Kate gives Gather the shape" — not labour planning.** The 14 v1 categories collapse meaningfully along a Food / Other-jobs axis: food is where Kate has people-knowledge to share; other-jobs are jobs Kate has thoughts about but whose content design is deferred until Moment 3 walks resolve.

3. **`setupCleanupData` column is still populated for existing rows** but its three booleans no longer match product intent. Per product call: deprecate by disuse, do not drop. New code stops reading or writing it.

### What was changed

**Phase 1 — Schema migration (single migration, three columns)**

Added three optional JSON columns to `EventSetup`:
- `setUpData Json?`
- `cleanUpData Json?`
- `otherJobsOtherData Json?`

Each holds the shape `{ freeText: string, stillDeciding: boolean }`. Single migration `20260507205438_gtc_133_event_setup_other_jobs_columns/migration.sql` adds all three in one ALTER TABLE. Existing `setupCleanupData` column unchanged.

**Phase 2 — Setup endpoint extension**

`src/app/api/events/[id]/setup/route.ts`:
- Added `OtherJobsAccordionData` interface and three fields to `EventSetupBody`.
- Added `validateOtherJobsField()` helper: rejects with 400 unless value is null or a plain object whose only keys are `freeText` (string) and `stillDeciding` (boolean).
- Wired the three fields into the upsert data builder.
- Existing requests without these fields work unchanged.

**Phase 3 — SetupCleanupAccordion retired**

`Moment2Step1Modal.tsx`:
- Removed `SetupCleanupAccordion` component (and its render call).
- Removed `SetupCleanupData` interface from modal state and the `setupCleanupData` field from `Step1State`.
- Removed `ToggleRow` component (was only used by the retired accordion).
- Stopped reading/writing `setupCleanupData` in fetch + saveToApi.
- Modal silently ignores stale `setupCleanupData` returned by GET — `readOtherJobs()` defaults missing/invalid shapes to `{ freeText: '', stillDeciding: false }`.

**Phase 4 — Three free-text accordions added**

New `FreeTextAccordion` component (in same file for cohesion) renders:
- 🛠️ Set up — placeholder "What needs setting up before guests arrive? E.g. tables, chairs, decorations..."
- 🧹 Clean up — placeholder "What needs cleaning up afterwards? E.g. dishes, rubbish, areas to tidy..."
- 📋 Other — placeholder "Anything else that needs organising? E.g. transport, gifts, music..."

Each renders a single textarea (rows=5, resize-y) plus the standard `AccordionShell` "Still deciding?" toggle. No checkbox lists, no OptionTree, no item-level inputs.

**No AI generation wired.** Accordion ids (`setUp`, `cleanUp`, `otherJobsOther`) are absent from `sectionDataMap` in `generateSection()`, so closing one returns early before any `/api/events/[id]/generate-section` call. Verified by code path inspection.

**Phase 5 — Section headers added**

Two visually subtle group headers wrap the accordion list:

```tsx
<div className="text-xs uppercase tracking-wider text-gray-500 mt-4 mb-2 border-t border-gray-200 pt-4">
  Food
</div>
... food accordions ...
<div className="text-xs uppercase tracking-wider text-gray-500 mt-6 mb-2 border-t border-gray-200 pt-4">
  Other jobs
</div>
... three new free-text accordions ...
```

Treatment matches the spec's "small uppercase typography, gray-500 text colour, thin top border, subtle vertical spacing."

**Phase 6 — Modal initialisation + persistence**

- `INITIAL_STATE` extended with `setUpData`, `cleanUpData`, `otherJobsOtherData` defaulting to `{ freeText: '', stillDeciding: false }`.
- `fetchSetup()` reads each via `readOtherJobs()` defensive helper (handles null, malformed, missing).
- `saveToApi()` includes all three in every POST (alongside existing fields). Standard 500ms debounce unchanged.

**Phase 7 — Regression checks**

- Modal renders for fresh events with no EventSetup row.
- Modal renders for events with existing populated `setupCleanupData` — `readOtherJobs()` defaults each new field, `setupCleanupData` itself is ignored (not read into state).
- Modal renders for events with the three new fields populated — round-trip via debounced POST.
- Generate-plan flow unaffected (no Setup & Cleanup accordion → no AI generate call for `setup` from this modal; allowed list still permits the section name in case other code paths reach it).
- Per ticket guidance, finalize-plan still references `'setup'` in FOOD_SECTIONS — explicitly deferred to sub-commit (e).

### Schema migration shape

```sql
-- AlterTable
ALTER TABLE "EventSetup"
  ADD COLUMN "setUpData" JSONB,
  ADD COLUMN "cleanUpData" JSONB,
  ADD COLUMN "otherJobsOtherData" JSONB;
```

### Other-jobs accordion design choices

- **Single-file component**: `FreeTextAccordion` lives inline in `Moment2Step1Modal.tsx` next to existing accordion components (`FoodAccordion`, `DietaryAccordion`, `OtherAccordion`). Matches existing pattern; no new file.
- **Emoji choices**: 🛠️ (Set up), 🧹 (Clean up), 📋 (Other). Reuses 🧹 from the retired Setup & Cleanup label since it now applies more narrowly to clean-up only.
- **Textarea**: rows=5, `resize-y` so Kate can grow it; placeholder text per spec.

### Section header treatment

Subtle typographic separator, not a major UI shift:
- `text-xs` (extra small), `uppercase`, `tracking-wider` letter-spacing
- `text-gray-500` (low contrast)
- `border-t border-gray-200 pt-4` thin divider above
- Both Food and Other-jobs sections get identical treatment for consistency

### Stale data handling

- New code: `readOtherJobs()` helper returns defaults when fed null, undefined, or a wrong-shape object. Validates `freeText` is string, `stillDeciding` is boolean.
- POST endpoint: existing `setupCleanupData` field is still accepted in the body type to avoid breaking any legacy caller, but the modal stops sending it. New columns gated by strict shape validation.

### Known limitations

- `setupCleanupData` is still present in the schema, the API body type, and the upsert builder. Spec explicitly defers its drop to a future cleanup ticket. Existing rows continue to have it populated.
- `finalize-plan/route.ts:141` still references `'setupCleanupData'`. Per ticket Phase 7: "finalize-plan may attempt to gap-fill a missing 'setup' section; that's acceptable for this checkpoint and gets cleaned up next sub-commit (e)."

- No AI prompts for Other-jobs accordions — content design deferred to GTC-135 after Moment 3 walks resolve.
