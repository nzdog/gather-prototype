# GTC-107 — Kate clicks save and nothing happens — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 0ac41bc

### What was found

- `handleAddAnother` and `handleDone` in `Moment1InputForm.tsx` had `try/finally` blocks with no `catch`. When `onAddPerson` threw (e.g. network error, auth failure), the error propagated as an unhandled promise rejection — no user-facing feedback, button silently reverted from "Saving..." to its original label.
- Button labels ("+ Add another person" and "Done adding people →") did not communicate that they save the current household before proceeding.

### What was changed

**`src/components/plan/Moment1InputForm.tsx`:**

- Renamed "+ Add another person" → "Save & add another"
- Renamed "Done adding people →" → "Save & move on →"
- Edit mode labels ("Save changes" / "Cancel") unchanged
- Added `saveError` state. Both `handleAddAnother` and `handleDone` now catch errors from `onAddPerson` and set `saveError = true`. In `handleDone`, catch also prevents `onComplete()` from firing — Kate stays on the form.
- Error message "That didn't save — please try again." (`text-red-600 text-sm`) appears above the action buttons when `saveError` is true
- Error clears when Kate types in the name field or when a retry begins

### Known limitations

- Error message only clears on name field change, not on every field interaction. Name is required and is the most common re-entry point, so this covers the typical flow.
