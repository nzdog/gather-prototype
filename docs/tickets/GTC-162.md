## Decisions (Phase 1 audit)

### 1. `gather-v1-v2-brief.md` — COMMIT at repo root, unchanged path

Cited at the literal path `gather-v1-v2-brief.md` (repo root, no `docs/`
prefix) by three skills: `gather-docs-and-writing` (twice — "Read FIRST"
in the doc-priority table, and again in the untracked-docs risk table),
`gather-v1-v2-reconciliation-campaign` ("founding documents"), and
`gather-data-model-and-migrations`. Per the ticket's own rule — keep at a
path skills already cite, rather than move — it stays at repo root. No
skill reference updates needed since the path is unchanged; committing it
resolves the "untracked, at risk of loss" warning `gather-docs-and-writing`
itself already flags.

### 2. `scripts/seed-gtc-133-test-event.ts` — COMMIT as-is

Referenced by six skills (`gather-validation-and-evidence`,
`gather-run-and-operate`, `gather-debugging-playbook`, `gather-ai-generation`,
`gather-experiment-methodology`, `gather-v1-v2-reconciliation-campaign`) and
three tickets (GTC-137, GTC-159, GTC-160) at its current path. GTC-159's and
GTC-160's regression evidence depend on it being runnable from a fresh
clone. Straightforward commit, no changes.

### 3. `scripts/list-recent-events-for-gtc125.ts` — COMMIT (judgment call: genuinely reusable)

Read the script in full: a read-only Prisma query listing the 10 most
recent events with per-team item counts, originally built to verify
GTC-125 (the `Item.displayOrder` persistence ticket) — its
`hasReorderableTeam`/`reorderableTeams` output fields are a vestige of
that ticket's reorder feature, which GTC-141 later removed from the UI
entirely (`gather-failure-archaeology` §8, "KNOWN-TRADEOFF").

Despite the reorder-specific fields being vestigial, the script is
**not** a one-shot artifact:
- `gather-run-and-operate`'s script inventory table lists it explicitly
  as "still useful for 'did generation over-produce?'" — i.e. a session
  already relies on it for operational recon beyond its original purpose.
- `gather-frontier-and-roadmap` cites it as the **nearest ancestor** /
  model for a proposed `scripts/report-event-metrics.ts` (Epic 6
  instrumentation candidate) — a future ticket is meant to be built
  *from* this script.

Two independent skills treating it as reusable infrastructure, not
one-off recon, settles the call: commit as-is. The reorder-specific
fields are informational vestige (same category as `Item.displayOrder`
itself per GTC-141's KNOWN-TRADEOFF entry) — not in scope to strip; doing
so would be a behaviour change this housekeeping ticket didn't ask for.

### 4. `docs/moment-1-and-2-build-report.md` — SUPERSEDED BANNER + COMMIT (not delete)

Checked `gather-failure-archaeology` first, per instruction. Its §5 (the
per-section AI generation era) covers the AI-generation-architecture
saga in full — build, symptoms, measured revert (86→25 items), merge,
prune — with the exact same tickets (GTC-116/121/138-140/145/146/152)
this report's "Progressive AI generation" section describes. That part
of the archaeology skill's story is a genuine duplicate, and the section
is factually wrong today (describes `generate-section`,
`EventSetup.generatedData` caching, and per-section token caps — all
deleted).

**But that's roughly a third of the document.** The rest —
GTC-101–115 (Moment 1: household/`PersonEvent` model redesign, opening
screen, input flow polish, card list UI, save-error UX, completion
summary) and Step 2's non-generation interaction design (item edit,
quantity inline-edit, add/remove, category add) — is **not** retold
anywhere in `gather-failure-archaeology`, which only chronicles settled
incidents/reverts, not routine feature-build narrative. Blanket deletion
would lose that narrative with no replacement.

Judgment call, per the ticket's explicit invitation to make one: added a
superseded banner at the top scoping the warning precisely to the two
stale sections (Progressive AI generation; the Step 2 "Reorder" bullet,
also dead per GTC-141), pointing to `gather-failure-archaeology` and
`gather-ai-generation`, and noting the household-PUT description is now
superseded by GTC-159/GTC-160. Committed as history, not as current
documentation.

### 5. `docs/tickets/.obsidian/` — DO NOT commit; added to `.gitignore`

Editor config. Confirmed it's the only `.obsidian` directory in the repo
(`find . -name .obsidian`). Added the scoped pattern `**/.obsidian/` to
`.gitignore` (future-proofs against an Obsidian vault appearing elsewhere
under `docs/`), placed under the existing `# IDE` section alongside
`.vscode/`/`.idea/`.
