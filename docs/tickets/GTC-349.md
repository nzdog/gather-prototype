# GTC-349 — the door's last look shows the text, and "Send to an email address" sends an email

**Status:** Open — a stub, filed 2026-10-01 at [[GTC-340]] on founder instruction (plan ruling Q6:
*"file all three (findings 1, 3 and 4) as stubs, numbered from GTC-347, severity blank, none a
precondition"*). Not scoped. **Not a deploy precondition.**
**Severity:** not set at filing — the founder's to set.

---

### Signal

Founder answer 2 (slice 7b): the door is a last look — *"the address it will send to, the message
it will send, and a press rather than a link."* `readDoor` in `src/lib/press/resend.ts` composes the
message with the pre-flight's own walk, for the person as the chooser routes them. For a guest
reached by text that is the text: a body with no subject (`composePreview` gives a texted row no
subject).

But the door's address action writes an EMAIL row. For a text guest with no address, that action
is now "Send to an email address" ([[GTC-340]] plan ruling Q1), and the drain then sends an email,
with a subject and the email's own composition, which the panel never showed.

This was true before for any text-routed guest whose ask failed, but such a guest had no door
unless a provider refused the text. Since [[GTC-340]], a text Gather's own setup stopped is red
with the door, so every text guest on a machine with texting off sees it.

   may converge with.
