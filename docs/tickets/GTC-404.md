## The founder's rulings (25 Oct 2026, in Cowork, from his prompt)

Note 4 of his last list: "Dietary needs should be either all sorted or
edit. Does changing them, adding a new dietary need do anything". From my
planning report's "NOTE 4" section, with his rulings:

1. Two states. A step whose answer is saved ("none" or "some") shows,
   when open, one line ("You said there are none." or "You said there
   are these: Vegetarian, no shellfish.") and a "Change" button; no
   pills. Pressing Change shows today's pills, ticks, "Other dietary
   needs" box and "Save this", plus "Cancel" (back to the saved answer,
   nothing saved). A step never answered opens straight into the
   editing state, without "Cancel".
2. The tick for the step stays allowed while it is unanswered ("Still
   don't know"). The closed line stays as it is today ("Needs
   confirmation" in amber for never answered, and so on). Do not change
   what Send needs.
3. The button reads "Save this" until something is saved. The word
   "Saved" is no longer a button label. After a save the step goes to
   the sorted state.
4. After a saved CHANGE, when a plan has been drafted, one line shows
   under the sorted line: "Saved. Your plan was drafted before this, so
   check the dishes still cover it." Nothing is re-run and nothing is
   re-drafted. (My words; he will rule on them when he sees them.)
5. Under that line, the host gets an "Add a dish" link (Part B). A
   "Suggest a dish" button using the AI is NOT in this ticket: it is
   scoped separately afterwards. Not built, no button for it.

Also from the prompt: his written word to make a new local branch and
commit on it, and to run the tests once at the end. No push, no tag push.
Only the dietary part of `src/app/plan/[eventId]/pre-flight/page.tsx`

## What a host sees now (Part A)

Step 2, "Dietary needs", on the pre-flight. Closed, its row is exactly
as before: "Needs confirmation" in amber when never answered, "No
dietary needs", or the list ("Vegetarian, no shellfish").

Open, there are now two states:

- A saved answer (the host said "none" or "some"): one line, "You said
  there are none." or "You said there are these: Vegetarian, no
  shellfish.", and a "Change" button. No pills, no ticks, no box, no
  "Save this". The list reads exactly as the closed row reads it (the
  same `dietaryTitleSummary`), so the two never disagree.
- Editing (after "Change", or a step never answered): today's three
  pills ("No dietary needs", "There are some", "Still don't know"), the
  five ticks and the "Other dietary needs" box after "There are some",
  today's line at the top, the button "Save this" (greyed until
  something changes), and, after "Change" only, "Cancel" beside it.
  "Cancel" puts back the saved answer and saves nothing. A step never
  answered has no "Cancel", because there is nothing saved to go back
  to.
- The button now always reads "Save this". The old "Saved" label is
  gone. A save goes back to the saved state.
- After a save, when the event has at least one dish, one amber line
  appears under the saved line: "Saved. Your plan was drafted before
  this, so check the dishes still cover it." With no dish on the event,
  no line. Nothing is re-run or re-drafted. The line goes when "Change"
  is pressed again, and is not there on a fresh visit.

How "a plan has been drafted" is known: after the save is accepted, the
page reads the event's items through the read the setup page already
makes (`GET /api/events/[id]/items`, host or co-host only, the same
guard as the pre-flight's own read) and asks whether any is a dish (a
job alone is not a dish). It is a read; no route was added or changed.
If that read fails, the line is not shown.

A save from "Change" to "Still don't know" stores "never answered", so
the step goes back to opening in the editor (ruling 1), and the
after-save line is not drawn there (it belongs under a saved line).

## Part B: the "Add a dish" link - NOT BUILT (skipped)

What I found, screen by screen, for how a host adds a dish:

- The pre-flight's own links go to Moment 2's plan view
  (`/plan/[id]/setup?at=plan`), to Moment 3 at one item, to the setup
  page and to the board. The pre-flight itself adds no dish.
- Moment 3 ("Who's on what?") has no way to add a dish.
- Moment 2's plan view adds dishes one SECTION at a time: each section
  has its own "+ Add item" button, which opens a form inside that
  section (`AddItemForm` in `src/components/plan/Moment2PlanView.tsx`).
  That form has the five dietary ticks (V, VG, GF, DF, NF) for a dish.
  There is no single add-dish box for the event.
- The old dashboard (`/plan/[id]`) has `AddItemModal`, one box for the
  event with a section picker, but its ticks are only "Vegetarian" and
  "Gluten Free", and opening the old dashboard makes the event's link
  tokens (it writes AccessToken rows), so a link there breaks "nothing
  changes the database".

Why I skipped it: the goal was the host reaching the add-dish box with
the tick for her new need already chosen, "only if it can be done by a
link and a small read of the address". It cannot. It needs:

1. The link: `setupHref(eventId, AT_PLAN)` plus a new address part, for
   example `&mark=VG` (the pre-flight page; fine).
2. The setup page reading that part, as it reads `?item=` today (small,
   `src/app/plan/[eventId]/setup/page.tsx`, not protected).
3. A new prop on `Moment2PlanView` to open one section's add form on
   arrival, and a new "starting ticks" prop on `AddItemForm`: two
   components' state, beyond "a small read of the address".
4. A ruling on WHICH section's box opens (Moment 2 has no event-wide
   box), or a ruling that every "+ Add item" starts with the tick.
5. Changes to the frozen-file checks that pin the setup page and
   Moment2PlanView (demo-tweaks-3, -4, -5 U1 and several walkthrough
   suites), as this ticket did for the pre-flight page.

No route, schema or protected file would be needed. If he rules on 4,
it is a small ticket of its own. Today the host can still go from the
pre-flight to Moment 2's plan view by the strip ("What's the plan?"),
press "+ Add item" in a section and tick the mark herself.

So no "Add a dish" link was built, and the suite has no check for one.
