## Why deferred

`npm audit` on `feat/moment-one-redesign` flags three packages in one chain — `prisma` (direct
devDependency, installed 6.19.3), `@prisma/config` (transitive, installed 6.19.3), and
`deepmerge-ts` (transitive, installed 7.1.5, GHSA-ggr8-5vv4-36mx — stack exhaustion / DoS when
merging recursive object graphs). For all three, `npm audit`'s own `fixAvailable` field reports
the only path is `prisma@6.12.0` with `isSemVerMajor: true` — that is not a forward upgrade, it
is a **downgrade** from the currently-installed 6.19.3, and a major-version move besides. There
is currently no released version of `prisma`/`@prisma/config` that both stays ahead of 6.19.3
and clears `deepmerge-ts`'s vulnerable range (`<8.0.0`).

Downgrading `prisma` is not acceptable given the schema work already built on 6.19.3-era
behavior: [[GTC-152]] shipped a reviewed migration
(`20260708081323_drop_generated_data_and_structure_change_request`) directly against this
branch's Prisma toolchain, and `GATHER-BUILD-CONSTANTS.md` Do-Not-Touch Zone 5 (Prisma
Migrations) already treats the migration history as fragile — the repo spent months on P3005
drift before baselining it clean on 2026-03-14. A Prisma downgrade is exactly the kind of change
that zone exists to prevent without explicit instruction and a dedicated ticket.

(Correction to the framing this ticket was filed under: [[GTC-241]] was checked and is a
seed-script cleanup ticket, not a migration — it does not touch `prisma/migrations/`. GTC-152 is
the ticket that actually carries recent migration risk; cited above instead.)

## Real-world exposure (why this is Medium, not the raw High severity)

`@prisma/client@6.19.3` — the package that actually ships into the production runtime — has
**zero dependencies** (`npm ls @prisma/client` confirms an empty dependency tree). The
`@prisma/config` → `deepmerge-ts` chain is pulled in exclusively by `prisma`, the CLI package,
which is a `devDependency` (`npm ls @prisma/config --all` shows its sole parent is `prisma`).
`deepmerge-ts`'s vulnerable code path is stack exhaustion when merging deeply recursive object
graphs — realistically triggered by a maliciously crafted Prisma config file processed by the
CLI, not by anything in this app's request-handling code. **This is a dev/CI-time exposure, not
a production-facing one.** Severity is recorded as Medium on that basis; re-escalate to High if
that assumption turns out to be wrong (e.g. if `@prisma/config` is ever loaded at runtime, not
just by the CLI).
