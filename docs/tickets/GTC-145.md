# [[GTC-145]] — Single-call AI generation experiment — CLOSED

**Status:** Complete | **Branch:** experiment/single-ai-call

## What was found

The per-section AI generation pattern ([[GTC-121]]) was firing one Claude call per accordion close, with no cross-section coordination. Each section was generated in isolation, producing:

- Cross-section item duplication (Yule Log appearing in both Cake AND Dessert)
- Cross-category contamination (Prosecco listed under Entrée AND Alcoholic Drinks)
- Parallel "alternatives" patterns rather than naturally-integrated dietary items
- Encyclopedic over-generation (86 items / 9 categories for a 17-person Christmas)

[[GTC-137]]'s 27% reduction came from removing the parallel dietary generator, but it could not address the architectural cause: the AI never sees the whole plan at once, so it cannot coordinate.

## What was changed (per phase)

**Phase 1** — Code audit (no code change). Surfaced relevant call sites, confirmed no discrepancies vs cowork's investigation.

**Phase 2** — Client gating in `Moment2Step1Modal.tsx`:
- `generateSection` removed entirely.
- Per-accordion state machine (`idle/generating/generated/failed`) removed.
- Status indicators (pulsing dot / ✓) removed from `AccordionShell`.
- Data-hash re-generation guard removed.
- `onSectionGenerated` prop removed.
- Pending-save flush retained on accordion close and on Generate click.
- Unused `totalAdults`, `totalKids`, `kidsWithJobs` state removed (only `peopleCount` for the feedback line is needed now).

**Phase 3** — `src/app/api/events/[id]/generate-section/route.ts` rewritten as a 410 Gone defensive stub with a deprecation message referencing [[GTC-145]].

**Phase 4** — New `buildPlanGenerationPrompt` in `src/lib/ai/prompts.ts`:
- Receives the full Step 1 context: event metadata, headcount, dietary requirements, per-category OptionTree selections, free-text notes.
- Cross-category coordination directive (every item appears in exactly one category).
- Dietary-as-input directive (prefer naturally-suitable integration over parallel alternatives).
- Realistic plan size guidance ("items Kate would actually buy and bring, not items she could possibly bring").
- Returns structured JSON with `sections`, `dietaryCoverage`, and `thingsToConsider` in one response.

**Phase 5** — `finalize-plan/route.ts` rewritten as the single-call route:
- Gap-fill loop removed.
- Dependency on `EventSetup.generatedData` removed.
- One `callClaudeForJSON` invocation with the new prompt.
- Response sections mapped to `Moment2Plan` shape consumed by `Moment2Step2Skeleton`.
- Pre-existing `source: GENERATED` teams cleared before write so re-runs don't stack.
- `AI_CALL_LIMIT` lowered from 20 → 10 (single call per finalize).

**Phase 6** — Per-section infrastructure deprecate-by-comment:
- `buildSectionPrompt`, `buildGapPrompt` marked DEPRECATED but retained.
- `MAX_TOKENS_SECTION_GENERATION`, `MAX_TOKENS_GAP_FILL` marked DEPRECATED but retained.
- New `MAX_TOKENS_FULL_PLAN = 16384` added.
- `EventSetup.generatedData` schema column untouched; new writes simply no longer populate it.

**Phase 7** — `Moment2Step2Skeleton.tsx`: no code change required. The component was already plan-prop driven; the staggered reveal animation now triggers when the single response arrives, exactly as before.

**Phase 8** — TypeScript clean, production build green, console.log count = 0, browser verification complete.

## Comparison: per-section vs single-call

| Measure | Per-section (baseline) | Single-call (this ticket) |
|---|---|---|
| Total items | 86 | 25 |
| Categories | 9 | 6 |
| Cross-section duplication | Yule Log in Cake AND Dessert; Prosecco in Entrée AND Drinks | None observed |
| Wait duration | ~instant on click | 43.86s |
| Coordination quality | parallel alternatives, encyclopedic over-generation | Vegetarian Wellington integrated as single Mains option; GF Crackers naturally placed in Snacks; structure resembles Kate's actual Christmas spreadsheet (3 mains / 6 sides / 3 desserts / etc.) |

Item count delta: **-71%**, closer to Kate's spreadsheet ground truth (~19 items for a real 33-person Christmas).

## Known limitations

- Single response is more error-prone than smaller per-section calls; may need retry logic for production scale.
- 16K token cap may be insufficient at 50+ guest scale; new `callSiteLabel` infrastructure ([[GTC-142]]) will surface this if/when it happens.
- Legacy `/api/events/[id]/generate` route untouched (separate concern — used by v1 GuidedPlanBuilder).
- Per-section infrastructure left in place behind DEPRECATED comments; full deletion deferred to a future cleanup ticket once single-call lands on main feature branch.

## Recommendations: ship vs revert

**Ship.** Bring to `feat/moment-one-redesign` as a real ticket.

The 44s wait is real but acceptable. The quality improvement is significant: 71% fewer items, no cross-section duplication, dietary integration that resembles real coordination rather than parallel alternatives. The architecture lets the AI see the whole plan, which is the only way to get the coordination Kate's spreadsheet exhibits.
