The founder, verbatim: **"Q19, the sign-in hole: not a stub. My ruling: "Fix before launch, next

### Evidence (checked by Cowork against the code on 8 Oct, read-only; the founder's words, verbatim)

- POST /api/auth/verify takes personId from the request body; the sign-in page copies it from the
  link's address (?personId=). After checking only that the token exists, is unexpired and unused,
  it sets that Person's userId to the signing-in user, even when the Person is already linked to
  someone else, and creates HOST EventRoles on every event whose hostId is that person and COHOST
  where coHostId is. MagicLink has no personId: nothing ties a link to a person.
- Anyone can get a valid link for their own address from POST /api/auth/magic-link. With a host's
  person id added to its address, they become a host of her events.
- Person ids reach people who aren't the host: GET /api/p/[token] returns team.coordinator.id, which
  is the host when she coordinates the guest's team (a category added in Moment 2, whose
  onAddCategory sets coordinatorId: event.hostId; template clones; the old dashboard). GET
  /api/c/[token] returns team members' ids.
- POST /api/auth/claim emails "Claim your Gather host account" to any address for any unclaimed
  Person, and never checks the returnToken it puts in the link.
- returnUrl is unchecked: the route returns it as redirectUrl and the page navigates to it. Next
  15.5.25's app router hands an outside address to location.assign (handleExternalUrl), and by the
  same check a javascript: address (read from its code, not tried). So a link to Gather's real
  sign-in page carrying the sender's own token signs the clicker in as the sender and can send them
  anywhere.
- The live app (origin/master, ebc21d9) has the same verify route and page.
- The claim flow GTC-309 relies on (GET /api/h/[token] sets needsClaim; the host page posts to
  /api/auth/claim) has to keep working.
- Related: GTC-263, GTC-282, GTC-309, GTC-359.

### What the ruling asks of the fix (the founder's four points)

1. Gather works out the person itself and never takes it from the link.
2. It never moves a person who's already linked to someone else.
3. It only sends you on to Gather's own pages.
4. A claim email needs the host's own link.
