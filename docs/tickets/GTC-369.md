### Evidence (checked by Cowork against the code on 8 Oct, read-only; the founder's words, verbatim)

- POST /api/auth/verify takes personId from the request body; the sign-in page copies it from the
  link's address (?personId=). After checking only that the token exists, is unexpired and unused,
  it sets that Person's userId to the signing-in user, even when the Person is already linked to
  someone else, and creates HOST EventRoles on every event whose hostId is that person and COHOST
  where coHostId is. MagicLink has no personId: nothing ties a link to a person.
- Anyone can get a valid link for their own address from POST /api/auth/magic-link. With a host's
  person id added to its address, they become a host of her events.
- Person ids reach people who aren't the host: GET /api/p/[token] returns team.coordinator.id, which
  is the host when she coordinates the guest's team (a category added in Moment 2, whose
  onAddCategory sets coordinatorId: event.hostId; template clones; the old dashboard). GET
  /api/c/[token] returns team members' ids.
- POST /api/auth/claim emails "Claim your Gather host account" to any address for any unclaimed
  Person, and never checks the returnToken it puts in the link.
- returnUrl is unchecked: the route returns it as redirectUrl and the page navigates to it. Next
  15.5.25's app router hands an outside address to location.assign (handleExternalUrl), and by the
  same check a javascript: address (read from its code, not tried). So a link to Gather's real
  sign-in page carrying the sender's own token signs the clicker in as the sender and can send them
  anywhere.
- The live app (origin/master, ebc21d9) has the same verify route and page.
- The claim flow GTC-309 relies on (GET /api/h/[token] sets needsClaim; the host page posts to
  /api/auth/claim) has to keep working.
- Related: GTC-263, GTC-282, GTC-309, GTC-359.

### What the ruling asks of the fix (the founder's four points)

1. Gather works out the person itself and never takes it from the link.
2. It never moves a person who's already linked to someone else.
3. It only sends you on to Gather's own pages.
4. A claim email needs the host's own link.

### Claude Code's corrections to the ticket

- C1. `POST` in `src/app/api/auth/verify/route.ts` marks the link used BEFORE it writes the person,
  outside the transaction. A made-up `personId` makes `tx.person.update` throw; the route answers
  500 `invalid` and the link is already spent.
- C2. `POST` in `src/app/api/auth/claim/route.ts` itself mints the attack link for any unclaimed
  person: any address, any `personId`, any `returnToken`, and the link it mails already carries
  that `personId`. For an unclaimed host, one claim call to your own address is the whole attack;
  nothing needs editing.
- C3. `POST` in `src/app/api/templates/[id]/clone/route.ts` sets `hostId = user.id` and looks up a
  Person by that User id, so it answers 404 "Host not found" unless a Person's id equals the User's;
  when it does run it sets `coordinatorId` to a User id. A separate defect: [[GTC-372]].
- C4. At this HEAD the sign-in page calls `router.replace` ([[GTC-362]]), so Next's external branch
  ends in `location.replace`, not `location.assign`; the live app still uses `router.push`, so
  `location.assign` is right there. Read in Next 15.5.25: `isExternalURL` (app-router) compares
  origins only, a `javascript:` URL's origin is "null", and `handleExternalUrl` (navigate-reducer)
  hands `url.toString()` on with no scheme check. Read from the code, not tried.
- C5. `GET` in `src/app/api/h/[token]/route.ts` sets the unclaimed state only when `NODE_ENV` is not
  `development`; on the dev server the claim form never shows. Tests drive the routes directly.
- C6. The ticket's evidence leaves out F1 and F2 below.

### Found while planning (not in the ticket's evidence)

- F1. Using up a link is not atomic: verify reads the link, checks `usedAt`, then updates it by id.
  Two requests at once with one token can both sign in. Folded in here (Q6).
- F2. Login CSRF: a link carrying the sender's own token signs whoever clicks it in as the sender.
  After this fix it can only land on Gather's own pages, but it remains. Filed as [[GTC-371]] (Q10).

### Reproduce

**Required state**
- No session needed. An attacker with a valid MagicLink for her own address (from
  `POST /api/auth/magic-link`, or written directly in a test).
- A victim host Person who hosts an event; linked or not to a User.
- Multi-actor: [x] Yes — the attacker (her own sign-in link) and the victim host (never acts).

**Steps**
1. `POST /api/auth/verify` with `{ token: <attacker's own token>, personId: <victim's Person id> }`.
2. Read the victim Person and the event's `EventRole` rows.

**Observe:** the victim Person's `userId` is the attacker's User, and the attacker holds HOST on the
victim's event, whether or not the victim was linked before. And with `returnUrl` set to an outside
or `javascript:` address, the response's `redirectUrl` is that address unchanged.

**Data setup:** the suite builds its own fixture (example.com users), writing every sign-in link
straight into the database; nothing is emailed.

### Scope

**Fix here:**
- `POST` in `src/app/api/auth/verify/route.ts`: no `personId` from the body; the person from
  `MagicLink.personId` only; a conditional link (`userId` null or this user) and a refusal
  (`error: 'claimed'`, 200) otherwise; the link used up by a conditional update whose count is
  checked; `returnUrl` through `safeReturnPath`.
- `POST` in `src/app/api/auth/claim/route.ts`: `resolveToken(returnToken)` first — a HOST link of
  that person or `{ ok: true }` with nothing written or sent; the MagicLink row carries the person;
  the link carries no `personId`.
- `src/app/auth/verify/page.tsx`: posts no `personId`; the "claimed" message (W1–W3).
- `src/lib/safe-return-path.ts` (new): `safeReturnPath`.
- `prisma/schema.prisma` and one migration: `MagicLink.personId`, nullable, FK to Person, ON DELETE
  SET NULL.
- `tests/sign-in-hole-test.ts` (new) and `test:sign-in-hole` in `package.json`.
- `tests/security-route-scan-control.ts`: ONE line, re-pinned to name `POST /api/auth/claim` alone
  (Q5 condition).
- `GATHER-BUILD-CONSTANTS.md`: one line (Q12). `scripts/`: the read-only production check (Q13).

**Do not touch:**
All Do-Not-Touch Zones in GATHER-BUILD-CONSTANTS.md are binding, beyond the Zone 2 and Zone 5 changes
