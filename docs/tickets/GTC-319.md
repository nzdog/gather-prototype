### Signal

**Expected**
A two-day event reads as a range a guest can act on: `13 Sept – 15 Sept`.

**Actual**
It reads `13 Sept-Sept`. The end day is gone and the month is printed twice.

**Root cause — it is a locale assumption, not a typo.** `formatDateRange` builds an
`Intl.DateTimeFormat('en-NZ', { month: 'short', day: 'numeric' })` and then takes
`.split(' ')[1]` of the formatted END date, expecting the day to be the second token. That is
true of `en-US` (`"Sep 13"` → `"13"`). **`en-NZ` formats day-first** (`"13 Sept"`), so the second
token is the MONTH. The start is printed whole and the end contributes its month again.

**Smallest failing case**
Open any participant page for an event whose start and end differ.

**Verified at `87a35ef`**

```
start formatted: "13 Sept"
end formatted:   "15 Sept"
end.split(" ")[1]: "Sept"
RENDERED RANGE:  "13 Sept-Sept"
```

The event used is "GTC-192 glance — mixed", `startDate` 2026-09-13T11:40Z, `endDate`
2026-09-14T17:40Z. Note the end formats as **15** Sept, not 14: the formatter is pinned to
`Pacific/Auckland` and 17:40 UTC on the 14th is 05:40 on the 15th locally. So the correct output
for this event is `13 Sept – 15 Sept`, and whether that is the RIGHT end date is a separate
question — see Unknown 2.

### Where it lives — three copies of the same helper, and a fourth that is correct

- `formatDateRange` in `src/app/p/[token]/page.tsx` — the guest page. **Guest-facing.**
- `formatDateRange` in `src/app/h/[token]/page.tsx` — the host's token page.
- `formatDateRange` in `src/app/gather/[eventId]/directory/page.tsx` — the family directory,
  which is **unauthenticated and public to anyone holding the event id**. Same bug, written out
  over three lines instead of one (`startFormatted`, `endDay`).
- `formatDateRange` in `src/app/plan/events/page.tsx` is a **different** implementation that
  formats both ends and compares them. It does not have this defect and is not in scope except
  as the shape to copy.

⚠ **Three copies is the reason this survived.** Fixing one leaves two, and a reader who checks
one file concludes it is fixed.

### Unknowns

1. **One shared helper or three fixed copies?** A shared helper is the obvious answer and it
   crosses three route trees, one of which is unauthenticated. Recorded as a choice.
2. **Is the stored `endDate` the intended instant?** This event's end is 17:40 UTC, which is the
   next calendar day in Auckland. That may be correct (an event running into the evening) or may
   be a capture defect. **Out of scope here** — this ticket makes the renderer honest about
   whatever is stored. Measure before assuming.
3. **Whether the range belongs on the guest page at all.** §3's closed content list does not
   include it, and the §3 sweep follows [[GTC-189]] slice 5. If that sweep cuts the line, this
   fix is still right for the other two surfaces.
