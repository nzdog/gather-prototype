# GTC-198 — A3d: Token-route UI

**Status:** Open | **Branch:** `experiment/send-lock-ledger` | **Commit:** [pending] | **Effort:** high

**Plan of record:** [`docs/04_roadmap/send-lock-reconciliation-plan.md`](../04_roadmap/send-lock-reconciliation-plan.md)
§4.2 Layer 4 (GTC-167, commit `76943e4`). Filed 2026-08-03 as part of the approved A3 four-way split
— see [[GTC-169]] (A3a), [[GTC-196]] (A3b), [[GTC-197]] (A3c). **Last ticket before the Epic A merge.**

---

### Context

The four token surfaces (`/h/`, `/c/`, `/p/`, `/join/`) still render a freeze that no longer exists.
27 sites across five pages. Split from A3c because the verification surface is four separate browser
walks, which GTC-169's original acceptance already required.

**⚠ Do-Not-Touch zone 1.** These are token routes, and `middleware.ts` scopes their cookies. This
ticket changes **page rendering only** — no auth, no `resolveToken`, no cookie handling, no
middleware. `/api/h/` is deliberately excluded from the session-strip list; do not "complete the
pattern." If a change appears to need auth work, that is Stop Condition 5.

### The ruling that shapes the participant view

**Coordinators — (a):** *"same always-allow + ledger as the host. No walls anywhere."* So the
coordinator view stops going read-only after the send: its edit affordances stay live, and the ones
the why-scope rule flags gain a reason prompt (the general component A3c introduced).
