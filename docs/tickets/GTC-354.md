### Signal

[[GTC-290]]'s planning found that `route-classifications.json` held 85 entries for 111 route files,
and none of them was a cron route. Since [[GTC-290]], the TNZ status poll
(`/api/cron/tnz-status-poll`) is classified (`CUSTOM`, the `CRON_SECRET` shared secret, failing
closed), the first cron route in the file. The four older ones are still absent:

- `src/app/api/cron/nudges/route.ts`
- `src/app/api/cron/outbound-dispatch/route.ts`
- `src/app/api/cron/wrap-up-dispatch/route.ts`
- `src/app/api/cron/decide-by-followups/route.ts`

All four carry the same `CRON_SECRET` guard ([[GTC-270]]), and `tests/security-route-scan-control.ts`
pins each one's verdict as `SHARED_SECRET:PROVEN+SHARED_SECRET:PROVEN`, so the scanner already sees
them. What is missing is only the inventory's record.

### Not decided here

Whether to add the four entries. Each one moves `test:glance-replay` layer 4's pinned route count
(86 at [[GTC-290]]), and `route-classifications.json` is treated as a zone file (GTC-290 showed its
edit for the founder's approval as Zone 6; `test:carried-child-door` F guards it).
