## ✅ RULED 2026-09-29 AT THIS TICKET'S PLAN

1. **The words.** The last line of every guest-bound email is, verbatim:

   ```
   Contact Gather: hello@gatheringtogether.co.nz
   ```

   Plain text, as the footer is today. Chosen over the plan's recommendation
   (`Contact Gather: nigel@mckorbett.co.nz`) and its two alternatives: Gather's own address from
   the start.
2. **No anchor.** With Gather's own address there is no interim personal address, so no
   `ANCHOR` and no stub ticket for a later switch. `ANCHOR(GTC-296)` goes, since the placeholder
   it marked goes.
3. **Approved as planned:**
   - the claim-account email is read as a sign-in link under ruling 6;
   - mutation M5 is planted on `sendMagicLinkEmail` and restored at once;
   - dated pointers are added in [[GTC-296]];
   - the edits to `tests/email-opt-out-test.ts` (Zone 9's test file) go ahead.
4. **`npm run build` runs with the dev server stopped.** Both write `.next`, and a build under a
   running dev server breaks it. The dev server is then restarted, keys blanked, for the gate.
5. **A deploy step.** Before launch, confirm that `hello@gatheringtogether.co.nz` receives mail:
   a message sent to it from an outside account arrives. The footer tells every guest they can
   reach Gather there. This is recorded in [[GTC-189]]'s gathered list.

### Signal

**Expected**
Every guest-bound email ends with the line ruled above. No guest email carries a postal address
or the placeholder ([[GTC-296]] ruling 7, as re-ruled and amended).

**Actual**
Every guest-bound email ends with this, verbatim:

```
[Gather — registered postal address to be confirmed before launch]
```

The line is `GATHER_POSTAL_ADDRESS` in `src/lib/email-footer.ts`, placed by `guestEmailFooter`.

**Smallest failing case**
`withGuestEmailFooter('<BODY>', '<PAGE_URL>')` at `7602e99` returns:

```
"<BODY>\n\n—\nDon't want emails about this event? <PAGE_URL>\n\n[Gather — registered postal address to be confirmed before launch]"
```

Both dashes are U+2014. There is no trailing newline.
