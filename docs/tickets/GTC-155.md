# GTC-155 — Track .claude/skills/ in git (unblock skill-library commit) — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** ships in the `chore(GTC-155)` commit alongside this ticket (hash not backfilled — bundled per the three-unit commit plan)

**Severity:** Low (tooling/config — but blocks the skill-library commit entirely)
**Surfaced by:** Skill-library work (2026-07-09). `.gitignore` blanket-ignored all of
`.claude/`, so the new `.claude/skills/` library could not be committed.

### Signal

`.gitignore:27` was `.claude/`, which ignores the entire directory including the intended-to-be-
tracked `.claude/skills/` library. `git add .claude/skills/` was a silent no-op.

### Fix

Replaced the blanket rule with a carve-out:

```
.claude/*
!.claude/skills/
```

`.claude/*` (with the star) rather than `.claude/` is required — a directory excluded as
`.claude/` cannot have children re-included, but excluding only its *contents* allows the
`!.claude/skills/` negation to take effect.

### Scope

**Fix here:** `.gitignore` only. **Do not touch:** any local `.claude/` state.

### Evidence (Executor-Completed)

Verified after the change (2026-07-09):
- `git check-ignore -v .claude/skills/gather-change-control/SKILL.md` → exit 1 (NOT ignored). ✓
- `git check-ignore -v .claude/settings.local.json` → matched `.gitignore:27:.claude/*` (ignored). ✓
- `.claude/settings.json`, `.claude/toggle-permissions.sh`, `.claude/worktrees`, `.claude/.DS_Store`
  all still ignored. ✓
- `git add -n .claude/skills/` stages exactly 16 files (15 SKILL.md + 1 scripts/plan-metrics.ts);
  `.claude/skills/.DS_Store` correctly excluded by the global `.DS_Store` rule (`.gitignore:19`). ✓

### Known limitations

None. Local-only `.claude/` state (settings, worktrees) remains ignored as before.
