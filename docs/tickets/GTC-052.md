# GTC-052 — Guest invite links broken — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** [fill after commit]

### What was found

**Root cause:** The shared link join page (`/join/[token]`) and Family Directory page (`/gather/[eventId]/directory`) listed ALL PersonEvent members regardless of role — including HOST (1) and COORDINATOR (7) people. These roles have HOST/COORDINATOR-scoped AccessTokens, not PARTICIPANT tokens. When any of these 8 people tried to claim their name through the shared link, the claim route looked for a PARTICIPANT token, found none, and returned "No access token found. Please contact the host."

The 35 PARTICIPANT-role people had correct PARTICIPANT tokens and could claim successfully. Tokens were confirmed present in the database — `ensureEventTokens()` ran correctly during the CONFIRMING transition.

**Scope of impact:**
- Shared link flow: 8 of 43 people (all HOSTs/COORDINATORs) could not claim
- Family Directory: 8 people showed "No access yet" despite having role-appropriate tokens
- Individual invite links (`/p/{token}`): Worked correctly for all 35 participants

### What was changed

**`src/app/join/[token]/page.tsx`**
- Added `where: { role: 'PARTICIPANT' }` filter to the `people` query so the shared link name selection page only shows participants (not coordinators/hosts who lack PARTICIPANT tokens)

**`src/app/api/join/[token]/claim/route.ts`**
- Changed token query from filtering by `scope: 'PARTICIPANT'` only to fetching all tokens for the event
- Added `scope` to the token select fields
- Added fallback logic: if no PARTICIPANT token exists, checks for COORDINATOR or HOST tokens
- For non-PARTICIPANT tokens, returns a `redirectPrefix` (`h`/`c`) so the client routes to the correct view
- Removed dead code (unreachable null check after early return)

**`src/app/join/[token]/NameSelectionClient.tsx`**
- Updated redirect after claim to use `data.redirectPrefix` (defaults to `p`) so coordinators/hosts who claim via shared link go to their correct view (`/c/` or `/h/`)

**`src/app/api/gather/[eventId]/directory/route.ts`**
- Changed from fetching only PARTICIPANT tokens to fetching all token scopes
- Added scope priority logic (PARTICIPANT > COORDINATOR > HOST) so each person gets their best token
- Returns `tokenPrefix` (`p`/`c`/`h`) alongside token for correct URL construction

**`src/app/gather/[eventId]/directory/page.tsx`**
- Added `tokenPrefix` to Person interface
- Updated navigation to use `tokenPrefix` instead of hardcoded `/p/` prefix
