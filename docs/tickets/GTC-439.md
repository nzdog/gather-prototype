# GTC-439 - The six lockfile checks are red on main

> Filed by Claude Code on 31 Oct 2026, at the founder's request, after
> GTC-435's dry run. Not built.

## What happens

One check in each of demo-tweaks 6 to 11 is red on main and on every
branch cut from it (fix/household-save at 9ff914d included):

```
demo-tweaks-6   U1  (its lockfile part)
demo-tweaks-7   U1  (its lockfile part)
demo-tweaks-8   U1  (its lockfile part)
demo-tweaks-9   U2  package-lock.json is as at the base, but for the
demo-tweaks-10  U2  one qs entry GTC-413 moves, which says 6.16.1 and
demo-tweaks-11  U2  nothing else
```

Each asks, through `lockfileIsBaseButQs`, that package-lock.json is
its base's but for GTC-413's one qs entry. The "now" side is the
lockfile in the working folder ([[GTC-414]] kept these six live on
purpose), so any later lockfile change turns them red. Shown on a clean
copy at 9ff914d in GTC-435's dry run (31 Oct 2026): the same six, each
1 failed.

## What moved the lockfile

Since 21a9577 (GTC-413, where the checks were last green), 31 entries,
all through Dependabot pull requests merged on main on 30 Oct 2026
(checked from each merge's second parent):

```
fabed8f  #49  Bump esbuild and tsx: esbuild 0.27.2 -> 0.28.2 (and its
              26 platform packages), tsx 4.21.0 -> 4.23.15, zod 4.3.6
              no longer in the tree
7b227b5  #69  Bump postcss-selector-parser and tailwindcss (Tailwind 4)
8bdd844  #73  Bump brace-expansion 1.1.18 -> 1.1.21 (and the copy under
              typescript-estree 5.0.9 -> 5.0.12)
14e5345  #77  revert #69 (Tailwind 3 to 4) so main builds again
```

GTC-429's ticket has #49 and #69 the wrong way round; the list above is
from the merges themselves.

## Does it relate to the Dependabot alerts?

Yes, in part. Read from GitHub's Dependabot alerts (read only, 31 Oct
2026):

- Two of the merges that moved the lockfile were security fixes: #73
  closed the brace-expansion alerts 108-110 and 117-119 (high and
  medium), and #49, merged first, closed alert 130 (zod, high): GitHub
  marked it fixed 7 seconds after that merge (29 Oct 18:46 UTC, 30 Oct
  07:46 NZ time). Each of the three Dependabot branches drops zod
  4.3.6; it left with #49.
- Five alerts are still open, and none of them is what moved the
  lockfile: postcss (45, 76, 77, 88; two high) and
  postcss-selector-parser (131, medium). The lockfile still holds
  postcss 8.5.28 (dev), next's own postcss 8.4.31, and
  postcss-selector-parser 6.1.4, exactly as at 21a9577. #69 (Tailwind
  4.3.3) took postcss-selector-parser out of the tree altogether; its
  revert (#77) put 6.1.4 back, so alert 131 (opened 27 Oct, never
  fixed) stays open. The fixed version is 6.1.5.

So the checks went red because the security bumps landed, and they
would go red again with every future Dependabot merge. Fixing the open
postcss alerts is not this ticket.
