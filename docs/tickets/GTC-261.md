# GTC-261 — Pre-flight step 3: label and alignment — CLOSED

**Status:** Complete | **Branch:** `feat/moment-one-redesign` | **Commit:** `e47e861` | **Effort:** low

### Context

Two founder-requested changes to the person rows in step 3 of the pre-flight
(`src/app/plan/[eventId]/pre-flight/page.tsx`), the per-person nudge-mark controls [[GTC-188]]
built on [[GTC-179]]'s model. Presentation only.

### Scope

**Fix here:**
- Relabel the null-state pill from "No mark" to "Normal nudge".
- Give the name a fixed-width column so every row's controls start at the same x.

**Do not touch:** the stored values, the schema, any route. Nothing in this ticket changes what
is written or read.

### 1. "No mark" → "Normal nudge"

**LABEL ONLY. The column stays NULL for this state.** `PersonEvent.nudgeMark` is unchanged, the
`onMark(personEventId, null)` call is unchanged, and `resolveNudgeOffsetDays` still reads NULL as
"no opinion, defer to the event pace" ([[GTC-179]] Ruling 4, quieter-wins).

⚠ **The risk the new label creates, and the comment left at the site to head it off:** "Normal
nudge" reads like a stored setting and is not one. [[GTC-179]]'s own field comment already warns
that an unset pace and an explicit STANDARD "reach the same days by different routes, and only
the unset one yields to a future change in the default". The same trap now has a label inviting
someone into it, so the site says in as many words: name what the host gets, not what the column
holds; do not turn this into a stored value.

It was the only occurrence of the label in this section. The other repo hits for "no mark" are
`no markdown` in AI prompts and a comment in `src/lib/eligibility/nudge-mark.ts` describing the
*value* — still accurate, deliberately not edited.

### 2. Fixed-width name column

The name was `min-w-[8rem]` — a **floor, not a column** — so a long name grew it and pushed the
controls right: "Aarav Patel-Henderson" sat further out than "Amy Henderson", and the rows read
ragged. Now `w-full sm:w-60` (240px) with the name `truncate`d inside it (`min-w-0` is what lets
`truncate` work in a flex child; `title` keeps the full name reachable).

**The channel badge moved INSIDE the column.** Left outside it, the one row carrying a badge
would have been the one row out of line — the exact defect being fixed, surviving in the single
case most likely to be overlooked.

### Known limitation, stated not hidden

**The cadence sentence wraps to its own line under the controls.** It lines up — same x on every
row — but it is not inline after them, and cannot be: the page container is `max-w-3xl`, so the
row is **678px at any window width**, while the content needs **820px** (240 name + 321 controls
+ 235 sentence + gaps). It wrapped before this ticket too, from a ragged starting point.

Inline would require the name column at roughly 110px, which truncates most of the
Patel-Hendersons mid-word. Not taken; raised with the founder as a trade rather than decided.

### ⚠ Incident during this ticket — `next build` against a live dev server

The founder reported "the buttons don't work". The cause was not this change: the whole page was
returning **Internal Server Error**. The executor had run `npm run build` as a gate **while the
dev server was serving the page**; `next build` writes into the same `.next/` the dev server
reads from and deleted its manifests:

```
⨯ ENOENT: .next/server/app/plan/[eventId]/pre-flight/page/app-build-manifest.json
```

Fixed by stopping the server, removing `.next`, and restarting clean.

**Two lessons, recorded because both are cheap to repeat:**

1. **Never run `npm run build` while a dev server is up on this repo.** Stop it first, or don't
   run the build. A green build gate that breaks the running app is worse than no gate.
2. **Geometry is not a working-page check.** Alignment numbers were reported as a browser walk;
   they were measured on a page whose buttons could not have worked. Click the thing.
