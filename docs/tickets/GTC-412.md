# GTC-412 - A host who pays keeps the capitals they typed in their first name

> Filed by Claude Code on 28 Oct 2026, from the founder's prompt (the FULL
> PROCESS, two small tickets on one branch, one final gate). Branch
> feat/final-fixes from feat/email-case at b5357c1. Status: built, not
> pushed.

## What was wrong

When a first-time host pays, the paid-event route (POST /api/events,
GTC-280) makes their Person and names it from the part of the address
before the @. GTC-411 changed that line to read the account's stored
address, which GTC-411 stores lower-case. So a host who paid as
Sarah@x.com started as "sarah", not "Sarah". Before GTC-411 the name came
from the address as typed.

## The founder's ruling (28 Oct 2026, in Cowork)

1. The Person made by the paid route takes its NAME from the address as
   typed (identity.bindTo before the @), as it did before GTC-411. Its
   email stays the account's stored address. Nothing else in the route
   changes.

## What changed

- src/app/api/events/route.ts: one line. The new Person's name is
  identity.bindTo.split('@')[0] again (it was user.email.split('@')[0]).
  email: user.email is kept. The comment above the Person gained two
  lines saying where the name comes from, so it stays true. Nothing else
  in the route moved.
- tests/email-case-test.ts: one new check, T7 (static, no database). It
  reads the route's code with comments stripped and asks: exactly one
  person.create call; its data has one name key and one email key; the
  name is identity.bindTo split at the @, first part; the email is
  user.email. Expectations are written by hand. The header list names T7.

identity.bindTo is the paid address exactly as resolvePaymentIdentity
returns it (src/lib/events/payment-identity.ts, not touched).

## Not touched
