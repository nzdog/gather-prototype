> THE HOUSEHOLD REMINDER SURVIVES AND CHANGES SPECIES. It is no longer an automatic chase. The host

---

### What is being retired, and how this differs

**Retired for adults by [[GTC-189]] slice 8:** the automatic proxy reminder —
`findProxyNudgeCandidates` in `src/lib/sms/proxy-nudge-eligibility.ts`, `sendProxyNudge` and
`getProxyHouseholdReminderMessage` — a text on a cron to a household's channel about its
unconfirmed members.

**This object differs on each axis that defined that one:**

- **Who starts it.** The host chooses to send it. Nothing schedules it.
- **What it says.** The exact status of everyone in the household, the yeses included — not a count
  of the unconfirmed.
- **What it is.** A status share, not a nudge — so not a chase leg.

### Why it has its own ticket

*The executor's recommendation on filing, 2026-09-14 — not a ruling.*

1. **It is not the chase.** Slice 8 is the automatic chase. Folding a host-initiated message into it
   would put an unruled design question inside an approved slice.
2. **It needs a register that does not exist.** `ASK_REGISTER` is the only `VoiceProfile` in
   `src/lib/messages/compose.ts`, and that file records adding a register as a founder ruling
   ([[GTC-187]] decision 7; *THE MISSING REGISTER*). A status share is not an ask.
3. **It needs a door the host opens**, on a surface nobody has named.
4. **It reports adults' answers through a household**, which the recipient model has to be
   reconciled with (below).

---

### Collisions recorded — not resolved

- **"The household is not a messaging unit for adults."** [[GTC-189]], founder ruling of
  2026-09-13, THE ASK. A share sent to a household that reports its adults' answers is a
  household-level message about adults. It is neither an ask nor a chase, so it may sit outside that
  sentence. The founder's to say.
- **The household switch.** `resolveHouseholdMuted` in `src/lib/households/channel.ts` ([[GTC-256]]
  Ruling 6) governs "household messages", which the 2026-09-13 ruling narrowed to carried child
  asks. Whether it governs this is open.
- **The don't-chase mark.** [[GTC-179]] Ruling 3 suppresses the proxy path for a `DONT_CHASE`
  channel. A host-chosen share is not a chase; whether the mark still reaches it is open.
- **[[GTC-252]]** awaits a ruling on the automatic proxy path's frequency. If that path is retired
  outright, its question may have no subject left. The founder's to call.
- **The outbound record.** [[GTC-189]] slice 4 gives each outbound row a `kind` of *ask or chase
  leg*. A status share is neither. Slice 4 is not started, so this is cheaper to meet before its
  migration than after.
