# GTC-272 — One demo event name, six spellings, two of them wrong

**Status:** Open — **filed, not started. Nothing has been built or driven for
this ticket.** Filed 2026-09-11 | **Branch:** TBD
**Severity:** [ ] Critical [x] High [ ] Medium [ ] Low
Escalated (brand/trust risk): [x] Yes — the failure mode is the public `/demo`
page, reached from the homepage's second CTA, breaking completely.

**Found during [[GTC-269]]'s investigation**, read-only, against HEAD
`9272222` on 2026-09-11.

**Founder ruling, 2026-09-11: file, do not fix.** [[GTC-269]] took the
one-line `isDemo: true` hardening on the lookup, because that closes a
collision whose consequence is unbounded and does not depend on this being
resolved. The shared constant is this ticket.

**This is not a new discovery.** It is already the canonical record in
`.claude/skills/gather-config-and-flags/SKILL.md` section 7, flagged there as
"CONFIRMED LIVE BUG (as of 2026-07-09)", with the instruction: "The fix shape:
ONE exported `DEMO_EVENT_NAME` constant imported by seed, both demo routes,
and tests. Open a GTC ticket; do not patch one site." This is that ticket. It
has been known for two months and has not been filed until now.

---

## Signal

**Expected**
The demo event is identified by one constant, defined once.

**Actual**
It is identified by a string literal written out in six places, and two of
those six disagree with the seed. Against a fresh `npm run db:seed` both demo
API routes answer 404 and the `/demo` page has no working content at all.

**Smallest failing case**
`npm run db:reset`, then `curl -X POST http://localhost:3000/api/demo/session`
→ `{"error":"Demo event not found"}`, 404. Same for `GET /api/demo/tokens`.

---

## Evidence

The six sites and their values, grepped at `9272222`:

- `prisma/seed.ts` — the `name:` field on the demo `event.create()` (the same
  call sets `isDemo: true`): **`Henderson Family Christmas 2026`**
- `DEMO_EVENT_NAME` in `src/app/api/demo/session/route.ts`: **`...2025`**
- `DEMO_EVENT_NAME` in `src/app/api/demo/tokens/route.ts`: **`...2025`**
- `DEMO_EVENT_NAME` in `tests/demo-endpoints-test.ts`: **`...2025`**
- `src/app/demo/page.tsx` — the step-1 accordion display copy: **`...2025`**
- `scripts/update-demo-dates.sql` — renames `2025` to `2026` in place

**The local database has a `2025` row and that is why nothing has broken
yet.** Measured 2026-09-11:

```
Henderson Family Christmas 2025
  id       cmmolxnlm00181yn154x1aylz
  isDemo   true
  created  2026-03-13T08:00:51.898Z
```

It was created before the seed was renamed and has never been re-seeded.
**The routes work on this machine by accident of history, not by design.**

**A seventh site was deliberately avoided.** [[GTC-269]] needed to resolve the
demo event in `tests/security-validation.ts` suite 11 and resolved it by
`isDemo: true` rather than by name, specifically so as not to add another
copy. There is exactly one `isDemo: true` event, which is why that worked.

**A related stale assertion, and it is currently failing.**
`tests/demo-ui-isolation.ts` asserts that `src/app/api/p/[token]/route.ts`
contains the `2025` literal, to prove the participant API identifies the demo
event by name. That route now derives `isDemo` from `event.isDemo` and
contains no Henderson string at all, so `npm run test:demo-ui` has one failing
assertion **independent of the database**. It is one of three pre-existing
failures proven at HEAD by [[GTC-269]]. Fixing it belongs here: the assertion
is asking the wrong question, and the right question is whether the route uses
`event.isDemo`.

- Multi-actor: [ ] Yes [x] No

**Steps**

## Scope

**Fix here:**
- One exported `DEMO_EVENT_NAME` constant in a shared module, imported by
  `prisma/seed.ts`, both demo routes, and the tests. Per the skill file's
  instruction: **do not patch one site.**
- Decide the value — 2025 or 2026 — as a product call. The seed and the copy
  in `src/app/demo/page.tsx` must agree with it, and a dated demo event will
  need this decision again every year, which is itself an argument for a name
  without a year in it.
- `scripts/update-demo-dates.sql` — reconcile or delete. A script whose job is
  to paper over this drift should not outlive it.
- `tests/demo-ui-isolation.ts` — reassert against `event.isDemo`, not against
  a string literal in a route that no longer carries one.

**Do not touch:**
All Do-Not-Touch Zones in `GATHER-BUILD-CONSTANTS.md` are binding. Zone 5
(Prisma migrations) is adjacent: renaming seed **data** is not a migration and
must not become one.

Out of scope: the `isDemo: true` filter on the lookup in
`src/app/api/demo/session/route.ts`. [[GTC-269]] already took it, and it stays
correct whatever this ticket decides the name should be.
