# [[GTC-047]] — Pre-fill form fields from query params on /plan/new — CLOSED

**Status:** Complete
**Branch:** gtc-042-part1-nudge-schema
**Commit:** 11389af

### What was found
- Form uses **controlled inputs** — React state (`formData`) bound to `value` props with `onChange` handler
- The form previously had only 3 fields: Event Name, Start Date, End Date
- No contact fields (name, email, phone) existed in the form at all
- Query params were read via `sanitiseParam()` into a `prefilledContact` state object, displayed only as a green notification banner ("Welcome, {name}!") — never populated into editable fields
- `prefilledContact` was saved to `gather_prefilled_contact` in sessionStorage during checkout for downstream use
- `gather_new_event` sessionStorage key persists form data across Stripe redirect — contact fields now included

### What was changed

**`src/app/plan/new/page.tsx`**
- Added `hostName`, `email`, `phone` fields to `formData` state (controlled inputs)
- Query params now pre-fill these form fields via `setFormData` in the mount useEffect, using existing `sanitiseParam()`
- Replaced `prefilledContact` state with simpler `referralRef` (string) and `showWelcome` (boolean)
- Demoted the large green banner to a subtle single-line welcome text: "Welcome back, {name} — your details are pre-filled below."
- Added three new form fields (Your Name, Email, Phone) between Event Name and Date Range
- All three contact fields are optional — they never gate checkout for non-prefilled users
- `startCheckout` now writes contact info from `formData` to `gather_prefilled_contact` sessionStorage (same shape: `{name, email, phone, ref}`), preserving downstream compatibility
- All form data (including new fields) persists in `gather_new_event` sessionStorage and restores on canceled payment or plain page load

### Known limitations / follow-up flags
- The `ref` query param (referral tracking) is preserved in sessionStorage but not displayed in the form — it's metadata, not user-facing
- All contact fields optional — no validation beyond browser `type="email"` / `type="tel"` hints
- The checkout API (`/api/billing/checkout`) still only receives event name + dates; contact info flows via sessionStorage — no API change needed
