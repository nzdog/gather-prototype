# GTC-485 - Multi-day: the deadline from the dish's session, and what guests and the board show

Base: origin/main 8454fed (24 Nov 2026, the merge of pull request #122,
GTC-480). The founder's multi-day rulings are in [[GTC-476]]; the date rule is

## The scope, from GTC-480's brief

- **D. The deadline:** a dish with a session counts back from that session's
  date, through the date helper, in ONE place (`lifecycle.ts` `neededBy`).
  With no session, or the switch off, exactly as today.
- **E.** The guest page shows a dish's session name AND its date.
- **F.** The board shows a small session tag on each dish line.
- **G.** The pre-flight's draft first line names the event's whole date range,
  not just the first day, when the event spans more than one date.

## Every reader of neededBy, and what each does with the change

- The board's colour for a maybe (`src/lib/glance/state.ts` `deriveItemState`,
  through `isDecideByExpired`): amber while there is time, red "maybe timed
  out" after. A maybe on an earlier session turns red sooner. Load:
  `src/lib/glance/read.ts`.
- The board's replay (`src/lib/glance/rewind.ts`, `replay.ts`): the amber to
  red steps since the host's last look. The same change. Load: `rewind.ts`.
- The reply facts (`src/lib/chase-reply-read.ts`): whether a maybe's
  follow-up is still owed and the "follow-up already sent" sentence. The same.
- The deadline carried on the board's data (`state.ts` `decideByAtFor`):
  carried, never shown.
- "Answers by" on the board's top line (`src/lib/events/event-dates.ts`
  `answersByDay`): event-level, no dish (ruled below).
- The maybe follow-up's finder (`decide-by-eligibility.ts`, the
  decide-by-followups cron every 15 minutes): who is due the one follow-up
  now. A maybe on an earlier session is followed up sooner. Zone 7.
- The follow-up's words (`decide-by-sender.ts`, `nudge-templates.ts`): "Still
  good for the X? Kate needs to know by <day>." The day comes from the finder;
  the words do not change.
- The follow-up's email retry (`decide-by-sender.ts`): names the earliest open
  maybe. Zone 9.
- Not readers: the nudges (timed from the send, they stop at the event's end),
  the guest page (no deadline date), the ask composer (start date only).

```
export function neededBy(
  item: { dropOffAt: Date | null; day?: { date: Date } | null },
  event: LifecycleEvent
): Date {
  if (item.dropOffAt === null && item.day && isSessionsOn()) {
    const at = new Date(`${sessionDateKey(item.day.date)}T00:00:00.000Z`);
    return at.getTime() < event.endDate.getTime() ? at : event.endDate;
  }
  return item.dropOffAt ?? event.endDate;
}
```
