# GTC-115 — Household members ordered newest-first — CLOSED

**Status:** Complete | **Branch:** feat/moment-one-redesign | **Commit:** 762e7ae

### What was found

Member sub-forms were grouped by type: partner first, then all helpers, then littles, then all guests. When Kate added a new member of any type, it appeared within its type group — not at the top of the list. This meant Kate's cursor jumped to different vertical positions depending on what type of member she added, and older entries of other types could sit above newer ones.

### What was changed

**File:** `src/components/plan/Moment1InputForm.tsx`

Introduced a `memberOrder` state array that tracks all named member sub-forms (partner, helpers, guests) by `{type, id}` in insertion order, newest first. The rendering now iterates `memberOrder` instead of rendering separate type-grouped sections:

- **`memberOrder` state:** `Array<{type: 'partner' | 'helper' | 'guest', id: string}>` — newest entries prepended
- **Add Partner button:** prepends `{type: 'partner', id: 'partner'}` to memberOrder
- **Kid with a job button:** prepends `{type: 'helper', id: h.id}` to memberOrder
- **Add Guest function:** prepends `{type: 'guest', id: g.id}` to memberOrder
- **Remove handlers:** all three types filter their entry from memberOrder on remove
- **Edit mode:** builds memberOrder from loaded members (partner, then helpers, then guests — original order preserved)
- **Reset:** clears memberOrder alongside other state
- **JSX:** single `memberOrder.map()` loop renders the correct sub-form for each entry, using `orderIdx === 0` for autoFocus so the newest member always gets focus
- **Kids without jobs:** stays at the bottom of the section, outside the memberOrder loop (it's a count input, not a named person)

Layout order is now: buttons → newest member sub-form → older members → kids without jobs (if present).

### Known limitations

- The "Kid with a job 1/2/3" numbering reflects position in the helpers array (data order), not visual order. This is intentional — the number corresponds to the data slot, not the display position.
- In edit mode, existing members load in their original order (partner, helpers, guests) since we don't have timestamp data for insertion order.
